## 1. 我理解本模块要做的事

对每个池内异常，在当时已经可见的信息里找出最多五个原因，用规则打分，并把「市场是不是在交易这个逻辑」和「经营上成不成立」分开。广域异常只回捞、只记录。LLM 只抽取说法和提出候选；分数、状态、结论都由规则算。

### 回捞与说法

- FR-M8-01：`close` 的起点是当日美东 09:30，`post` 的起点是当日收盘。主窗口是起点前 72 小时到本次运行时刻。同一批检索实体另取 [起点 − 7 个自然日, 起点 − 72 小时) 的背景，和主窗口合并后仍只留 40 条。背景带角色和发布时间，不能当成这次异常的直接触发。引用必须在本次运行时点已经可见。
- FR-M8-02：检索实体 = 异常成员 + 这些成员所属篮子的成员 + 图谱上一跳邻居（任何状态）+ 关联的监控实体。
- FR-M8-03：规则检索（`entities` 或 `tickers` 与检索实体相交）和向量检索取并集。向量用「篮子名、方向、成员名」做查询，窗口内按余弦相似度取前 50。按 `source_root` 去重。
- FR-M8-04：排序分 = 0.5 × 实体重合度（上限 1）+ 0.3 × 向量相似度 + 0.2 × 信源权重（一级 1.0、二级 0.75、三级 0.5、四级 0.25）。前 40 条才进候选生成。
- FR-M8-05：回捞少于 5 条时，用 Tavily / Exa / Google CSE 按实体和日期补搜。每天总次数不超过 `search_daily_budget`，规格初始值 200。补进 `info_items` 时 `first_seen_at` 是当前时间，时间对齐只用 `published_at`。预算用完就不再搜，报告写「补证未执行」。
- FR-M8-06：前 40 条里还没有说法的，用 `claim_extraction`（`deepseek-v4.1-flash`）抽说法。原文不支持的字段留空。

### 候选与证据

- FR-M8-07：`anomaly_candidates`（`glm-5.3`）最多五个候选。机制只允许供给、需求、竞争、客户融资、估值倍数。每个候选有传导链、预期受影响的篮子和标的及方向、对照篮子、引用的信息 id。提示词和 JSON 见第 8 节。
- FR-M8-08：引用为空或不在本次回捞集合里的候选丢掉（I23）。标的不在池内也不在广域里就删掉该标的。另加固定候选「无事件 / 资金面」，不打分；只有其他候选都低于 0.5 时它才作为结论。
- FR-M8-09：六项分 0–1，缺数据是 `NULL`，总分按还在的权重重配。时间对齐：最早 `published_at` 早于起点所在时段为 1.0，同一时段 0.7，晚于 0。暴露梯度：状态至少「观察到」的关系给出直接 3、间接 2、概念 1、无 0，与按预期方向取号的 `resid_z` 做 Spearman，取 max(0, ρ)；成员少于 3 为 `NULL`。篮子特异性：预期篮子 `|resid_z|` 均值减去对照篮子 `|resid_z|` 均值，再除以 3，限制在 [0, 1]；没有对照篮子为 `NULL`。叙事证据：窗口内同时提到事件实体和受影响实体的独立来源根数 N，min(N ÷ 5, 1)。隐含幅度：相容 1.0、部分相容 0.6、不相容 0.2、无法检验 `NULL`。替代解释排除：1 −（当日有自身财报反应、8-K 指引或评级变化的成员数 ÷ 成员数）。
- FR-M8-10：权重 20 / 20 / 15 / 15 / 15 / 15。总分 ≥ 0.70 为高，0.50–0.70 为中，低于 0.50 为低。最优候选 ≥ 0.5 时联动事件进入「假设中」。`golden/m8_attribution.json` 的 `evidence_scores` 全部命中，不改 golden。

### 隐含幅度

- FR-M8-11：ΔE_mkt = Σ 成员（前一日市值 × 当日剩余收益 ÷ TTM PE）。EPS ≤ 0 的成员不计入。全都不可计则「无法检验」。用剩余收益，不用总涨跌（Q-M8-1）。
- FR-M8-12：渠道由机制决定。供给走供给 / 价格；需求、竞争走直接收入；客户融资走订单 / 积压加融资 / 对手方；估值倍数走估值倍数，没有盈利上限。比例上限按候选引用里最高的信源等级查表（Q-M8-2）：收入或价格变化、订单延期，一级 100%、二级 25%、三级 15%、四级 10%；对手方违约，一级 100%、二级 15%、三级 10%、四级 5%。增量利润率在暴露基础是分部收入时用分部利润率，否则用 `op_margin_ttm`（Q-M8-3）。订单 / 积压还要除以兑现年数。
- FR-M8-13：美元暴露只取状态至少「观察到」的关系。R = |ΔE_mkt| ÷ ΣΔE_evt。R ≤ 1.5 相容，1.5–5 部分相容，大于 5 不相容。缺暴露是无法检验，不能记成不相容。部分渠道缺暴露时，已知渠道 R ≤ 1.5 才是相容，否则无法检验。`implied_magnitude` 全部命中。不相容不生成情绪标签（I30）。

### 市场确认、二次命中、原因未明

- FR-M8-14：四项同时满足才进入「市场确认」：有最早说法时间；对应对象有异常响应；至少一条独立于价格的证据（独立来源根 ≥ 2，或监控实体搜索热度突增，或三级及以上点评）；替代解释排除分 ≥ 0.5。缺一项只是关联候选。
- FR-M8-15：市场归因至少为中的候选登记指纹。之后 `published_at` 晚于原起点、实体相交的新信息，同一来源根只算一次。反应时段里预期篮子 `resid_z` 方向一致且绝对值 ≥ 1、对照篮子绝对值 < 1 为命中；方向相反且绝对值 ≥ 1 为反证；其余无响应。至少一次命中且没有反证为确认；至少一次反证或连续两次无响应为否定；没有后续信息为未检验。这个结论只写市场层。
- FR-M8-16：所有候选都低于 0.5 时，异常状态是「已发现·原因未明」。每个交易日再回捞一次，共 5 个交易日。涉及持仓且 `max_abs_z ≥ 4` 时写系统日志「请人工查看」。持仓只看代码和优先级标签，不看账户、数量、金额。

### 联动事件与三轨

- FR-M8-17：每次状态变化写历史：时间、旧状态、新状态、触发条件、证据 id。不允许跳过「假设中」直接进入「市场确认」。转换表见第 10 节。
- FR-M8-18：五维分开存。真实性：只有三四级为未核实；有二级独立信源为部分核实；一级确认为核实；一级改数字为修订；一级否认或事实矛盾为证伪。叙事：当日独立来源根 Nₜ，首日初现；Nₜ ≥ 3 且 ≥ 1.5 × 昨日为扩散；连续 2 天 ≤ 0.5 × 峰值为衰减；衰减之后 ≥ 0.8 × 峰值为重新活跃；其余稳定。市场关联按指纹和二次命中。交易状态：回吐比例 r = 1 − 累计剩余 ÷ 首日剩余；前两个交易日为风险释放；r ≥ 0.3 为初步修复；r ≥ 0.5 且维持 5 个交易日为持续确认；初步修复后创出低于首日收盘的新低为修复失效。
- FR-M8-19：资金轨道：k ≤ 1 为冲击中；r ≥ 0.5 为已消化；同方向累计 ≥ 1.2 × 首日为延续；r ≥ 1.0 为反转；其余消化中。
- FR-M8-20：基本面轨道读 M2 的共识修订和广度、8-K、一二级定量说法。待验证 → 局部支持（一条一二级定量说法）→ 支持或冲突（达到第 7.3 节任一门槛，方向一致或相反）→ 失效（截止日未到门槛）。供给 / 需求类事件带六项约束核查：新增供给占需求增量、投产与良率、产品代际、需求吸收、订单相对可交付、价格传导。每项是未知、有数据或结论。
- FR-M8-21：截止日 = min（暴露最直接的标的的下一个财报反应日，机制对应周期，20 个交易日）。到期必须落到支持、反证、条件风险之一，不能续期。只有新的一二级原始证据、新的异常范围，或接近兑现期，才能重新激活。转载不能重启。
- FR-M8-22：背离标签只在截止日或「已验证」时给出，其他时刻为空。阈值：未下修是当年 EPS 共识较 7 天前 > −2% 且下修家数不超过上修家数；显著下修是 ≤ −3%，或近 7 天下修家数 ≥ 覆盖家数的 30%。情绪性折价、合理重定价、滞后风险、情绪性溢价、基本面驱动上涨五张表按规格第 7.4 节。
- FR-M8-23：`l1_state` 不是正常，或 `shock_flag` 为真的交易日，用 `systemic_event_tag`（`deepseek-v4.1-flash`）从当日回捞信息给标签。至少一条引用是一级或二级，否则为「无」。
- FR-M8-24：事件可解释 = 符号 × min(|总剩余|, ΣΔE_evt × PE ÷ 市值)；无法检验时为 0。资金放大 =（总剩余 − 事件可解释）×（M7 里为真的资金放大特征数 ÷ 可得特征数）。未解释是其余。三项之和等于总剩余，允许 0.1 个百分点舍入（I23）。
- FR-M8-25：不调用 stock-pm，不读它的库。基本面结论只来自基本面轨道。
- FR-M8-26：估值倍数类连带写 N2；叙事冲击且基本面未变写 N1；原因未明写 N6。写入 `perception.ticker_status`。
- FR-M8-27：解释报告含冲击分解、类型候选（补上事件冲击 / 叙事冲击 / 原因未明）、候选和证据明细、影响范围、对估值（固定为「不变 / 待基本面轨道」）、对交易（留给 M9 / M10）、跟踪清单、已检索信源和缺口。
- FR-M8-28：北京 09:15 出候选和分数（M7 之后）；09:30 更新三轨并做截止日结案；12:30 写 T+1 打标草稿交给 M10。冬令时各顺延 1 小时，按 README §3.1。写 `job_runs`。正式按时跑一次留给合并后的运维核对，不能拿来冒充 AC-M8-06。

## 8. 候选生成的提示词和输出 JSON

任务名 `anomaly_candidates`，模型 `glm-5.3`，已在注册表。输入只含本次前 40 条，不送全量新闻。系统提示要求：只根据给定信息 id 提出机制；不要编造 id；不要给分数；最多五个；机制枚举固定。

输出：

```json
{
  "candidates": [
    {
      "mechanism": "供给",
      "chain": [{"entity_id": "toshiba", "new": false}],
      "affected": [{"basket_id": "hdd", "ticker": "WDC", "direction": "down"}],
      "control_baskets": ["memory"],
      "info_ids": ["info-nikkei-toshiba"]
    }
  ]
}
```
