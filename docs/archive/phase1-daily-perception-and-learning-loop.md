## 0. 目标对齐

**基本认识**：资金行为只能事后找原因。很多资金行为会借助消息面和情绪面，形成轧空或踩踏，并放大价格异常。当下无法仅凭新闻感知资金行为。

**最终目标**：系统通过持续复盘积累案例和规律，逐步具备**感知能力**，也就是在异常发生前后更早、更准地识别"正在发生什么"。

**第一阶段目标**（以天为单位，允许延迟）：

| # | 能力 | 判断标准 |
|---|---|---|
| A1 | 感知股价异常 | 每个交易日收盘后（含盘后收盘价），发现所有覆盖标的和主题篮子的异常 |
| A2 | 自主建立符合逻辑的连接 | 对每个异常自动给出候选解释、证据和置信度，无需人工发起 |
| A3 | 基础分析 | 每个异常有一份标准化的解释报告，包括冲击分解、影响范围、跟踪清单 |
| A4 | 稳定的估值体系 | 所有标的每天有可复现的估值区间；没有基本面变化时价值不乱动 |
| A5 | 合理的交易行为 | 交易由 Muse 规则加估值和事件约束机械产生，每个动作和"不动作"都有理由 |
| A6 | 复盘补强 | 每个异常都变成案例；案例持续沉淀为模式、权重和先兆特征，按规则晋级 |

## 1. 能力阶梯：从"事后解释"到"感知"

| 阶段 | 能力 | 第一阶段是否交付 | 进入下一阶段的条件 |
|---|---|---|---|
| **C1 事后解释** | T+1 早上说清楚昨天发生了什么、最可能的几个候选原因、影响到谁 | **交付** | 处置覆盖率 100%；归因事后命中率按置信度分桶有区分度（"高"组命中率明显高于"中"组）；连续运行 3 个月 |
| **C2 结构识别** | 当天就能判断异常的类型：事件冲击、情绪踩踏、轧空、主题轮动、宏观流动性 | **部分交付**（先给出类型候选，第 3.3 节） | 类型判断的事后准确率达到冻结下限；每类 ≥ 30 个案例 |
| **C3 先兆识别** | 在异常发生前，识别出"容易发生异常"的前置状态：拥挤、空头集中、叙事升温、估值极端 | 不交付，**但从第一天起积累数据**（第 6 节） | 先兆特征在保留样本上对异常有稳定的预测提升；≥ 200 个异常 + 对照样本 |
| **C4 感知** | 前置状态加触发信号 → 给出"异常可能发生 / 正在演变"的预警，并影响仓位 | 不交付 | 前向运行验证预警有效，并经你拍板 |

**关键**：C3 和 C4 不能靠设计出来，只能靠 C1 和 C2 阶段积累的案例长出来。所以第一阶段最重要的不是"聪明"，而是**每个异常都被完整记录、被事后打标**。

## 3. 日级异常感知与资金放大识别

### 3.1 异常发现（日级）

沿用第三部分第 3 节，频率改为每日：

- 四层剩余涨跌：大盘、主题篮子、个股相对篮子、篮子内部离散；
- 同时看**收盘到收盘**和**收盘到盘后收盘**两段，盘后暴跌（东芝案例）在当天早上 08:00 就能被看到；
- 广域集合（约 1000–1500 只）、高频集合（约 150 只）、约 40 个主题篮子全部覆盖；
- 多日累积异常：连续 3–5 日同向剩余累积超过阈值，也算异常。这类"阴跌 / 缓涨"单日不明显，但往往是资金持续进出。

### 3.2 冲击分解：事件、资金放大、未解释

每个异常的价格变化拆成三部分：

```
总剩余涨跌 = 事件可解释部分 + 资金放大部分 + 未解释部分
```

| 部分 | 怎么估 |
|---|---|
| 事件可解释部分 | 用隐含幅度检验（第三部分第 5.4 节）：事件可能带来的盈利变化 × 当前 PE ÷ 市值，取上限 |
| 资金放大部分 | 超出事件可解释部分、且同时出现第 3.3 节资金放大特征的部分 |
| 未解释部分 | 剩下的部分 |

例（OpenAI 传闻，示意）：AI 篮子剩余 −4%，其中事件可解释上限约 −0.5%；同时出现拥挤度高、多头集中、看跌期权隐含波动率跳升、篮子内同步下跌 → 约 −3% 归为资金放大（踩踏特征）；剩余 −0.5% 未解释。

这个分解不精确，但它把"消息被资金利用并放大"这件事显式地记录下来，供复盘统计。

### 3.3 资金放大特征（只用免费或现有数据）

| 类型 | 特征 | 数据来源 | 第一阶段可得性 |
|---|---|---|---|
| **轧空** | 空头占流通股比例高；回补天数高；价格上涨伴随成交量 > 3 倍均量；跳空高开；看涨期权持仓和隐含波动率同时上升；上涨发生在利空或无消息时 | FINRA 空头数据（每月两次，免费）；Muse 已有空头回补天数；CBOE 期权快照；日线 | 可得（空头数据有约两周滞后） |
| **踩踏** | **拥挤度**：过去 6 个月涨幅位于前 10%，且篮子内部相关性在升高；跳空低开 + 放量；篮子广度坍塌（篮子内 > 80% 同跌）；看跌期权隐含波动率跳升、偏度变陡；随后数日快速回吐 | 日线；篮子相关性（自算）；CBOE 快照 | 可得 |
| **杠杆 / 被动** | 相关杠杆 ETF 规模和当日涨跌；指数调整日；期权到期日 | ETF 日线；日历 | 可得 |
| **情绪放大** | 叙事热度（来源数、搜索热度、榜单）上升速度远快于基本面证据 | 第三部分情绪轨道 | 可得 |

输出：每个异常一个**资金放大类型候选**（轧空 / 踩踏 / 杠杆被动 / 情绪放大 / 无）及其特征明细。这只是描述，**不进入估值，也不单独触发交易**，只用于：

1. 冲击分解；
2. 事件闸门的资格判断：踩踏型冲击加上基本面未变，是"不机械止损"的典型场景，需要回测；
3. 复盘统计（第 5 节）和先兆特征（第 6 节）。

### 3.4 异常类型候选（C2 的起点）

| 类型 | 典型组合 |
|---|---|
| 事件冲击（基本面型） | 隐含幅度相容；一级 / 二级信源；暴露梯度明显 |
| 叙事 / 情绪冲击 | 隐含幅度不相容；叙事证据强；资金放大特征明显；之后快速回吐 |
| 轧空 | 空头集中 + 无消息或利空下的放量上涨 |
| 踩踏 | 拥挤 + 广度坍塌 + 跳空放量 |
| 主题轮动 | 一个篮子跌、另一个篮子涨，大盘平稳 |
| 宏观 / 流动性 | 大盘层异常；跨资产（利率、美元、VIX）同步；无单一事件 |
| 原因未明 | 以上都不成立 |

第一阶段只要求给出类型候选和理由，准确率由复盘统计，不作为交易依据。

## 4. 自主建连与基础分析

### 4.1 自主建连的分工

| 步骤 | 谁做 | 约束 |
|---|---|---|
| 回捞候选信息 | 检索（规则 + 向量检索） | 72 小时窗口，全量库 |
| 提出候选机制 | LLM | 必须引用回捞到的具体信息 id；不能凭空编；每个异常最多 5 个候选 |
| 证据打分 | **规则** | 时间对齐、暴露梯度、篮子特异性、叙事证据、隐含幅度、替代解释（第三部分第 5.2 节） |
| 影响范围 | 图谱 + 规则 | 直接 / 间接 / 概念 / 共振 |
| 新连接入库 | 系统起草 → 进候选库 | 新边一律从"候选"开始，升级走证据阶梯 |

**LLM 负责"想到"，规则负责"判断"**。这样新机制能被提出来（例如"智能体多任务 → CPU 需求"），但不会因为 LLM 说得像样就被当真。

### 4.2 异常解释报告（标准模板）

```
异常编号 / 日期 / 层次 / 篮子 / 成员与剩余涨跌 / 盘后变化
冲击分解：事件可解释 x% | 资金放大 y%（类型：踩踏，特征…）| 未解释 z%
异常类型候选：叙事 / 情绪冲击（理由…）
候选解释（按市场归因置信度排序）：
  ① 解释、信源等级、首次可得时间、证据得分明细、隐含幅度、基本面成立度
  ② …
影响范围：直接 / 间接 / 概念 / 共振，各标的
对估值：不变 / 档位切换 / 待基本面轨道
对交易：持仓动作 + 理由代码；候选动作 + 理由代码
跟踪清单：情绪 / 资金 / 基本面各自的检查点与截止日
已检索信源与缺口
```

## 5. 复盘补强闭环（第一阶段的核心）

### 5.1 复盘把什么变成系统资产

| 系统资产 | 来自复盘的什么 | 怎么用 | 晋级规则 |
|---|---|---|---|
| **案例库** | 每个异常的完整记录：解释报告、事后打标、结局 | 一切统计的基础；新异常检索相似历史案例并展示 | 全部保存，包括失败和"原因未明" |
| **模式库** | 反复出现的"触发类型 → 传导 → 资金行为 → 结局"组合，例如"应用榜单登顶 → 主题叙事上涨 → 20 日回吐 70%" | 新异常命中模式时，显示历史同类的回吐比例、持续时间、基本面兑现率 | 候选 → 观察（≥ 10 例）→ 有效（≥ 30 例，且在保留样本上成立）；只展示统计，不直接触发交易 |
| **归因权重** | 每个证据维度事后是否有区分度 | 调整第三部分第 5.2 节的权重 | 季度调整一次；每次幅度有上限；用保留样本验证 |
| **图谱边强度** | 预测影响范围 vs 实际 | 调整关系强度、机制类型 | 沿用因果边阶梯 |
| **篮子定义** | 自动聚类发现的"未命名篮子"；成员漂移 | 新增 / 拆分 / 合并篮子 | 人工命名确认 |
| **信源缺口清单** | 漏检报告里"信源没覆盖"的条目 | 数据接入建议，按出现频率和影响排序 | 你决定是否采购 |
| **先兆特征库** | 每个异常发生前 T−5 到 T−1 的状态快照，加上对照样本 | 为 C3 做准备（第 6 节） | 样本足够后评估 |
| **交易规则候选** | 规则对照（被冷静期挡掉的、被止损卖掉后反弹的、该减没减的） | 进 Muse 治理流程：一次一条、PIT 回测、拍板 | 沿用 Muse |

### 5.2 复盘的节奏

| 节奏 | 做什么 | 谁做 |
|---|---|---|
| **T+1** | 昨日异常初步打标：类型候选是否合理、有没有当时没捞到的信息 | 系统自动 + 系统日志提示 |
| **T+5** | 资金轨道：回吐比例、是否延续；资金放大类型是否被后续走势支持 | 系统自动 |
| **T+20 / 截止日** | 三轨结论；市场归因与基本面成立度事后打标 | 系统起草，你每周批量确认 |
| **下一份财报** | 基本面最终结论；估值区间变化是否方向正确 | 系统自动 |
| **每周** | 漏检报告；模式库新增 / 晋级候选；需要你确认的打标 | 你，约 30 分钟 |
| **每月** | 归因校准报告；交易规则对照；信源缺口排序 | 你拍板 |
| **每季度** | 权重和参数调整（经保留样本验证）；能力阶梯评估（C1 → C2 是否达标） | 你拍板 |

### 5.3 防止"复盘越多越过拟合"

沿用第二部分第 11 节：按事件家族划分样本；保留样本只用一次；登记全部尝试；模式只展示统计、不直接交易；交易规则改动一次一条；样本不足宁可"继续观察"。

另加两条：

- **相似案例展示时必须同时展示反例**（同类触发但结局相反的案例），防止只看到支持当前判断的历史；
- **"原因未明"的案例和失败案例与成功案例同等保存**，并单独统计它们的占比变化。占比下降才说明系统在进步。

## 6. 为"感知"做准备：先兆特征库

### 6.1 为什么第一天就要开始

C3 先兆识别需要大量"异常发生前的状态"样本，以及同样多"状态相似但没发生异常"的对照样本。这些只能从现在开始逐日积累，事后无法补齐（特别是叙事热度、榜单、期权快照这类不保留历史的数据）。

### 6.2 每日为每只标的、每个篮子存一份状态快照

| 维度 | 特征 |
|---|---|
| 拥挤度 | 6 个月涨幅分位、篮子内部相关性、与动量因子的暴露 |
| 空头 | 空头占流通股比例、回补天数及其变化 |
| 期权 | 看涨 / 看跌持仓比、隐含波动率分位、偏度、到期集中度 |
| 叙事热度 | 独立来源数、搜索热度、榜单名次变化 |
| 估值 | 估值区间位置 p、隐含增长 vs 一致预期 |
| 价格结构 | 距均线、波动率分位、连续涨跌天数 |
| 预期 | 一致预期修订方向和广度 |

### 6.3 评估方式（达到样本门槛后）

- 对每类异常，比较"发生前 5 天"和"对照样本"的特征分布，找出有区分度的组合；
- 用时间顺序的保留样本检验预测提升（例如：某个组合出现后 10 日内发生踩踏的概率，是否显著高于基础概率）；
- 通过后先作为"风险提示"展示，前向运行验证，再考虑进入仓位规则（例如：拥挤度极高的主题降低估值系数上限）。

## 7. 第一阶段验收

| # | 验收项 | 标准 |
|---|---|---|
