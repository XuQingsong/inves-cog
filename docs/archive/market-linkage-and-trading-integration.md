### 0.2 stock-pm 已经实现、本文直接复用的机制

你要的"快慢机制"，stock-pm 的 Brain 已经有很大一部分，本文**不重做**，只在其上扩展：

| 你的需求 | stock-pm 已有实现 | 位置 |
|---|---|---|
| 快慢分层 | 五层认知架构：观察层（新闻、事实、事件、价格）→ 市场层（预期、市场关注、市场假设、价格背离）→ 状态层（公司 / 行业 / 宏观状态、暴露度、影子状态）→ 投资推理层（驱动因子、核心论点、财务影响、情景、估值状态、投资命题）→ 结构知识层（商业模式、因果边）。只有前两层可以自动提交 | `brain/types.py`、`brain/layers.py` |
| 价格不能改基本面 | "宪法"规则：价格不能修改基本面论点和状态；新闻不能改核心论点；事件 / 价格不能修改财务影响、情景、估值、投资命题；"无法解释的价格变动不等于错误定价" | `brain/constitution.py` |
| 小道消息隔离 | 低可信度 / "据报道""小作文"类信息进入**影子状态**，不出现在当前状态里；确认后也只能"提议"改状态 | `brain/shadow.py` |
| 不被单条新闻带偏 | 滞回：新闻类来源要改变论点状态，需要 ≥ 2 条独立反证，且每次只能跳一级 | `brain/hysteresis.py` |
| 变更需审批 | 变更提案：违反宪法 → 拒绝；慢层变动超出预算 → 待审核；否则批准 | `brain/phase0.py`、`brain/budget.py` |
| 价格背离 | 价格-基本面背离对象："价格是传感器，不是证据"。单日 ≥ 5% 或相对同行 ≥ 4% 且"基本无法解释"时开启，后续新闻解释后关闭；价格本身不能作为关闭依据 | `brain/divergence.py` |
| 同行对照 | `peer_pattern`：本股 ≥ 5% 且同行都 ≤ 1.5% → 公司特有；同行均值 ≥ 3%、≥ 60% 同向、与本股差 ≤ 4 → 板块 / 宏观 | `brain/hypothesis.py` |
| 传导链 | 事件 → 状态 → 暴露度 → 驱动因子 → 论点 → 财务 → 情景，不允许跳层；"仅相关"的暴露不能影响论点 | `brain/transmission.py`、`brain/exposure.py` |
| 连接需要证据 | 因果边状态阶梯：候选 → 观察到 → 有支持 → 已确立；新边一律从候选开始；价格不能创建已确立的边；新闻类要升到"有支持"需 ≥ 2 条独立支持 | `brain/causal.py` |
| 市场在交易什么 | 市场关注（对齐 / 部分 / 无法解释）、市场驱动假设（AI 需求、客户集中、估值、板块宏观、公司特有）；"市场假设不是事实" | `brain/market.py` |
| 信源分级 | 可信事件 1–4 级信源（官方 / 一线媒体 / 卖方 / 聚合）；官方事实才能定方向 | `events/policy.py` |
| 宏观需要市场确认 | 宏观传导需 ≥ 2 个独立确认通道、同一时间窗口、3 天内 | `decision/causal.py` |
| 闭环 | 预测打脸：时间窗 + 涨跌边界，破界自动打脸，改口留痕 | `prediction.py` |

## 1. 原则

### 1.1 沿用 stock-pm 的宪法，不另起一套

第 0.2 节的宪法、影子状态、滞回、因果边阶梯、变更提案规则，全部适用于新增的联动机制。新增对象必须挂到五层认知架构的某一层，并遵守该层的写入权限：

| 新增对象 | 所属层 | 能否自动提交 |
|---|---|---|
| 异动簇、线索 | 观察层 | 能 |
| 联动事件（候选、市场确认）、市场分层画像 | 市场层 | 能 |
| 联动事件的基本面核查结论 | 状态层 | 不能，走变更提案 |
| 全局行业关系边 | 结构知识层 | 不能，新边一律"候选"，升级走证据阶梯 |
| 交易覆盖层 | 不属于 Brain，属于桥（第 7 节） | 由规则生成，只读 Brain 结论 |

### 1.2 新增原则

| # | 原则 | 含义 |
|---|---|---|
| P1 | **研究与交易单向依赖** | stock-pm 不读 Muse 的持仓和盈亏；Muse 不读 stock-pm 的原始新闻，只读覆盖层 |
| P2 | **覆盖层只能让交易更保守** | 暂停新开、首笔减半、撤销买单，都是"少做"；任何"多做"（例如止损复核）必须先回测。估值规则 V1–V3 属于 Muse 自身规则（第 18.6 节），按治理流程单独验证 |
| P3 | **离散快照** | 覆盖层按版本发布，Muse 每次扫描读确定的一版；缺失时 Muse 照常运行并标注 |
| P4 | **新规则走 Muse 治理流程** | 影响交易的每条规则：一次一条、PIT 回测、与定版对比、拍板 |
| P5 | **状态不压缩成一个分** | 消息真实性、叙事传播、市场关联、经营传导、交易状态分开展示（第 4.4 节）；不用一个红绿灯或总分代替 |
| P6 | **未知必须有终点** | 每个待核查问题有截止日；到期必须落到"支持 / 反证 / 转条件风险"之一，不能自动续期（第 4.6 节） |
| P7 | **诚实覆盖** | 没接通的数据显示"未接通"；检测覆盖不足时不称"全市场结论"；转载数量不等于独立证据数量 |

## 3. 模块一新增：市场结构与发现

建议放在新包 `stock_pm/linkage/`，存储在 stock-pm 库的新表里，不往 `queries.py` 里堆方法（沿用 `BRAIN_V1_DESIGN.md` 5.1 节的约束）。

### 3.1 四层市场主体（补 G9）

你要求的"四个层级的动态市场"，定义如下。stock-pm 现有的 broad / sector / industry 映射前三层；size、style、factor、cross_asset 作为横向分析维度。

| 层级 | 主体与成员 | 展示与用途 |
|---|---|---|
| L1 市场整体 | 美股宽基（SPY、QQQ、IWM）、广度、利率、美元、信用、VIX | 区分整体风险、风格因素与局部异常；ETF 只是代理 |
| L2 一级行业 | 标准行业及成分、行业 ETF | 相对强弱、内部广度、集中度；ETF 涨跌不能代替内部广度 |
| L3 细分产业与主题 | 业务组（HDD、NAND、DRAM、CPU、数据中心电力…）与叙事主题（AI、存储周期…）分开登记 | 业务组按产品 / 经营暴露归类；叙事主题不冒充统一业务 |
| L4 公司与经营节点 | 公司、分部、产品、客户、供应商、核心指标 | 具体暴露和经营传导，对接 Brain 和 Muse |

规则：

- 同一公司可属于多个主题；成员和权重带生效时间。
- 组内统计至少给出：成分覆盖率、等权表现、市值加权表现、异常成员比例、离散度；**汇总按去重公司计算**，避免同一股票经 ETF 和主题重复贡献。
- **扩散只能逐层向上**：L4 异常先更新 L3；只有行业广度支持才扩大到 L2；L1 状态转换需要独立的多维证据（宽基 + 广度 + VIX / 信用）。
- **反向只做提示**：L1 冲击可以对 L4 生成"背景风险检查"，不能直接判定所有公司盈利下降。

### 3.4 异动发现：三条路径（补 G1、G6）

**输入**：三层宇宙的分钟线和日线（含盘前 / 盘后）、广域集合日线、SPY / QQQ / 行业 ETF / 风格代理。

**三条路径并行，任一触发即建立异动簇**，不要求三条同时通过：

| 路径 | 条件 | 解决的问题 |
|---|---|---|
| A 总冲击 | 一组股票原始收益同步异常（同窗涨跌超过该组自身历史波动的 3 倍，且同向比例 ≥ 60%） | 整组一起跌、但剔除大盘后个股剩余异常近零的情况（例：QQQ 和 AI 股同跌）不会被漏掉 |
| B 相对异常 | 个股收益减去市场 / 行业解释部分后，剩余异常（相对同行 ≥ 4%，或剩余 ≥ 3 倍历史波动；与 Brain `materiality.py` 一致） | 局部的个股或环节事件（例：HDD） |
| C 因子自身异常 | 宽基、行业、风格或跨资产代理相对自身历史异常 | 市场 / 风格层面的冲击，随后追踪其成分 |

辅助条件：成交量 ≥ 3 倍均量（同 `flow.py` 的放量阈值）只作描述，不单独触发。

**聚类与归层**：

1. 同一时间窗（盘后 / 盘前 / 盘中 30 分钟 / 日级）内方向一致的异常，先按时间同步和量能聚类，再用全局图谱和四层主体解释成员；不先限定"同一标签"。
2. 簇级结构判定：复用 `peer_pattern`，推广为"公司特有 / L3 环节 / L2 行业 / L1 市场"。
3. **ETF 与成分股不重复计数**；三条路径命中同一对象时合并为一个簇，保留各入口，不算三份独立证据。
4. 每个参照标注"是否可能同受该事件影响"；受影响的参照可用于分解，不能充当"未受影响"的对照。
5. **数据质量先核对**：极端分钟线先核对报价来源、复权、拆股、交易时段和异常成交条件；缺乏数据时标"待核验"，不立即生成"流动性崩溃"结论。
6. 没有足够历史时用同行差值并降级，不伪造统计显著性。

**输出：异动簇**（观察层，可自动提交）

```
cluster_id, 检测时间, 时段(盘前/盘中/盘后/日级), 触发路径[A/B/C],
成员[ticker, 所属宇宙, 涨跌%, 剩余%, 成交量倍数],
所在层级(L1–L4), 主导环节, 集中度, 扩散路径, 方向, 评级(S/A/B/C),
检测覆盖率, 缺失资产
```

簇允许合并、拆分、扩散、收缩和成员退出，变化留痕。

### 3.5 信息入口：说法、鉴伪、重要性与漏报（补 G11）

**两个发现入口**：

- **现象入口**：异动簇 → 反向检索信息（第 4.2 节）。
- **信息入口**：重要新说法、公告或观点 → 沿图谱提出"应该受影响的股票" → 看行情是否响应。
- 两个入口匹配后合并到同一联动事件，保留最初入口与发现时间。找不到原因时保留"**异动已确认，驱动未识别**"，并生成补证任务。

**说法对象**：信息抽取必须生成具体"说法"——谁、何时、对哪个实体 / 变量 / 机制、提出什么变化，量化值、兑现期、确定性和出处分开保存。原文不支持的字段保持未知，不用关键词方向补齐。

**传闻拆成两件事**：

| 对象 | 能否核实 | 进入哪里 |
|---|---|---|
| "某来源发表了该说法" | 能，是传播事实 | 叙事传播维度、市场层 |
| "该说法的内容属实" | 必须独立验证 | 未验证前进入 Brain 影子状态，不进经营事实 |

**鉴伪检查项**：原始出处、完整表述、发布时间、首次取得时间、是否旧闻重发、传播关系、独立来源数、反方材料。**晚于行情出现的报道可以解释后续传播，不能自动解释之前的下跌**。同一消息重复传播只更新传播状态，不生成新内容版本。

**重要性队列**（决定 LLM 预算先花在哪）：

1. 持仓的经营证伪或风险越限；
2. 直接量化的经营变化；
3. 异动簇中的新解释；
4. 可能改变产业关系的新机制；
5. 普通重复背景。

真实性与优先级独立：官方重大经营信息即使传播很低也必须进入核验；高热度传闻即使不进经营事实，也保留传播和异动研究。

**漏报控制**：

- 每轮保留少量"低热度新机制"探索名额（初始每日 3 条）；
- 每周随机抽样被丢弃的信息（初始 20 条）人工复核，统计后来证明重要的漏报，进入第 11.3 节漏检评价。

### 3.6 弱信号累积（补 G11）

没有明显价格异常时，也要能发现"分散的小信息拼起来的变化"（招聘、认证、设备安装、客户调整、供应商表述……）。

- **线索层**（观察层）：保存尚未形成议题的碎片，按实体、产品 / 项目、可能的经营变量、兑现期、**来源根**建立可修订的组合。未知项目先候选关联，不用同公司名称强行合并。
- **触发条件**（本期只用两个参数）：观察窗 W（初始 30 个交易日）内，来自 ≥ 3 个**不同来源根**、覆盖 ≥ 2 个**不同阶段**（例如"招聘"和"设备"）的线索指向同一经营变量，且没有直接反证 → 建立"可能发生某经营变化"的联动事件（状态"假设中"）和补证任务。
- **触发只提高研究优先级**，不升级真实性、不改 Brain 状态、不进覆盖层。
- 同源转载不增加计数；材料指向不同项目则拆分；到期未触发则归档为"未触发线索"，进入漏检评价。

### 3.7 资金面信号分级（统一两套系统的口径）

| 信号 | 来源 | 验证状态 | 用法 |
|---|---|---|---|
| 内部人公开市场买入 | Muse `insider_transactions` | Muse 已验证有效 | 基本面核查中的正面证据 |
| VIX 恐慌区 | 两边都有 | Muse 已验证有效 | 系统性冲击判定 |
| 8-K 指引变化 | Muse `eightk_filings`、stock-pm SEC 事件 | 上调弱正，下调样本不足 | 一级信源事实 |
| 大额成交（tick rule 推断方向） | stock-pm `flow.py` | 未验证 | 异动簇的辅助描述，不进判定 |
| 期权墙、Put/Call | stock-pm Alpaca / Cboe；Muse CBOE 快照 | 未验证（无历史） | 只展示 |
| CMF / OBV"吸筹 / 派发代理信号" | stock-pm `analytics.money_flow` | **Muse 已证伪同类量能信号** | **降为纯展示**，从复盘结论文案中移除"吸筹 / 派发"判断，或加"未验证"标注 |
| 卖空回补天数 | Muse | 弱 | 背景标记 |

**由同一成交序列算出的多个指标（CMF、OBV、tick rule、成交量倍数）只算一个通道**，不能冒充多个独立确认。不能凭跌幅或 Put 持仓就认定"机构卖出""做市商对冲"等具体行为；"流动性不足 / 拥挤 / 被动减仓"只作为候选解释之一。

|---|---|
| from / to 实体 | 跨公司 |
| 连接类型 | 业务关系（客户、供应、竞争、替代）、市场共振、市场叙事、经营传导（四类分开，见下） |
| 传导机制 | 供给、需求、竞争、客户 / 融资、估值倍数 |
| 方向、强度、时滞 | |
| 状态 | 复用因果边阶梯：候选 → 观察到 → 有支持 → 已确立 |
| 支持 / 反对证据 | 证据 id，必须有来源和时间 |
| 首次发现、最后有效证据、下次检查、失效条件 | 支撑第 4.6 节的跟踪终点 |

**四类连接分开存**（来自 ChatGPT 版）：业务关系是已知结构；市场共振是观察到的同步 / 分化；市场叙事是投资者在传播的解释，内容可未证实；经营传导是"某变化如何作用于需求、价格、订单、收入、成本、利润、现金流"。**市场共振和叙事不能升级成经营传导**，除非有经营证据。

**机制类型决定能传到 Brain 的哪一层**：

| 机制 | 示例 | 对应 Brain 驱动因子类别 | 能否触发基本面核查 |
|---|---|---|---|
| 供给类 | 东芝扩产 → HDD 单价 | supply | 能 |
| 需求类 | 云厂商资本开支 → 近线盘 / GPU 出货 | demand | 能 |
| 竞争类 | 份额、技术代际 | competition | 能 |
| 客户 / 融资类 | OpenAI 收入 → 合作方订单兑现 | customer / financial | 能 |
| 估值倍数类 | 主题情绪联动 | 无（只到市场层） | **不能**，只影响市场关注和背离解释 |

**初始数据**：从 `research/templates/*.json` 的问题轴、`issuer_directory.json`、Brain 已有的 `brain_exposures` 和 `brain_causal_edges` 中提取候选关系，人工审核一轮后作为种子。每条种子关系都从"候选"开始；价格共振不能把关系升到"已确立"（宪法 `price_cannot_create_established_causal_edge`）。

**新连接生成**：系统可以起草此前不存在的产品、工作负载、机制节点（例如"代理应用 → CPU 需求"），但一律进入候选库，与已确认的客户 / 供应关系分开；类比只能提出假设，不能提升真实性。

### 4.2 联动事件对象、竞争解释与影响范围（补 G4）

**新表** `linkage_events`（市场级父对象）：

```
linkage_event_id
入口：现象 / 信息 / 弱信号累积；首次发现时间
说法：[说法 id，信源等级(复用 1–4 级)，发布时间，首次取得时间]
传导链：[实体 → 关系(类型, 机制, 符号, 时滞) → 实体 ...]（引用 linkage_relations）
竞争解释：[解释 id, 传导链, 解释力, 支持 / 反证, 缺口]
影响范围：[ticker, 所属宇宙, 方向, 机制, 暴露类别(直接/间接/概念关联/纯共振), 证据, 加入/退出理由]
五维状态 + 状态历史（第 4.4 节）
生命周期阶段（第 4.5 节）
跟踪清单（含截止日，第 4.6 节）
关联异动簇
子对象：每只研究池 / 交易池股票对应的 brain_events.event_id
```

**与单票 Brain 的关系**：联动事件是父对象。对影响范围内的研究池 / 交易池股票，**调用现有的 Brain 增量更新**（`runtime.run_brain_update`），把联动事件作为一条观察输入。之后由 Brain 自己的物质性门槛、宪法、滞回、变更提案决定这只股票的状态和论点会不会变。联动引擎**不直接写**任何单票的 Brain 对象。

**竞争解释**：对每个重要异动至少检查可区分的替代解释（数量由信息决定，不强凑三条），例如"东芝扩产 / 大盘风格切换 / 某公司自身消息 / 流动性与拥挤"。不同机制可以叠加。没有校准依据时用证据强弱和缺口描述，不展示精确概率。

**解释力评分**（每条竞争解释分别打分，防止把大盘下跌归因于个别事件）：

| 维度 | 说明 | 初始权重 |
|---|---|---|
| 时间先后 | 信息发布早于或贴近异动起点；**晚于异动的信息不得分** | 25% |
| 图谱距离 | 1 跳 > 2–3 跳 | 20% |
| 覆盖率 | 簇成员中能被这条链解释的比例 | 20% |
| 方向一致 | 预测方向 = 实际方向 | 15% |
| 幅度合理 | 暴露度高的动得多 | 20% |

**影响范围**：每个对象标明直接业务暴露 / 间接传导 / 概念关联 / 纯市场共振。范围从"已知暴露"和"实际行为"共同发现，不预设"某事件利空全部 AI"。传递到下一环时重新检查业务暴露，防止无限扩散。范围变化记录加入和退出理由。

**链条强度不高于最弱环节**：市场反应确认不替代消息真实性；消息真实不替代对具体公司的盈利传导；最初用于发现异动的价格变化，不能再次作为经营证据。

**多个联动事件同时影响一只股票**：Brain 合并全部有效事件，而不是取最近一条；同一变量的相同效果按共同来源去重；相互矛盾的材料交给 Brain 的滞回和变更提案裁决。

### 4.3 市场响应与共识的检验

声明"市场正在按这条逻辑交易"（进入"市场确认"）须同时列出：

1. 可取得的最早说法或传播时间；
2. 随后对应对象的异常响应；
3. 至少一个独立于价格的传播或交易证据（报道、卖方点评、搜索量、去重后的社交来源）；
4. 市场 / 行业参照和同期替代解释。

缺最早时间、独立通道或关键参照时，只显示"关联候选"。这与 stock-pm `assess_market_confirmation` 的"≥ 2 个独立通道"一致。

**四项市场指纹**（用来排除明显不相容的解释，不保证识别唯一原因）：

| 指纹 | 检查 |
|---|---|
| 暴露梯度 | 暴露更直接的公司是否反应更强（HDD > 磁头盘片 > NAND） |
| 无暴露对照 | 没有暴露的参照是否表现不同 |
| 时序相容 | 消息扩散与价格反应的先后是否相容 |
| 反证响应 | 出现反证（如官方否认）后，反应是否减弱 |

**共识度**（补 G5）：独立来源数、搜索量相对自身历史的变化、去重后的大 V / 社交来源、卖方点评。**共识度只说明"资金在按这条逻辑交易"**，只写入市场层（市场关注 / 市场假设），不能作为基本面证据。

### 4.4 五个独立状态维度（映射到 Brain 已有对象）

每个联动事件同时展示以下五个状态，不压缩成一个分：

| 维度 | 状态值 | 改变依据 | 对应 Brain / stock-pm 对象 |
|---|---|---|---|
| 消息真实性 | 未核实 / 部分核实 / 核实 / 修订 / 证伪 | 原始来源、披露、可信反证 | 信源 1–4 级（`events/policy.py`）+ 影子状态（`brain/shadow.py`） |
| 叙事传播 | 初现 / 扩散 / 稳定 / 衰减 / 重新活跃 | 独立来源数、搜索量、社交 | 市场关注（`brain/market.py`）；共识度 |
| 市场关联 | 待观察 / 共振 / 部分符合 / 分化 / 脱钩 | 时间、相对表现、参照、持续性、市场指纹 | 价格背离（`brain/divergence.py`）、`peer_pattern`、市场假设 |
| 经营传导 | 待验证 / 局部支持 / 支持 / 冲突 / 失效 | 业务暴露、预期修正、一级信源、产业数据 | 因果边阶梯（`brain/causal.py`）、传导链（`brain/transmission.py`）、变更提案 |
| 交易状态 | 风险释放 / 初步修复 / 持续确认 / 修复失效 | 价格结构、量能、流动性 | Muse 时机账；覆盖层的 `cooling_off` |

传闻被证伪后，其内容退出经营依据，但已发生的价格冲击和传播记录保留；叙事衰减只降低研究优先级，不代表已确认的经营影响消失。

### 4.5 生命周期与覆盖层

五维状态之外，联动事件有一个**生命周期阶段**，用来驱动 Brain 和覆盖层：

| 生命周期阶段 | 进入条件 | 单票 Brain 里对应发生什么 | 交易覆盖层 |
|---|---|---|---|
| 已发现 | 异动簇、可信事件或弱信号累积触发 | 无 | 无 |
| 假设中 | 生成传导链，最优解释力 ≥ 0.5 | 市场层：生成市场驱动假设（候选）；价格背离开启（若无法解释） | 无 |
| 市场确认 | 满足第 4.3 节四项条件 | 市场层：市场关注"对齐"；价格背离转"部分解释" | 受影响的交易池股票（暴露为直接、机制非估值倍数类）：**冷静期** |
| 基本面核查中 | 机制为供给 / 需求 / 竞争 / 客户融资类 | 状态层：影子状态 + 研究问题；跟踪清单 | 首笔减半（P1） |
| 已验证·有影响 | 达到第 6.3 节门槛 | 变更提案：公司状态 / 驱动因子变更（受滞回约束）；影子状态 → 确认 | 暂停新开，直到下次财报进入 Muse |
| 已衰减·无影响 | 截止日到期证据不足 | 影子状态关闭；价格背离按"已解释（估值倍数 / 情绪）"关闭 | 解除限制；标签"情绪性折价 / 溢价" |
| 已证伪 | 官方否认、事实矛盾 | 影子状态关闭；下调信源可信度 | 同上 |

### 4.6 跟踪清单、截止与重新激活

- 每段关键连接生成可验证的问题、所需指标、来源、预计验证窗口、截止日、触发条件和停止条件。"有任务"不等于"有证据"。
- 截止日默认取：官方发布日（如下次财报）、采购 / 交付周期，或最长 20 个交易日，三者取先到者。
- **到期必须三选一**：得到支持 → 更新关系；得到反证 → 失效；仍未知 → 转为"条件风险"（保留标签，覆盖层解除冷静期，但该路径不能作为加仓依据）。不能自动续期。
- **重新激活**：只有重大新原始证据、新的异动范围或接近原定经营兑现期可以重新激活；普通转载不能重新开始验证时钟。
- 研究资源优先分配给：持仓风险 > 近期交易候选 > 可改变驱动因子的关键环节 > 重大未知异动；低相关、重复、已失效的议题降低频率。

## 5. 预期层数据打通（补 G8）

stock-pm 的决策内核和 Brain 都有完整的"预期层"逻辑（实际值 vs 财报前最新共识、共识修订、价格-预期张力），但 FMP 的预期接口不可用，导致这一层大部分为空。Muse 的 `quant` 库每天有：

- `estimates_trend`：EPS 共识（当季 / 下季 / 当年 / 次年）及 7 / 30 / 60 / 90 天回望
- `estimates_revisions`：近 7 / 30 天上修 / 下修家数
- `price_targets`：目标价均值、中位数、高低
- `earnings_history`：实际值 vs 预期

**需求**：stock-pm 新增只读同步任务，每天把交易池 + 研究池股票的上述数据同步到 stock-pm 的预期层（作为 street consensus 来源，`source=yfinance-via-quant`，带 `as_of`）。注意：

- 目标价进入的是"市场预期"，**不是**估值目标；`FORBIDDEN_VALUATION_KEYS` 不变。
- 财务实际值、管理层指引、市场共识、系统推断四者分开保存，不互相覆盖。
- Muse 的快照从 2026-10-08 起积累，修订方向的有效性约 90 天后才能验证；在此之前，修订数据只用于事件状态判断，不进交易规则。
- 观察池股票（WDC、STX）需要在 Muse 的预期抓取任务里补上，否则核查时没有预期数据。

## 6. 基本面锚与"背离"（两套系统合起来看）

### 6.1 四类锚

| 锚 | 来源 | 速度 | 谁维护 |
|---|---|---|---|
| 财务锚 | Muse 质量账、成长账、持有分（SEC 时点财报） | 季度 | Muse |
| 定性锚 | stock-pm Brain 核心论点、驱动因子、公司状态、估值方向（支持扩张 / 中性 / 压缩风险 / 不确定）、情景 | 慢（受宪法和滞回约束） | stock-pm |
| 预期锚 | EPS 共识修订、上修 / 下修家数、目标价、8-K 指引 | 中（每日） | Muse 采集，stock-pm 同步 |
| 价格侧 | Muse 估值账、时机账；stock-pm 价格背离、市场关注 | 快 | 双方 |

### 6.2 背离类型

| 类型 | 价格侧 | 预期锚 | 定性锚（Brain） | 联动事件 | 含义 |
|---|---|---|---|---|---|
| 情绪性折价 | 大跌，估值账升、时机账降 | 未下修 | 核心论点、驱动因子未变 | 已衰减 / 已证伪 / 估值倍数类 | 候选买入观察 |
| 合理重定价 | 大跌 | 显著下修，或 8-K 下调指引 | 变更提案已批准（驱动因子转弱） | 已验证·有影响 | 不买；持仓按原规则 |
| 滞后风险 | 小跌或未跌 | 显著下修 | 驱动因子转弱 | 已验证·有影响 | 持仓风险提示 |
| 情绪性溢价 | 大涨 | 未上修 | 未变 | 估值倍数类 | 不追 |
| 基本面驱动上涨 | 大涨 | 显著上修 | 驱动因子转强 | 已验证（正向） | 正常走 Muse 门槛 |

初始阈值："未下修" = 当年 EPS 共识较 7 天前变化 > −2% 且下修家数 ≤ 上修家数；"显著下修" = 较 7 天前 ≤ −3%，或近 7 天下修家数 ≥ 覆盖家数 30%。阈值约 90 天样本后按 Muse 方法重新标定。

### 6.3 "已验证"门槛（满足其一）

| 证据 | 门槛 |
|---|---|
| 公司一级信源 | 8-K 指引变更、财报电话会定量表述 |
| 预期修正 | 覆盖分析师 ≥ 30% 同向修正，且共识变化超过阈值 |
| 产业数据 | ≥ 2 个独立来源根的二级 / 三级信源定量数据同向 |
| 竞争对手一级信源 | 经全局图谱映射到本公司驱动因子 |

**不能作为证据**：股价、资金流、共识度、社交热度、单一四级信源、已证伪信号、同源转载。这与 stock-pm 宪法完全一致。

### 6.4 经营约束核查（供给类 / 需求类事件必做）

供给或需求类事件进入"基本面核查中"后，跟踪清单必须包含一张**约束核查表**，不能用一个"增长 / 下滑"参数替代：

| 环节 | 东芝扩产案例中的问题 |
|---|---|
| 新增供给规模 | 扩产量占行业近线盘需求增量（EB）的比例 |
| 投产时间与良率爬坡 | 哪个财季开始有可交付量 |
| 产品代际 | 是否覆盖高容量近线盘（WDC / STX 的利润来源） |
| 需求吸收 | 云厂商资本开支能否吸收新增供给 |
| 订单 vs 可交付 | 已有订单 / 积压能否锁定价格 |
| 价格传导 | 合约价、交期是否出现变化 |

核查结果只有四种：约束可计算且冲击有限 / 约束可计算且冲击实质 / 约束不清但有可信上下界（保持"核查中"）/ 关键约束冲突（转"条件风险"）。这张表是 Brain 驱动因子变更提案的证据附件，不直接改任何分数。

### 6.5 慢层仍然各走各的路

- Muse 的财务账只随新财报更新；
- stock-pm 的核心论点只能通过变更提案 + 滞回改变；
- 联动事件"已验证"本身**不改**任何一方的慢层，它的作用是在财报到来前，阻止 Muse 在"即将变差的基本面"上新开仓。

## 7. 桥：交易覆盖层与 Muse 侧新规则（补 G10）

### 7.1 覆盖层契约

stock-pm 每个交易日北京时间 **20:30 前**生成：

- HTTP 只读接口：`GET /api/linkage/overlay?date=YYYY-MM-DD`
- 文件：`event_overlay_YYYY-MM-DD.json`（按 Muse 同步方案投递到 `paper_live/`）

```
version, generated_at, source_events_asof, params_version
tickers: {
  "<TICKER>": {
    linkage_events: [id, 生命周期阶段, 五维状态, 机制, 暴露类别],
    brain: { core_claim_changed: bool, divergence_status, valuation_direction },
    expectation: { eps_0y_chg_7d_pct, down7, up7, coverage },
    cooling_off: bool,              # 冷静期：暂停新开 / 撤单
    first_lot_multiplier: 1.0|0.5,  # 核查期首笔比例
    divergence_tag: 情绪性折价|合理重定价|滞后风险|情绪性溢价|基本面驱动上涨|null,
    stop_review_eligible: bool,     # 止损复核资格（回测通过前恒为 false）
    reason: 中文说明（可追溯到联动事件和证据）
  }
}
market: { risk_level: 正常|警戒|危机, l1_state, systemic_events: [...] }
```

覆盖层由规则生成，只读 Brain 和联动事件的结论；它属于"桥"，不是 Brain 的一层，所以不受 stock-pm 主路径"买卖用语禁令"的约束，但也不在研究主路径页面展示。

### 7.2 Muse 盘前扫描读取覆盖层（P0，修补接刀漏洞）

1. `cooling_off = true` → 不生成买单，写入 `skipped`："事件冷静期：联动事件 xxx"。
2. 当日覆盖层把某只股票设为冷静期，而它已有 `pending_buys` → **撤销该买单**。这是接刀漏洞的修补：盘后暴跌的股票，次日开盘低于触发价时会按开盘价自动成交。
3. `first_lot_multiplier = 0.5` → 首笔减半（P1，与"距 MA50 > 15% 减半"是否叠加由回测决定）。
4. 覆盖层缺失或过期（`generated_at` 早于当日 18:00）→ 照常运行，盘前报告标注"事件覆盖层缺失"。

这条只会让 Muse 少买，风险最低，建议作为 P0 唯一进入 Muse 的规则。上线前仍按 M7 做一次 PIT 回测，报告"被撤单的股票此后 5 / 21 日表现"，确认没有系统性错杀。

### 7.3 事件闸门（P2，回测后才启用）

这是你要的"战争、关税、疫情时止损不机械执行"，是 VIX 恐慌闸门在个股层面的推广：

| 条件 | 要求 |
|---|---|
| 事件 | 系统性外生冲击（战争、关税、疫情、流动性危机）且 VIX 恐慌区；或机制为估值倍数类的主题连带 |
| 个股 | 当日相对 SPY 和板块的超额收益接近 0（下跌主要来自 beta）；无"已验证·有负面影响"的联动事件；Brain 核心论点未变 |
| 基本面 | 无基本面死亡红线；预期锚未显著下修 |

闸门打开后只能：卖出一半；剩余设二级止损（原止损再下移一档：防守 −4%、普通 −6%、进攻 −9%，初始值）；最长 5 个交易日，到期重新判定，不能续期。

**硬线不受闸门影响**：基本面死亡清仓；单票亏损超过总权益 1.5%（Muse 满仓单票按原止损的最大亏损约 1.44%，硬线设在其上方，只约束闸门放宽的部分）；黑天鹅规则。

闸门判定必须写在盘前覆盖层里（`stop_review_eligible`），因为 Muse 的结算是盘后用 1 分钟线回放，不能盘中临时判断。

### 7.4 其他候选规则（P2，逐条回测）

- 观察名单波段（v18 回测已有）只在"情绪性折价"标签下允许入场；
- "滞后风险"触发减仓；
- 扩池：观察池股票反复出现"情绪性折价"且四本账能过门槛 → 扩池候选清单（需先为其补 SEC PIT 财报和预期数据）。

### 7.5 美元价值（v0.5 已改为引入，见第 18 节）

v0.4 暂不引入美元价值。v0.5 的结论是：在**模块二**引入**机械估值区间**（悲观 / 中性 / 乐观），而不是 ChatGPT 版那种按人工经营模型推出的单一合理价值和"可执行买价"。区别在于：

- 规则固定、输入只来自财报和一致预期、可以 PIT 回测，不需要逐只手工建模；
- 不改 Muse"能不能买"的门（时机账否决保留），只影响买多少、拿多久、何时减；
- 只在模块二的 `/paper/*` 区域展示；stock-pm 研究主路径的 `FORBIDDEN_VALUATION_KEYS` 和 `test_main_path_copy_gate.py` 保持不变。

事件闸门（第 7.3 节）增加一个估值条件：价格低于悲观值且悲观值未下修，才算"情绪性折价"，可以申请止损复核（第 19.3 节）。

#### 分支 A：影响有限

| 证据 | 结果 |

系统动作：

1. 五维状态：真实性 核实 / 叙事 衰减 / 市场关联 部分符合 → 分化（WDC / STX 开始跑赢 HDD 供应链）/ **经营传导 失效** / 交易状态 初步修复。
2. 生命周期 → "已衰减·无影响"；影子状态（"东芝扩产可能压低 HDD 价格"）关闭。
3. 覆盖层：解除冷静期；WDC / STX 标签"情绪性折价"。

5. 交易含义：时机账 38 低于任何一层入场线，Muse **不会立刻买**。这是趋势型时机账的设计结果，也是防接刀的天然保护。之后要么等时机账修复过线（可叠加内部人放大 ×1.20），要么在 P2 回测"情绪性折价 + 观察名单波段"规则。
6. WDC / STX 多次出现"情绪性折价"后进入扩池候选清单。

#### 分支 B：基本面受损

| 证据 | 结果 |
|---|---|
| 扩产规模大、投产快、覆盖高容量近线盘 | 约束核查：可计算且冲击实质 |
| 渠道调研出现近线盘降价（两个独立来源根的二 / 三级信源） | 产业数据过门槛 |
| 近 7 天下修 9 家（45%），当年 EPS 共识 −6%，目标价中位数 −15% | 预期修正过门槛 |
| 管理层回应含糊或 8-K 下调指引 | 一级信源 |

系统动作：

1. 五维状态：经营传导 支持；交易状态 修复失效。
2. 生命周期 → "已验证·有影响"。
3. 覆盖层：WDC / STX 标签"合理重定价"；若在交易池，冷静期延续到下一次财报进入 Muse 的财务账。
4. 估值账"变便宜"是假象：预期锚已经提前下修。下一次财报后，Muse 成长账、质量账会按 PIT 下调（示意：质量 72 → 64，成长 80 → 62）。
5. 复盘时提高"龙头扩产类"关系的强度。

### 10.1 OpenAI ARR 低于预期（四级信源、大范围扩散）

| 联动发现 | 原始信源为分析师透露、媒体转发 → **四级**，可信度低，共识度极高 |
| 五维状态 | 真实性 未核实 / 叙事 扩散 / 市场关联 共振 / 经营传导 待验证 / 交易状态 风险释放 |
| Brain 处理 | 各股按宪法进入**影子状态**（"OpenAI 收入不及预期可能影响算力订单"），只产生研究问题；价格背离开启，解释等级"部分解释" |

| 对 Muse | 持仓 NVDA、AVGO、MRVL、GOOGL、META 多为低暴露 → 不冻结；若系统性下跌触发止损，按 9.5 的闸门逻辑 |

要点：**信源可信度低 + 共识度高** = 市场在按这条逻辑交易，但基本面没有证据。五维状态把"叙事扩散"和"经营传导待验证"分开展示，正是为这种情况。

### 10.2 Meta Muse 登顶 App Store（利好，推导链弱）

| 阶段 | 系统表现 |
|---|---|
| 异动 | META 与 CPU 概念股（交易池 AMD）同步上涨 |
| 传导链 | ① Muse 用户增长 → META 用户时长 / 变现（直接）；② 多任务 / 智能体模式 → 服务器 CPU 需求（2–3 跳推导，新建"代理工作负载"节点，进候选库） |
| 鉴别 | 下载排名不等于使用量；多任务不等于 CPU 占比；工作量不等于新增订单 —— 链 ② 断点标在"工作负载 → CPU 采购" |
| Brain 处理 | 链 ① 对 META：新闻不能改核心论点（宪法），进入市场层"市场关注"；链 ② 对 AMD：图谱关系为候选，估值倍数机制，不进核查 |
| 跟踪清单 | Muse DAU / 留存、META 资本开支中 CPU 采购表述、CPU 厂商数据中心指引、预期修正 |
| 对 Muse | META 持仓正常（触及止盈 865.07 按规则减 1/3）；AMD 若过热（RSI > 80 且距 MA50 > 15%）已被 Muse 过热过滤挡住；标签"情绪性溢价"直到出现上修证据 |

### 10.3 失败案例：错连（消息晚于下跌）

假设 STX 在美东 15:30 开始下跌，东芝扩产报道 16:45 才发出。

- 解释力"时间先后"维度对东芝扩产得 0 分；它只能解释 16:45 之后的盘后传播，不能解释 15:30 的下跌。
- E-001 的最优解释不足 0.5 → 停留"已发现"，页面显示"**异动已确认，驱动未识别**"，并生成补证任务（检索 15:30 前的信息、期权异常、大宗交易）。
- 若之后发现 15:30 前有渠道调研流出，新建解释并按时间重新评分；原记录保留，不倒填。
- 验收要求：系统不能把晚到的报道当作下跌原因。

### 10.4 影响有限的事件

解释力低或共识度不达标 → 停留在"假设中"，截止日转"已衰减"，不触发 Brain 增量运行，不生成覆盖层条目。复盘统计这类"短暂异动后回落"的规律，作为"情绪性溢价"判定的候选因子。

### 11.2 独立结果标签

每个环节单独评价，**方向猜对但原因错误，不算传导验证成功**：

| 评价对象 | 标签 |
|---|---|
| 消息内容 | 支持 / 反证 / 修订 / 仍未知 |
| 市场连接 | 指纹支持 / 部分支持 / 冲突 / 无法识别 |
| 经营连接 | 兑现 / 未兑现 / 相反 / 尚未到期 / 到期仍未知 |
| 交易执行 | 是否遵循生效规则（盈利不等于执行正确） |
| 规则效果 | 收益、回撤、成本、换手、错失机会、**错误阻断** |

"尚未到期"不计成败；"到期仍未知"计入无法识别，不当作"无影响"。

### 11.3 独立漏检评价

只统计"系统发现的事件里有多少对"会掩盖漏报。另设一个**独立于系统候选的样本框**：

- 每月从以下来源分层抽样：未达阈值的行情异动、未触发的线索、被丢弃的消息、广域集合中未输出的公司；
- 人工判定"是否是应发现的事件"（不看系统是否发现）；
- 分别报告检出率（独立目标中被发现的比例）和正确率（系统输出中正确的比例），未知和数据不覆盖单列，不悄悄从分母剔除。

| 漏检发生在哪一环 | 闭环动作 |
|---|---|
| 证券 / 来源不在覆盖范围 | 记为覆盖漏检，提数据接入建议（第 3.3 节） |
| 有数据但异动 / 累积入口未触发 | 记为检测漏检，检查阈值和观察窗 |
| 议题已启动但没提出关键中间机制 | 记为连接生成漏检 |
| 机制已提出但没查到当时可得的资料 | 记为补证漏检 |

例：受控目标 20 个、系统只发现 5 个且全对 → 报告"检出 25%、漏检 15"，不能因"正确率 100%"就发布。

### 11.4 验证纪律（防过拟合）

- 不能用单个事件（一次东芝扩产）定参数；
- **按事件家族划分样本**：同一根源的原始消息、后续认证、订单与指引修订属于同一家族，不能拆到训练和验证两边；
- 时间顺序划分开发 / 验证样本；最终验证集只用一次，看过并据此修改后即转为开发集；
- 登记全部尝试过的候选和参数，不只保存获胜者；
- 每次比较同时看收益、回撤、成本、换手、错失机会和错误阻断；
- 参数版本化，交易决策记录参数版本；
- Muse 现有结论来自单一 9 个月涨市窗口、30 只事后赢家池，事件类规则同样要声明样本窗口；样本不足就继续研究，不发布；
- 复盘只产生修改建议，不在线自动改权重、门槛、止损或交易池。

2. **主题连带不冻结**：E-001 对 MU 为估值倍数机制 → MU 的 Brain 传导链在暴露度处停止；覆盖层 `cooling_off = false`。
3. **接刀漏洞修补**：T0 有 STX 买单（触发价 100），T0 盘后 E-001 市场确认 → T+1 盘前该单被撤销，`skipped` 有"事件冷静期"，开盘 88 不成交。

5. **小道消息隔离**：四级信源事件 → 受影响股票只产生影子状态和研究问题，不出现在当前状态里。
6. **误扩散识别**：同时段 NAND 股因大盘下跌 → 不进入 E-001 的核查范围。
7. **分支 A**：证据不达门槛 → 事件衰减 → "情绪性折价" → Muse 仍按时机账门槛判断。
8. **分支 B**：修正广度 45% → 事件验证 → "合理重定价" → 冷静期延续到下次财报。
9. **硬线不受闸门影响**：基本面死亡、单票亏损超过总权益 1.5% 立即清仓。
10. **闸门有边界**：只能"卖一半 + 二级止损 + 5 日期限"，不能续期。
11. **覆盖层缺失降级**：stock-pm 停止发布 → Muse 正常扫描并标注"事件覆盖层缺失"。
12. **未验证信号不进规则**：大额成交、期权、CMF / OBV 只出现在展示层；同一成交序列的多个指标只算一个通道。
13. **研究主路径用语不变**：`/market`、`/`、`/stock`、`/brain` 不出现买卖和仓位用语、不出现美元合理价值（现有 `test_main_path_copy_gate.py` 继续通过）；只有 `/paper/*` 和覆盖层使用交易语义。
14. **整体冲击不漏**：QQQ −3%、AI 股同跌、个股剩余异常近零 → 路径 A 或 C 建立异动簇。
15. **ETF 不重复计数**：同一股票经 ETF 和主题出现 → 组统计按去重公司计算；三条路径命中同一对象只算一个簇。
16. **晚到消息不归因**：消息发布时间晚于异动起点 → 该解释"时间先后"得 0，系统显示"驱动未识别"。
17. **五维不压缩**：传闻被证伪后，真实性 = 证伪，但价格冲击和传播记录保留；页面同时显示五个维度。
18. **截止日不续期**：截止日到期仍未知 → 转"条件风险"并解除冷静期；普通转载不能重启时钟。
19. **转载不算独立证据**：同一来源根的 10 篇转载 → 独立来源数 = 1。
20. **弱信号只提优先级**：3 个来源根、2 个阶段的线索触发议题 → 不改 Brain 状态，不进覆盖层。
21. **未接通如实显示**：搜索量未接通 → 共识度面板显示"未接通"，不显示模拟值。
22. **漏检有独立分母**：抽检样本中系统漏掉的事件计入检出率分母，不能只报告正确率。
23. **版本可追溯**：任意一条 Muse 跳过 / 撤单记录 → 可追到覆盖层版本、参数版本、联动事件和证据。
24. **一键入池**：输入一个新代码 → 自动完成证券核对、数据补齐、分类、打分、估值；任何一步失败都显示原因，不静默跳过。
25. **价格不改价值**：股价单日 −20%、财报和一致预期不变 → 悲观 / 中性 / 乐观值不变，只有区间位置变化。
26. **周期股不被 TTM 误导**：利润率处于近 10 年 90 分位以上的周期股 → 估值使用归一化盈利，旧口径"便宜"、新口径"偏贵"时两者都显示。
27. **估值可复现**：同一天、同一参数版本重算 → 结果完全一致；人工调整单独标记。
28. **同样过线，离价值近的买得多**：两只股票都通过 Muse 门槛，p 分别为 0.42 和 0.78 → 前者首笔权重更高。
29. **超过乐观值不新开**：p > 1.0 → 估值系数 0，盘前计划显示"不新开：高于乐观值"。
30. **便宜但基本面受损不买**：p < 0 且悲观值在下修 → 估值系数 0，标签"合理重定价"。
31. **价值上修恢复加仓资格**：财报后中性值上修使 p 从 0.9 降到 0.6 → 恢复确认加仓资格。
32. **组合约束生效**：新买入会使 L3 主题超过 25% 或总在险超过 10% → 按剩余额度缩减或跳过，并写明原因。
33. **幸存者偏差控制**：回测按当时的池子成员计算，被降级或冻结的标的保留在历史样本中。

## 17. 标的管理系统

### 17.1 目标

任何一只美股都可以被加入系统，加入后**自动**完成数据补齐、四本账打分、估值区间计算和分类，之后每天更新。交易池不再是固定的 30 只，而是"通过数据和估值门槛的候选池"。这同时缓解 Muse 现有结论最大的偏差：30 只是事后挑出的赢家。

## 18. 估值体系：沿用 Muse 打分，还是另建估值？

> **v0.9 修订**：估值区间第一阶段只读、只展示，不参与仓位与交易；本节的 V1 / V2 / V3 改为影子运行。算法以 [`universe-muse-spec-and-valuation-v1.md`](universe-muse-spec-and-valuation-v1.md) 第 4 节为准。

### 18.1 两种思路的本质区别

| | Muse 打分法 | 目标价法 |
|---|---|---|
| 起点 | 现价 | 自己判断的"值多少钱" |
| 问的问题 | "按现价，这家公司的倍数在固定刻度上算便宜吗？" | "价格离我认为的价值有多远？" |
| 输出 | 0–100 分，过线即买 | 一个目标价，低于目标价若干即买 |
| 优点 | 机械、可回测、没有主观判断 | 能回答"值多少钱""还能涨 / 跌多少"，能直接用于仓位 |
| 缺点 | 不知道下行空间有多大；刻度跨行业通用 | 目标价往往是主观的，难以验证，容易锚定 |

### 18.2 Muse 打分法的问题（来自代码和 V10 诊断，不是推测）

估值账由四项组成，用**固定的绝对刻度**打分（`paper_trade_2026.py:compute_books`）：PE(TTM) 35%、PEG 近似 25%、PS 20%、FCF 收益率 20%。由此产生四个具体问题：

| 问题 | 证据 | 后果 |
|---|---|---|
| ① 刻度跨行业通用 | PE 20 → 72 分，对软件和对银行一样 | V10 诊断 P2：AMD 全年 192 天、AVGO 149 天被估值账挡死；v12 用"PEG 补丁"缓解 |
| ② 只用过去 12 个月（TTM） | 没有前瞻预期，没有周期位置 | **周期股陷阱**：存储类公司在盈利顶点时 PE 最低、估值账最高。MU 在 6 月高点附近估值账依然好看，随后一个月 −36%，占组合最大回撤的 63%，V10 至今未解 |
| ③ 只给分数，不给空间 | 70 分不知道对应"还能跌 10% 还是 40%" | 仓位只能按层上限 × 首笔比例，无法按风险收益比分配（第 19 节） |
| ④ 止盈是固定百分比 | 前向纸面 +15 / +20 / +25% 卖 1/3 | 与价值无关：低估的股票过早卖出，高估的股票卖得太晚 |

**它做对的地方也必须保留**：完全机械、只用当时可见的数据、可以 PIT 回测；红线和四本账的"能不能买"判断有回测支撑（v18：+49.45%，SPY +13.98%）；新规则一次一条地验证。

### 18.3 主观目标价法的问题

- **不可验证**：人或 LLM 给的目标价没有当时的版本记录，没法做 PIT 回测；Muse 已经证伪了"分析师评级升降级"这类信号。
- **锚定**：给了目标价以后，价格跌破目标会倾向于加仓，正好违背"不接飞刀"。
- **过拟合**：每只股票都能编出一个合理的目标价。
- **与宪法冲突**：stock-pm 禁止研究主路径输出目标价，因为价格和叙事会污染基本面判断。

### 18.4 结论

**两者都不单独采用，而是"Muse 打分管能不能买，机械估值区间管买多少、拿多久、何时减"。**

1. **保留 Muse 作为"能不能买"的门**：红线 + 四本账 + 分层门槛 + 盘前机械下单，逻辑不变。
2. **新建一个机械估值引擎**，输出的不是一个目标价，而是"悲观 / 中性 / 乐观"三个价值，以及价格在区间中的位置。规则固定、输入只来自财报和一致预期、结果每天可复现、可以 PIT 回测。**不做任何人工拍脑袋的目标价。**
3. **估值进入交易的三个入口**，每个都作为 Muse 的一条新规则、按治理流程单独回测：
   - 规则 V1：用"区间位置"替换估值账里的绝对刻度（解决问题 ① 和 ②）；
   - 规则 V2：仓位系数随区间位置变化（解决问题 ③，第 19 节）；
   - 规则 V3：止盈改为按价值减仓（解决问题 ④）。
4. **价格不能改价值**：估值区间只随财报、一致预期、Brain 的情景判断变化，不随股价变化。这与 stock-pm 宪法同一个精神。
5. **放在模块二**：你的模块二本来就叫"估值与交易"。美元价值只在模块二的页面出现；stock-pm 研究主路径的"禁止目标价"规则不变。这就是第 0.5 节 Q6 的答案。

### 18.5 估值引擎设计

**五种估值类型**（入池时自动分类，可人工修正并留痕）：

| 类型 | 典型标的 | 主方法 | 交叉检查 |
|---|---|---|---|
| 稳定盈利 | AAPL、MSFT、V、JNJ、COST、WMT | 未来 12 个月 EPS × 本股 5 年 PE 分位带（20 / 50 / 80 分位） | FCF 收益率分位带 |
| 成长盈利 | NVDA、AVGO、META、GOOGL、AMZN、NFLX | 未来 12 个月和次年 EPS × 增速调整后的 PE 带（本股历史 PEG 分位） | 反向 DCF：现价隐含的 5 年增速 vs 一致预期 |
| **周期** | MU、WDC、STX、XOM | **归一化盈利**：近 7–10 年营业利润率中位数 × 当前营收 → 归一化 EPS × 周期中枢 PE；顶部附近对当期 EPS 只用低倍数 | 市净率 / EV/Sales 分位带；标注"当前利润率处于历史第几分位" |
| 未盈利成长 | 未盈利 SaaS、早期平台 | EV/Sales × 增速（Rule of 40）的同行分位 | 现金跑道 |
| 金融 | JPM | P/B × ROE 对应分位 | P/E 分位带 |

**输入**（全部带"当时可见"时间戳）：

- SEC 财报历史（PIT，Muse 已有 `fetch_financial_facts`，约 2009 年起）；
- 一致预期（Muse yfinance 快照，2026-10-08 起）：均值、高、低；
- 本股自身的历史倍数分布（按季度重算，5 年窗口）；
- Brain 情景标签（若有基线）：看多 / 中性 / 看空，**只决定用一致预期的高 / 均 / 低哪一档**，Brain 本身不写任何数字（遵守 `FORBIDDEN_VALUATION_KEYS`）；
- 联动事件"已验证·有影响"：强制把中性档切到低一档预期，直到下次财报。

**输出**（每只标的每天一行，表 `valuation_ranges`，属于模块二）：

```
ticker, as_of, 估值类型, 方法版本, 参数版本,
悲观值, 中性值, 乐观值,
现价, 区间位置 p = (现价 − 悲观) / (乐观 − 悲观),
赔率 = (中性 − 现价) / (现价 − 悲观)（现价低于悲观时显示"低于悲观值"）,
隐含增长（反向 DCF）, 一致预期增长, 利润率历史分位（周期类）,
变化原因（财报 / 预期修正 / 情景切换 / 方法更新）, 人工调整标记
```

**更新规则**：

| 触发 | 重新计算什么 |
|---|---|
| 每日收盘 | 只更新现价、区间位置、赔率（价值本身不动） |
| 一致预期变化 > 2% | 重算价值 |
| 新财报 | 重算价值和历史分位 |
| Brain 情景变更提案获批、联动事件"已验证" | 切换预期档位 |
| 每季度 | 重算本股历史倍数分布 |

**人工调整**：允许，但必须写原因，单独标记"人工"，复盘时人工调整和机械结果分开统计。如果人工调整长期跑输机械结果，就停用人工调整。

### 18.6 估值如何进入 Muse

| 规则 | 现在 | 改为 | 验证方式 |
|---|---|---|---|
| V1 估值账口径 | 四项绝对刻度 | 估值分 = f(区间位置)：p ≤ 0 → 95，p = 0.5 → 70，p = 1 → 40，p ≥ 1.3 → 10（初始值，分段线性） | 30 只上对比 v18（重点看 AMD / AVGO 是否放行、MU 高位是否收紧），再在扩池后重跑 |
| V2 仓位 | 层上限 × 首笔比例 | 乘以估值系数（第 19.2 节） | 同上，看回撤和集中度 |
| V3 止盈 | 固定 +15 / +20 / +25% | 按区间位置减仓（第 19.3 节） | 同上，看是否过早卖掉赢家 |

顺序：V1 → V2 → V3，一次一条。V1 不过关就不做 V2。

### 18.7 数据限制与验证计划

- **可以马上回测的部分**：本股历史倍数带、周期归一化盈利，只需要 SEC 财报和历史价格，可以严格按 PIT 回测。
- **不能回测的部分**：一致预期只从 2026-10-08 开始积累，"未来 12 个月 EPS"相关的方法没有历史可回测。处理办法：回测时用 TTM 版本代替，前向运行时用一致预期版本，两者并行影子运行至少一个完整财报季，再决定是否让前瞻版本影响交易。
- **样本偏差**：只在 30 只上回测会高估效果；扩池（第 17 节）后的结果才算数。

## 19. 仓位与风险管理

> **v0.9 修订**：本节的仓位公式（风险预算 × 估值系数 × 确定性 × 事件系数）和按价值止盈改为影子运行。第一阶段仓位只按 Muse 规格执行，见 [`universe-muse-spec-and-valuation-v1.md`](universe-muse-spec-and-valuation-v1.md) 第 3 节。

### 19.1 现状与目标

Muse 现在的仓位 = 层上限（防守 / 普通 12%、进攻 8%）× 首笔比例（按成长确定性）；距 MA50 超过 15% 时减半；止损为建仓价的固定百分比（−8 / −12 / −18%）。它**不看**价格相对价值的位置、止损距离对应多少权益风险、持仓之间是否集中在同一主题。

目标：**仓位由"风险预算 × 估值位置 × 事件状态"三者共同决定，组合层再加主题和总风险上限。**

### 19.2 单票：买多少

```
目标权重 = min( 层上限 , 风险预算 ÷ 止损距离 ) × 估值系数 × 确定性系数 × 事件系数
```

| 因子 | 规则（初始值，需回测） |
|---|---|
| 风险预算 | 单票触及止损时最多亏总权益 1.25% |
| 止损距离 | 沿用分层止损 8 / 12 / 18%（已验证、简单） |
| 估值系数 | 按区间位置 p：p < 0 且基本面未受损 → 1.0；0 ≤ p ≤ 0.5 → 1.0；0.5–0.8 → 0.7；0.8–1.0 → 0.4；p > 1.0 → 0（不新开） |
| 确定性系数 | 沿用 Muse 首笔规则（`opening_fraction`）和内部人放大 |
| 事件系数 | 覆盖层：冷静期 → 0；核查期 → 0.5；其他 → 1.0 |

"p < 0 但基本面受损"（背离标签"合理重定价"，或悲观值本身在下修）→ 估值系数 0：便宜是假象。

**加仓**：沿用 Muse 的确认加仓条件，另加"p ≤ 0.8"。价格已经接近乐观值时不再加仓。

### 19.3 持仓：拿多久、何时减

| 情况 | 动作 |
|---|---|
| p 在 0–1 之间，基本面不变 | 持有，不因价格上涨被动减仓（保留 Muse 原则） |
| p ≥ 1.2（明显超过乐观值） | 减 1/3，同一估值版本只触发一次；价值上修后重新计算 |
| 单票市值 > 总权益 20% | 减到 20%（集中度硬线） |
| 价值上修（财报 / 预期上调） | 区间整体上移，p 下降，自动恢复加仓资格。MU 这类真成长不会因为涨了就被卖光 |
| 价格跌破悲观值，基本面不变（"情绪性折价"） | 获得事件闸门复核资格（第 7.3 节），不自动加仓 |
| 悲观值本身下修 > 10%，或联动事件"已验证·有负面影响" | "合理重定价"：止损照常执行，不进入复核 |
| 基本面死亡、单票亏损 > 总权益 1.5% | 立即清仓（硬线不变） |

关于"减赢家"：Muse v13 的"高位回撤保护"失败了（在普通回调中卖掉了 MRVL、AMD）。本规则不同：它按**估值**而不是按**价格回撤**触发，而且价值随盈利上修会上移。但它仍可能降低 MU 这类股票的收益，必须回测确认"回撤减少"大于"收益损失"。

### 19.4 组合层

| 约束 | 初始值 | 依据 |
|---|---|---|
| 总在险金额（所有持仓到止损的潜在亏损之和） | ≤ 总权益 10% | 防止同时触发多个止损 |
| 同一 L3 主题 / 环节（如"存储"） | ≤ 25% | 来自四层市场主体和全局图谱；直接针对"MU 一只占回撤 63%、利润集中在三只半导体" |
| 同一 L2 行业（如"半导体"） | ≤ 40% | 同上 |
| 现有规则 | 黑天鹅暂停、组合回撤刹车、VIX 闸门、层预算 | 不变 |

### 19.5 算例（示意数字）

账户权益 1,050,000 美元。NVDA 通过 Muse 普通层门槛，现价 230，估值区间 180 / 240 / 300，p = 0.42。

- min(层上限 12%, 1.25% ÷ 12% = 10.4%) = 10.4%
- 估值系数 1.0（p ≤ 0.5），首笔确定性系数 0.6，事件系数 1.0
- 首笔权重 = 10.4% × 1.0 × 0.6 = 6.25% → 约 65,600 美元 → 285 股
- 主题检查：半导体 L2 现有 AVGO 9% + MRVL 7% + MU 3.8% = 19.8%，加上后 26% < 40%，通过
- 总在险检查：新增 6.25% × 12% = 0.75%，组合合计 6.1% < 10%，通过

同一天如果 AMD 也过线，现价 640，区间 430 / 560 / 700，p = 0.78 → 估值系数 0.7 → 首笔权重 = 8%（进攻层上限）与 1.25% ÷ 18% = 6.9% 取小 → 6.9% × 0.7 × 0.6 = 2.9%。**同样是"过线"，NVDA 买得比 AMD 多，因为它离价值更近。** 这是现在的 Muse 做不到的。
