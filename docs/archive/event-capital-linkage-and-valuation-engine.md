# 事件—资金—估值—仓位：鲁棒机制与估值引擎实现 —— 开发需求 v0.6（第三部分）

> 状态：需求草案，不含代码
> 关系：本文是《美股市场联动发现与交易体系融合》v0.5 的第三部分，回答两个问题：①估值引擎怎么实现、怎么做成动态的；②事件与股价异常的连接在"当下"怎么做才可靠，以及它如何一路传到估值和仓位，并让用户看得懂。
> 案例：OpenAI ARR 低于预期的传闻（AI 股大跌）、Meta Muse 登顶 App Store（CPU 股和 META 大涨）、东芝扩产（HDD 大跌）。另用一个**真实历史案例**做回放验证：2025-01-27 DeepSeek 应用登顶美国 App Store 免费榜后，NVDA 单日下跌约 17%。
> 所有价格、市值、分数均为示意值。

---

## 0. 先说结论

1. **系统不可能在当下确定因果**，事后能找出一百种理由。本设计不追求"猜对原因"，而是追求"**原因不确定时也做对决策**"：交易动作主要由"基本面是否真的变了"和"价格离价值多远"决定，归因只影响研究优先级和冷静期。"原因不明"本身就是一个有固定动作的正式状态。
2. **异常发现不依赖新闻**：先看价格。个股、主题篮子、行业、大盘四层同时算"剔除共同因素后的剩余涨跌"，篮子一起动就会被发现，哪怕当时一条相关新闻都没有。
3. **信息不删除，只排序**：所有抓到的信息都进入可检索的信息库。一旦出现价格异常，系统**回头重新检索过去 72 小时的全部信息**，包括当时被判为"普通"的那些。这是解决"源头事件被当作普通信息过滤掉"的关键。
4. **源头常常不在新闻里**：Muse 登顶、DeepSeek 登顶都是 App Store 榜单数据。所以要直接监控少量"一手数据源"（应用榜单、搜索趋势、SEC、公司官网），而不只是新闻。
5. **连接用证据打分，不用故事**：时间对齐到分钟、暴露梯度（越相关的公司动得越多）、篮子特异性（CPU 涨而 GPU 不涨）、市场自己的叙事证据、替代解释排查，再加一个关键检验——**事件隐含幅度**（市值变化是否和事件可能带来的盈利变化在同一数量级）。输出的是"归因置信度 + 多个候选"，不是单一答案。
6. **三条跟踪轨道、三个时钟**：情绪（天）、资金（天到周）、基本面（周到季）。**只有基本面轨道能改估值**；情绪和资金轨道只影响冷静期、时机和标签。
7. **每个异常都必须有处置结论**，并展示给用户：没发现、发现了但原因不明、发现并理解了但判断不用动（附理由和下次检查时间）、发现并行动了。"不行动"也是一条有理由、可复盘的决策。漏掉的事件在复盘里单独列出。

## 1. 核心原则：归因不确定下的决策

| 决策依赖 | 依赖什么 | 是否需要知道"真正原因" |
|---|---|---|
| 估值区间（值多少） | 财报、一致预期、Brain 情景（只在基本面轨道确认后切换） | 不需要 |
| 能不能买（Muse 门槛） | 四本账，包含时机账 | 不需要 |
| 买多少 | 风险预算 × 估值系数 × 事件系数 | 只有事件系数需要：是否存在"直接暴露、正在核查"的事件 |
| 止损 / 止盈 | 固定止损、估值减仓线、硬线 | 只有止损复核需要：是否属于"系统性或叙事冲击 + 基本面未变" |
| 研究优先级 | 归因候选、暴露、置信度 | 需要，但错了只浪费研究时间，不直接亏钱 |

这样设计的含义是：**归因错了的代价被限制在"冷静期多停几天"或"研究资源浪费"**，不会直接把一次错误的归因变成一笔交易。归因唯一能放宽的交易动作（止损复核）要求最严格，而且要先通过回测。

## 2. 估值引擎实现

### 2.1 组件

| 组件 | 职责 | 输入 | 输出 |
|---|---|---|---|
| ① PIT 财务库 | 存每个财务数字"何时可见" | SEC companyfacts（10-K / 10-Q 含修订）、提交日期 | 任意日期可见的财务快照 |
| ② 价格与股本库 | 日线、股本、拆股 | Alpaca / yfinance、SEC 股本 | 任意日期的市值、EV |
| ③ 预期快照库 | 一致预期每日快照（均值、高、低、家数、修订） | Muse `quant` yfinance 快照 | 任意日期可见的预期 |
| ④ 分类器 | 定估值类型（稳定盈利 / 成长盈利 / 周期 / 未盈利成长 / 金融） | 利润率历史及波动、营收增速、盈利状态、行业 | 类型 + 理由；按季度复核，类型切换留痕 |
| ⑤ 方法库 | 每种类型一套固定算法 | ①②③ | 每种方法的悲观 / 中性 / 乐观 |
| ⑥ 历史分布器 | 本股倍数的 5 年分位、周期利润率 7–10 年分位 | ①② | 分位带（按季度重算） |
| ⑦ 情景选择器 | 决定用一致预期的低 / 均 / 高哪一档 | Brain 情景（获批的）、联动事件"已验证"、基本面跟踪轨道 | 档位 + 依据 |
| ⑧ 合成器 | 主方法 + 交叉检查加权，检查方法间分歧 | ⑤⑦ | 最终区间；分歧过大标"低置信" |
| ⑨ 变化分解器 | 每次价值变化拆成：预期变化 / 档位切换 / 分位带重算 / 方法或参数更新 / 财报 | 新旧版本 | "价值为什么变了"的说明 |
| ⑩ 条件价值器 | 对未确认的事件给出"如果成立，价值会怎样" | 事件跟踪中的假设 | 只展示，不进交易 |
| ⑪ 隐含幅度器 | 把价格变动换算成"市场隐含的盈利变化" | 市值变化、当前倍数 | 供连接检验用（第 5.4 节） |
| ⑫ 回测与监控 | PIT 回测、方法准确度跟踪 | 历史版本 | 每种类型、每种方法的历史误差 |

### 2.2 每种类型的算法（规则固定，参数版本化）

| 类型 | 悲观 | 中性 | 乐观 |
|---|---|---|---|
| 稳定盈利 | 预期低档 EPS × 本股 PE 20 分位 | 预期均值 EPS × PE 50 分位 | 预期高档 EPS × PE 80 分位 |
| 成长盈利 | 次年 EPS 低档 × 增速调整 PE 20 分位 | 均值 × 50 分位 | 高档 × 80 分位；另做反向 DCF：现价隐含的 5 年增速 |
| 周期 | 归一化 EPS × 中枢 PE 低位 | 归一化 EPS × 中枢 PE 中位，与"当期 EPS × 顶部低倍数"取平均 | 当期 EPS × 历史中位 PE（仅在利润率不在顶部 20% 时） |
| 未盈利成长 | 次年营收 × 同类 EV/Sales 20 分位（按增速 + 利润率分组） | 50 分位 | 80 分位；现金跑道 < 1.5 年时乐观值封顶为中性 |
| 金融 | P/B 20 分位 × 账面价值（按 ROE 分组） | 50 分位 | 80 分位 |

没有一致预期时（例如刚入池的小公司），自动降级为 TTM 版本并标"降级"。

### 2.3 "动态"体现在哪里

| 动态机制 | 触发 | 效果 | 例子 |
|---|---|---|---|
| 预期驱动 | 一致预期变化 > 2% | 区间随预期移动 | MU 财报后上修 6% → 区间上移约 6% |
| 档位切换 | 基本面轨道确认事件影响 / Brain 情景变更获批 | 中性值用低档或高档预期 | 东芝扩产"已验证" → STX 中性切到低档 |
| 分位带更新 | 每季度 | 本股的"正常倍数"随时间缓慢变化 | 平台公司增速下降后，PE 带逐季下移 |
| 类型迁移 | 每季度复核 | 公司从"未盈利成长"变成"成长盈利"时换方法 | 换方法当季两种方法并列展示 |
| 周期位置 | 每季度 | 利润率进入顶部 20% 时自动压低乐观倍数 | 存储股在景气顶部被自动收紧 |
| 条件价值 | 事件进入跟踪 | 展示"如果成立"的价值，不进交易 | "若 Muse 带来 CPU 增量 X，AMD 中性值 +Y%" |

**不动的东西**：股价涨跌不改价值区间。价格只影响"位置"。这是防止"价格涨了就把估值往上调"的追涨机制。

### 2.4 每日运行时序（北京时间）

| 时间 | 步骤 |
|---|---|
| 07:30 | 收盘价进库 → 更新所有标的的位置和赔率 |
| 10:30 | 新财报（如有）进 PIT 库 → 受影响标的重算 |
| 11:00 | 预期快照同步 → 变化 > 2% 的重算 |
| 11:30 | 读取基本面轨道和 Brain 获批变更 → 档位切换 → 重算 |
| 12:00 | 变化分解 → 生成"今日价值变化"列表 |
| 20:00 | 盘前价格 → 更新位置 → 交给仓位规则和盘前计划 |

### 2.5 估值可信度

每个区间附带置信度：方法间分歧（主方法和交叉检查差 > 30% → 低）、数据降级（无预期、财报不足 5 年 → 低）、类型刚迁移（→ 中）。**低置信的区间，估值系数上限为 0.7**：估值不确定时不让估值放大仓位。

## 3. 第一个问题：怎么捕获股价异常

### 3.1 四层"剩余涨跌"

不用"涨跌超过 5%"这种固定阈值。每只股票每天、盘中每 5 分钟计算：

```
剩余涨跌 = 实际涨跌 − β市场 × 大盘涨跌 − β行业 × 行业涨跌 − β主题 × 主题篮子涨跌
```

β 用过去 120 个交易日滚动估计。然后在四个层次分别找异常：

| 层次 | 看什么 | 例子 |
|---|---|---|
| 大盘 | QQQ / SPY 相对自身波动 | OpenAI 传闻当天 QQQ 异常下跌 |
| 主题篮子 | 篮子相对大盘的剩余涨跌 | "AI 算力"篮子剩余 −3σ；"服务器 CPU"篮子剩余 +3σ |
| 个股相对篮子 | 个股相对所属篮子的剩余 | AMD 相对 CPU 篮子正常，说明是整个篮子在动 |
| 篮子内部离散 | 篮子内是一起动还是个别动 | CPU 篮子 5 只里 4 只同向 → 主题级事件 |

### 3.2 主题篮子从哪来

篮子是数据，不是代码：从全局图谱（主文档第 4.1 节）和四层市场主体（第 3.1 节）自动生成，每个篮子有成分、权重、生效时间。初始约 40 个，例如：AI 算力（GPU / ASIC）、服务器 CPU、HBM / 存储、HDD、光模块、数据中心电力、云厂商、AI 应用、广告平台、OpenAI 合作方、半导体设备……

**OpenAI 合作方**这种"关系篮子"很重要：OpenAI 不是上市公司，它的消息只能通过合作方篮子的异常被看到。

此外，每天用最近 60 日剩余收益的相关性做**自动聚类**，发现图谱里没有的新篮子（例如一组平时不相关的股票突然一起动），作为"未命名篮子"提示人工命名。

### 3.3 频率与时段

| 时段 | 频率 | 覆盖 |
|---|---|---|
| 盘前 / 盘后 | 5 分钟 | 高频集合（持仓、候选、观察池，约 150 只）+ 所有篮子 ETF 代理 |
| 盘中 | 5 分钟 | 同上 |
| 收盘后 | 日级 | 广域集合（约 1000–1500 只） |

Alpaca 有约 15 分钟延迟，实际发现时间约为异动后 15–20 分钟。这对"盘前覆盖层"足够，对盘中交易不够（本期也不做盘中交易）。

### 3.4 输出

异常对象附带：层次、篮子、成员及剩余涨跌、**起点时间（精确到 5 分钟）**、扩散路径、数据质量核对结果。起点时间是后面做时间对齐的关键。

### 3.5 三个案例当下会被怎么发现

| 案例 | 当下看到的价格现象 | 被哪一层发现 |
|---|---|---|
| OpenAI ARR 传闻 | QQQ −2%；AI 算力篮子剩余 −3.5σ；OpenAI 合作方篮子剩余 −4σ；软件篮子正常 | 大盘 + 两个主题篮子 |
| Meta Muse 登顶 | 服务器 CPU 篮子剩余 +3σ（AMD、INTC、ARM 同涨）；GPU 篮子正常；META 个股相对广告平台篮子 +2.5σ | 主题篮子 + 个股 |
| 东芝扩产 | HDD 篮子盘后剩余 −6σ；存储篮子 −1.5σ | 主题篮子（盘后） |

**关键点**：哪怕当时一条新闻都没抓到，这三个异常也会被发现，并进入"已发现·原因未明"状态。

## 4. 第二个问题：能不能抓到源头事件，抓到了会不会被过滤掉

### 4.1 源头常常不是新闻

| 案例 | 源头 | 新闻什么时候出现 |
|---|---|---|
| DeepSeek（2025-01，真实） | R1 模型在一周前发布；周末登顶 App Store 免费榜，社交媒体扩散 | 大跌当天及之后，新闻在解释已经发生的下跌 |
| Meta Muse（案例） | App Store 榜单 | 晚于榜单变化 |
| OpenAI ARR | 分析师 / 媒体爆料（四级信源） | 本身就是"新闻"，但信源弱 |
| 东芝扩产 | 公司公告 / 媒体 | 同步 |

所以需要直接监控一手数据，而不只依赖新闻。

### 4.2 信源矩阵

| 信源 | 抓什么 | 成本 | 期次 |
|---|---|---|---|
| SEC EDGAR | 8-K、10-Q、Form 4 | 免费 | 已有 |
| 新闻 API | 全量财经新闻（不只是 Nasdaq） | 低 | P1 |
| **App Store / Google Play 榜单** | 美国免费榜、畅销榜前 100，每小时一次；监控名单内应用（Meta 系、OpenAI、Google、DeepSeek 类）的排名变化 | 免费（Apple 官方 RSS 榜单） | **P1** |
| **Google Trends** | 监控实体（公司、产品、应用、模型名）的搜索热度 | 免费，限频 | P1 |
| 公司官网 / 官方博客 / 产品发布 | 监控名单内主体的发布页面变化 | 免费 | P1 |
| X / 社交 | 监控名单账号（公司、核心分析师、科技媒体）+ 实体提及量 | 按量付费 | P2 |
| 模型榜单 / GitHub 趋势 | AI 模型发布、开源项目爆发 | 免费 | P2 |

**监控实体清单**由全局图谱自动生成：每个篮子的关键上游主体，包括非上市公司（OpenAI、Anthropic、DeepSeek）、关键产品（Muse、ChatGPT、Gemini）和关键数据（HDD 合约价）。

### 4.3 信息不删除：分层存储 + 回捞

**问题根源**：传统做法是按重要性打分，低分直接丢掉。Muse 登顶在当下看起来就是"一个 App 排名变化"，很可能被打低分。

**设计**：

| 层 | 内容 | 处理 |
|---|---|---|
| 全量库 | 所有抓到的信息（新闻、榜单变化、搜索突增、公告），带实体标注和向量索引 | 保留 90 天，可检索 |
| 关注队列 | 按重要性排序的前若干条 | 进入研究、可能调 LLM |
| 探索名额 | 每天固定几条低热度但涉及新机制的信息 | 进入研究 |

**回捞规则**：每出现一个价格异常，系统用异常的成员、篮子、关联实体、上下游主体生成检索条件，**在全量库里重新检索异常起点前 72 小时到当前的所有信息**，按与异常的相关性重新排序。当时被排在后面的"Muse 登顶"，会因为"CPU 篮子异常 + META 异常 + Meta 系应用榜单变化"三者的实体重合而被捞回来。

**一手数据突变本身也是信号**：榜单名次跳升 > 20 名、搜索热度 > 自身 3 倍历史、官网发布新产品，这些即使没有新闻报道，也直接进入关注队列。

### 4.4 覆盖自检

每天统计：有多少异常找到了候选事件，有多少是"原因未明"。如果原因未明的比例持续上升，说明信源覆盖不足，在数据源健康页报警。

## 5. 第三个问题：怎么建立正确的连接

### 5.1 不是一个答案，而是一组候选 + 置信度

对每个异常，系统生成全部候选解释（来自回捞的信息 + 图谱上游 + 宏观日历 + "无事件 / 资金面"默认解释），逐个打分。

### 5.2 证据打分

| 证据 | 怎么算 | 权重（初始） |
|---|---|---|
| 时间对齐 | 信息首次可得时间 vs 异常起点（5 分钟精度）。早于或同时 → 高分；晚于起点 → 0（只能解释后续） | 20% |
| 暴露梯度 | 按图谱给每个成员一个暴露度；暴露度和剩余涨跌的秩相关 | 20% |
| 篮子特异性 | 预期受影响的篮子动了，**预期不受影响的对照篮子没动**（CPU 涨、GPU 不涨） | 15% |
| 叙事证据 | 市场本身有没有在说这条逻辑：新闻、卖方点评、社交中"事件 + 受影响对象"共同出现的独立来源数（去重来源根） | 15% |
| 隐含幅度 | 第 5.4 节：市值变化与事件可能带来的盈利变化是否在同一数量级 | 15% |
| 替代解释排除 | 同时段是否有成员自身财报、指引、评级、宏观数据 | 15% |

输出两种置信度，**分开展示**：

- **市场归因置信度**：市场是不是在按这条逻辑交易（高 / 中 / 低）；
- **基本面成立度**：这条逻辑在经营上是否成立（待验证 → 由基本面轨道逐步更新）。

### 5.3 Meta Muse → CPU 的打分（示意）

| 证据 | 结果 | 得分 |
|---|---|---|
| 时间对齐 | 榜单登顶在 CPU 篮子起涨前 1 天；当天上午社交提及量起涨 | 高 |
| 暴露梯度 | 服务器 CPU 占比高的公司涨得多（ARM、AMD > INTC）；META 涨 | 中高 |
| 篮子特异性 | CPU 篮子 +3σ，GPU 篮子正常，广告篮子小涨 | 高 |
| 叙事证据 | 卖方点评与科技媒体出现"智能体多任务 → CPU 需求"，独立来源 6 个 | 中 |
| 隐含幅度 | CPU 篮子市值增加约 900 亿美元；对应每年增量净利润需约 30 亿美元。一个应用登顶短期内带来的 CPU 采购远达不到这个量级 | **不相容** |
| 替代解释 | 同期无 CPU 公司财报；INTC 有一条无关的晶圆代工消息（已排除） | 中 |

**结论**：市场归因置信度"中高"（市场确实在交易这个叙事），基本面成立度"待验证，量级存疑"。系统定性为**叙事驱动的上涨**，不是经营事实。

**这正好回答"它怎么知道 CPU 上涨是 Muse 登顶带来的"**：它不"知道"，而是判断"市场正在按这个叙事交易"的证据有多强，同时判断"这个叙事在经营上能不能撑起这么大的市值变化"。两件事分开回答。

### 5.4 隐含幅度检验（最重要的"推敲"工具）

```
市场隐含的年盈利变化 ≈ 市值变化 ÷ 当前 PE
```

把它和"事件可能带来的盈利变化"的上限比较：

| 案例 | 市值变化（示意） | 隐含年盈利变化 | 事件可能的直接影响 | 判断 |
|---|---|---|---|---|
| OpenAI ARR 低于预期 | AI 篮子 −8,000 亿美元 | 约 −250 亿美元 / 年 | OpenAI ARR 少几十亿美元，即便全部传导到合作方的订单，量级也远小于此 | **不相容 → 主要是估值倍数 / 情绪冲击** |
| Meta Muse → CPU | CPU 篮子 +900 亿美元 | 约 +30 亿美元 / 年 | 单个应用短期的 CPU 增量很小 | 不相容 → 叙事驱动 |
| Meta Muse → META | META +600 亿美元 | 约 +25 亿美元 / 年 | 用户时长和广告变现的潜在增量，可以达到这个量级（需要 DAU 数据验证） | 可能相容 → 进基本面核查 |
| 东芝扩产 → HDD | HDD 篮子 −120 亿美元 | 约 −10 亿美元 / 年 | 若新增产能占需求增量的大部分，HDD 价格下跌可达到此量级 | 可能相容 → 进基本面核查 |

**用法**：不相容 → 把这次价格变化归为"估值倍数 / 情绪"，**不进入估值**；可能相容 → 进入基本面核查，等证据。你说的"OpenAI ARR 新闻禁不住推敲"，这个检验就是把这种推敲机械化。

### 5.5 什么都对不上时

所有候选的市场归因置信度都低 → 状态"**已发现·原因未明**"：

- 不做任何估值变动；
- 若异常涉及持仓且幅度大，提醒你人工看一眼；
- 每天回捞一次新信息，持续 5 个交易日；
- 交易端只按原有规则（止损、时机账）运行，不额外动作。

## 6. 持续跟踪：三条轨道

| 轨道 | 指标 | 频率 | 状态 | 影响什么 |
|---|---|---|---|---|
| **情绪轨道** | 独立来源数、搜索热度、社交提及、语气、榜单名次持续性 | 每日 | 初现 → 扩散 → 稳定 → 衰减 → 重新活跃 | 冷静期、标签；**不改估值** |
| **资金轨道** | 篮子剩余涨跌累计、**回吐比例**（5 / 20 日回吐初始冲击的百分比）、相对强弱、成交量相对均量、期权隐含波动率和偏度、ETF 资金流（若可得） | 每日 | 冲击中 → 消化中 → 已消化 / 延续 → 反转 | 时机账（已有）、事件闸门资格；**不改估值** |
| **基本面轨道** | 一致预期修订、公司表态、8-K、关键经营数据（如应用 DAU / 留存的代理指标、资本开支指引、合约价）、下一份财报 | 每周 + 事件触发 | 待验证 → 局部支持 → 支持 / 冲突 → 失效 | **唯一能改估值的轨道**（切换预期档位、上修 / 下修） |

每条轨道都有检查点和截止日（沿用主文档第 4.6 节）：到期必须落到"支持 / 反证 / 条件风险"之一，不能自动续期。

**三条轨道的组合含义**：

| 情绪 | 资金 | 基本面 | 解读 |
|---|---|---|---|
| 衰减 | 已回吐 > 50% | 未变 | 情绪冲击已消化 |
| 衰减 | 未回吐 | 未变 | 价格新均衡，可能有未被看到的信息 → 回捞 + 提高研究优先级 |
| 扩散 | 延续 | 开始修订 | 基本面开始兑现 → 估值随预期移动 |
| 衰减 | 延续 | 冲突 | 价格和基本面背离 → 背离标签 |

## 7. 从跟踪到估值，再到仓位

### 7.1 传递链

```
事件 → 情绪轨道 ─┐
     → 资金轨道 ─┼→ 事件系数（冷静期 / 首笔减半）、时机账、止损复核资格 ─┐
     → 基本面轨道 → 预期修订 / 档位切换 → 估值区间 → 位置 p → 估值系数、减仓线 ─┴→ 仓位动作
```

### 7.2 持仓的决策矩阵

| 价格方向 | 基本面轨道 | 位置 p | 动作 | 理由 |
|---|---|---|---|---|
| 下跌，未破止损 | 未变 / 待验证 | 任意 | **持有不动**；冷静期内不加仓 | 情绪冲击不改价值 |
| 下跌，破止损 | 未变，且属于系统性 / 叙事冲击，且 p < 0 | < 0 | 有复核资格：卖一半 + 二级止损 + 5 日期限（回测通过后启用） | 第 7.3 节闸门 |
| 下跌，破止损 | 其他情况 | 任意 | **止损执行** | 规则优先 |
| 下跌 | 已验证负面，价值下修 | 下修后 p 上升 | 止损照常；下修后 p ≥ 1.2 → 减 1/3；基本面死亡 → 清仓 | 合理重定价 |
| 上涨 | 未变（叙事驱动） | p ≥ 1.2 | **减 1/3**（按价值止盈） | 价格超过价值，基本面没跟上 |
| 上涨 | 未变 | p < 1.2 | 持有，不加仓（p > 0.8 时） | 不追 |
| 上涨 | 已验证正面，价值上修 | 上修后 p 下降 | 持有；p ≤ 0.8 时恢复加仓资格 | 基本面兑现 |

### 7.3 未持仓：要不要买

| 情况 | 动作 |
|---|---|
| 叙事驱动下跌，**低暴露**，基本面未变 | 价值不变、p 下降 → 价值总表上变"便宜"。但买不买仍由 Muse 门槛决定，时机账通常刚跌破，所以多数情况是"**等**"；系统挂"修复观察"，时机账回到线上再买 |
| 叙事驱动下跌，**直接暴露**，正在核查 | 冷静期，不买 |
| 叙事驱动上涨 | 不追：p 上升使估值系数下降；过热过滤；p > 1 不新开 |
| 基本面兑现的上涨（预期上修） | 价值上移，按正常门槛和仓位规则 |
| 原因未明的异常 | 不额外动作，按 Muse 原规则 |

## 11. 验收用例

1. **无新闻也能发现**：屏蔽全部新闻源后回放 Meta Muse 案例 → CPU 篮子异常仍被发现，状态"原因未明"。
2. **回捞**：Muse 登顶信息在当时被排在关注队列之外 → CPU 篮子异常出现后 30 分钟内被捞回并成为候选。
3. **一手数据**：App Store 榜单名次跳升 > 20 名且属于监控实体 → 无新闻也进入关注队列。
4. **晚到不归因**：信息首次可得时间晚于异常起点 → 时间对齐得 0。
5. **对照篮子**：CPU 篮子涨、GPU 篮子不涨 → 特异性得分高；两者都涨 → 得分低，提示可能是更大的主题。
6. **隐含幅度**：OpenAI 案例 → "不相容"，不进入估值。
7. **情绪不改估值**：情绪轨道和资金轨道任意变化 → 估值区间不变。
8. **基本面改估值**：一致预期上修 3% → 中性值随之上修，变化分解显示"预期变化"。
9. **低置信估值限仓**：方法分歧 > 30% → 估值系数上限 0.7。
10. **完整性**：任何超过阈值的异常在当日结束时都有处置状态；没有的在系统日志里标红。
11. **不行动有理由**：每个"不行动"都带理由代码和下次检查时间。
12. **漏检可见**：事后确认的漏检出现在周报里，并标出漏在哪一环。
13. **DeepSeek 回放**：按第 10.1 节的预期结果通过。
14. **原因未明不乱动**：所有候选都是低置信 → 不改估值、不触发冷静期、只按原规则。

## 12. 诚实的边界

- **系统不能在当下确定因果**。它能做的是：快速看到异常；尽量找全候选；用证据区分"市场在交易什么"和"经营上是否成立"；在不确定时按固定规则行动；事后诚实地评估自己对了多少。
- **一手数据覆盖有限**。社交数据要付费；产业价格数据很贵；总会有信源之外的源头。漏检报告就是用来暴露这一点的。
- **15 分钟延迟**意味着当天来不及反应，交易影响以次日盘前为准。
- **参数都是初始值**，要靠回放和前向运行校准；样本少的时候，系统宁可"原因未明，等待"，也不硬给答案。
