# T10 · M10 页面、处置卡与复盘

> 交给：一个开发 agent。按第一阶段任务书第 4 节的工作规则执行，完成后提交验收。

## 你的任务

做出用户每天使用的页面和 JSON 接口：系统日志首页、市场四层、联动事件详情、标的总表、个股、持仓（含估值—仓位对照）、盘前计划、数据健康、复盘；处置卡五种状态、决策时间线；案例库与 T+1 / T+5 / T+20 打标、先兆快照、独立漏检抽样、模式库候选、周报和月报。页面只展示上游结果，不重新计算。`/paper/plan` 原样展示 M4 提供的逐输入完整性清单，不单独突出 overlay 缺失而遗漏其他来源状态。

## 自测报告要附的证据

- 每个页面的 JSON 样例和截图
- 四种处置状态（①②③⑤）的案例演示记录
- 连续 5 个交易日首页完整的记录；运行满 20 个交易日后的打标、周报和月报
- 按模板（模块文档 README 第 7.2 节）写 `handoff/M10/self-test.md`，逐条对应上表的验收条款

## 最容易出错的地方

- 页面不重新计算任何数字；每个数字都能在上游表里找到同一个值
- `/paper/plan` 逐源透传 M4 `input_completeness` 状态/覆盖/缺失/影响；若 M4 未提供则标“输入完整性未报告”，不得推断成完整
- 市场与研究页面不显示订单、仓位和估值区间；这些只在 `/paper/*`
- 北京 13:00 仍没有处置状态的异常要在首页标红
- "不动"也要在时间线上记一条
