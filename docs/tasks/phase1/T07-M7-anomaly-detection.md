# T07 · M7 异常感知

> 交给：一个开发 agent。按第一阶段任务书第 4 节的工作规则执行，完成后提交验收。

## 你的任务

每天收盘后（含盘后），不依赖任何新闻，把所有不正常的价格变化找出来：三条发现路径和多日累积、数据质量核对、合并与归层、资金放大特征、初步类型候选；北京 20:00 做一次盘前复核。本任务只回答"哪里异常、是什么形状"，不写任何原因。

4. 下表中标为阻塞的验收条款都有证据（需求方验收时逐条判定，只按这张表）：

| 条款 | 判定标准 | 类型 | 阻塞 |
|---|---|---|---|
| AC-M7-01 | 第 7 节 blocking 测试和 `test_case_detection` 全绿 | H | 是 |
| AC-M7-02 | **屏蔽全部新闻源**后重跑四个案例，异常照样被发现（规格验收"无新闻也能发现"） | D | 是 |
| AC-M7-03 | 连续 5 个交易日真实运行：每天北京 08:15 前产出清单；每个异常都有层次、篮子、成员、入口、数据质量结果 | E | 是 |

类型：H = 自动测试；E = 证据（报告、数据、截图）；D = 现场演示。

## 自测报告要附的证据

- 四个案例的检测结果
- 屏蔽全部新闻源后重跑四个案例的结果
- 连续 5 个交易日的异常清单和 `job_runs` 计数
- 按模板（模块文档 README 第 7.2 节）写 `handoff/M7/self-test.md`，逐条对应上表的验收条款

## 最容易出错的地方

- 模块的输入里不能有新闻表
- 同一天同一时段命中同一组股票只算一个异常，保留全部入口
- 归层只能逐层向上
- 盘前复核不创建新的日级异常
