# 整体需求与目标

> 读者：参与本项目开发的 agent 和开发者。
> 本文是入口：讲清这个系统要做什么、为什么这样设计、分几个阶段、每个阶段做到什么算完成。细节规格在 [`../system-spec.md`](../system-spec.md)，第一阶段的开发任务在 [`phase1/00-phase1-brief.md`](phase1/00-phase1-brief.md)。

---

## 1. 这是什么系统

一套**美股市场分析与纸面交易系统**，由两个严格分开、又互相提供依据的模块组成：

| 模块 | 回答的问题 | 速度 |
|---|---|---|
| **模块一：市场与基本面** | 市场今天发生了什么？哪里出现了异常？原因可能是什么？这件事会不会改变公司的基本面？ | 消息和情绪快（天），基本面慢（季度） |
| **模块二：估值与交易** | 每只股票值多少？按现价能不能买、买多少？持有的该拿着、减仓还是卖出？ | 决策慢，只随基本面和规则变化 |

这是一个**独立项目**：全部代码在本仓库 `XuQingsong/inves-cog`，不依赖其他系统的代码和数据库。系统只做研究和纸面组合，**不接券商、不下真实订单**。

## 2. 要解决的问题

1. **快慢打架**：消息、情绪、资金每天在变，公司基本面按季度变化。如果交易跟着情绪和资金走，系统会变成追涨杀跌、很脆的系统。快信息只能影响"看什么、什么时候暂停"，不能直接驱动买卖。
2. **当下看不清**：事后能给任何行情找一百种理由，但事情正在发生时，系统要能：
   - 发现股价异常（个股、主题、板块、大盘，以天为单位）；
   - 找回源头信息，即使它当时看起来很普通（一条榜单变化、一条小道消息）；
   - 用证据把事件和异常连起来，并区分"市场在按这个逻辑交易"和"这个逻辑在经营上成立"；
   - 持续跟踪情绪、资金、基本面，直到得出结论：基本面有没有变，股价和基本面有没有背离。
3. **估值和交易要有逻辑**：所有标的都有评分和估值；高成长、高 PE 的股票要有买得进去的路径；仓位、止损、止盈不能是纯机械的，遇到战争、关税、疫情这类系统性冲击时要能复核。
4. **看得懂**：用户要能分清系统是漏看了，还是看到了、理解了、判断不用动，并且之后还会继续盯。
5. **越用越好**：每个异常都变成案例，事后复盘、打标、补强，逐步积累出"感知能力"。

用户举过的典型案例（贯穿全部文档）：

- **东芝扩产**：当晚 HDD 板块（WDC、STX）盘后大跌 10% 以上。要判断的不是"跌没跌"，而是基本面有没有变、价格和基本面有没有背离。
- **OpenAI ARR 低于预期**：一条分析师的小道消息被媒体转发，AI、数据中心概念股和 QQQ 一起大跌。消息经不起推敲，但行情是真的。
- **Meta 的 Muse 登顶 App Store**：META 和 CPU 概念股大涨。系统要推出"智能体多任务 → 利好 CPU"这条链，并判断它能撑起多大的市值变化。
- **DeepSeek（2025-01-27，真实）**：源头是一周前的模型发布和周末的榜单登顶，新闻只是在事后解释已经发生的下跌。

## 3. 总体目标：能力阶梯

系统的最终目标是具备**感知能力**：在异常发生前后，更早、更准地识别"正在发生什么"。这种能力设计不出来，只能从大量被完整记录、被事后打标的案例里长出来。

| 阶段 | 能力 | 说明 |
|---|---|---|
| C1 事后解释 | 第二天早上说清楚昨天发生了什么、最可能的几个原因、影响到谁 | 第一阶段交付 |
| C2 结构识别 | 当天判断异常的类型：事件冲击、情绪踩踏、轧空、主题轮动、宏观流动性 | 第一阶段给出类型候选；准确率达标后进入 |
| C3 先兆识别 | 异常发生前，识别"容易出事"的状态：拥挤、空头集中、叙事升温、估值极端 | 第一阶段起积累数据 |
| C4 感知 | 前置状态加触发信号 → 预警，并影响仓位 | 最终目标 |

## 4. 系统构成

```
信息获取 → 异常发现 → 建连归因 → 三轨跟踪（情绪 / 资金 / 基本面）      ← 模块一
                │                     │
         价格结构层（只用价格）   覆盖层（只收紧） / 影子信号（只记录）   ← 两模块之间的桥
                ▼                     ▼
       估值区间（只展示） · 规则 A 打分 → 红线 → 分层 → 纸面订单         ← 模块二
                                      ▼
            复盘补强：案例 → 模式 / 权重 / 图谱 / 先兆 / 因子候选         ← 闭环
```

几条贯穿全局的设计原则：

| 原则 | 含义 |
|---|---|
| 价格先行 | 异常发现不依赖新闻，先看价格；哪怕一条相关新闻都没抓到，异常也会被发现 |
| 信息不删除 | 所有信息都入库；出现异常后回头检索前 72 小时的全部信息 |
| LLM 想到，规则判断 | LLM 只负责提出候选原因（必须引用信息 id）和抽取字段；所有分数、状态、结论由规则计算 |
| 只有基本面能改估值 | 情绪和资金只影响时机、冷静期和标签；估值只随财报和一致预期变化；价格只改变"位置" |
| 桥只收紧 | 模块一对交易的影响只能是"少做"（暂停买入、撤单）；任何"多做"或"少卖"都要先回测、再批准 |
| 每个异常都有结论 | 原因未明也是一个正式状态；"不行动"也要写理由代码和下次检查时间 |
| 诚实覆盖 | 没接通的数据写"未接通"，不编数字 |

## 5. 硬约束（所有阶段都适用）

1. **独立项目**：代码、测试、配置、迁移都在本仓库；不导入、不调用其他系统的代码，不读写它们的数据库。
2. **纸面交易**：不接券商，不下真实订单。
3. **当时可见（PIT）**：任何一天的计算只用当天已经公开的数据；财报按 SEC 申报日生效。
4. **LLM 只用两个模型**：困难任务 `glm-5.3`，其他任务 `deepseek-v4.1-flash`。
5. **交易规则先按规则 A（Muse v18）走**；新规则一次一条，回测、影子运行、批准后才能生效。
6. **估值在第一阶段不改仓位**：只展示、只做影子对照。
7. **Harness 先行**：没过测试的改动不能合并；标准答案只有需求方能改。

## 6. 阶段路线

| 阶段 | 目标 | 主要内容 | 进入下一阶段的条件 |
|---|---|---|---|
| **第一阶段** | 系统每天能**看见、解释、记录**，并按现有规则 A 机械交易 | 数据采集与基本面档案；规则 A 重写并复现 v18；估值 v1.1（只展示）；日级异常感知、建连归因、三轨跟踪；覆盖层（冷静期、撤单）；影子信号和因子候选池；页面和复盘闭环 | 第一阶段完成定义（[`phase1/00-phase1-brief.md`](phase1/00-phase1-brief.md) 第 5 节）全部满足 |
| **第二阶段** | 用回测和第一阶段积累的影子记录，**验证并逐条启用**更完善的交易规则 | 回测框架；扩池基线；A+ 逐条消融；S10 冲击回放；估值历史评估；因子回测；通过的规则按"先收紧、后放宽"逐条启用（V-T1 / V-T2 → A+ 条目 → 因子） | 每条启用的规则都有回测报告、一个季度的并行影子和用户批准 |
| **第三阶段** | **估值进入仓位**；基本面恶化在两次财报之间可以触发减仓 | V1 替换估值账（B1 退役）；V2 按估值定仓位；V3 按价值减仓；X1–X3 中通过评估的影子信号转为规则 | 两个财报季影子 + 回测 + 批准 |
| **之后** | 从"事后解释"走向"感知" | C2 结构识别达标；C3 先兆特征验证；C4 预警影响仓位 | 第 3 节能力阶梯的条件 |

每个阶段开始前，需求方会出该阶段的任务书。

## 7. 每个阶段怎么算成功

| 阶段 | 成功的样子 |
|---|---|
| 第一阶段 | 用户每天早上打开系统：能看到昨夜的异常和可能的原因；所有标的都有评分、估值参考和"能不能买、为什么"；盘前计划里每一笔动作和"不动作"都有理由；四个历史案例回放都能被发现并正确建连；所有案例按时打标，周报和漏检报告按时生成 |
| 第二阶段 | 每条候选规则都有"比规则 A 好还是坏"的结论；至少一条收紧类规则通过并启用；高成长股的买入路径有回测证据支撑 |
| 第三阶段 | 同样过线的两只股票，离价值更近的买得更多；价格明显超过价值且基本面没跟上时会减仓 |

## 10. 术语

| 术语 | 含义 |
|---|---|
| 四本账 | 规则 A 的四个打分：公司质量、成长与预期、估值、入场时机 |
| 规则 A | Muse v18 的交易规则（规格第 9 节，M-01 至 M-63） |
| A+ | 在规则 A 基础上的改进提案（规格第 10 节），第二阶段验证 |
| 剩余涨跌 | 个股或篮子的涨跌，扣掉大盘、板块、主题能解释的部分之后剩下的 |
| 篮子 | 一组可以放在一起比较的股票（板块 L2、主题 / 关系 L3） |
| 联动事件 | 一个可能同时影响多只股票的事件对象，带生命周期和五个状态维度 |
| 隐含幅度 | 把市值变化换算成"市场隐含的盈利变化"，与事件可能带来的盈利变化按渠道比较 |
| 二次命中 | 同一叙事的后续消息让同一批股票按预期方向再动一次，作为"市场共识"的确认 |
| 三轨 | 情绪、资金、基本面三条跟踪轨道，只有基本面轨道能改估值 |
| 冷静期 | 覆盖层对直接暴露标的的"暂停新买和加仓" |
| 影子 | 每天计算"如果这条规则生效会怎样"，只记录、不下单 |
| 因子候选池 | 新因子从登记、影子计算、回测、前向影子到生效的流程 |
| PIT | Point-in-time，只用当时已经公开的数据 |
| 标准答案（golden） | 需求方按规格公式算好的期望值，开发只能比对、不能改 |
| 不变量（Ixx） | 永久测试，Harness 的核心 |
