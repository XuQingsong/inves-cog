## 0. 结论先行

**逻辑能走通，资源"大部分够、少数关键缺口必须补"。** 补齐这些缺口的成本很低，主要是工程工作量，不是钱。

| 能力 | 现状判断 | 走通的前提 |
|---|---|---|
| 日级感知股价异常 | **基本够** | 把盘中采集延长到美东 20:00（拿到盘后收盘价）；广域日线批量采集；新建主题篮子和剩余涨跌计算 |
| 获取源头信息 | **不够，但补齐便宜** | 接入 Alpaca News API（Benzinga 全市场新闻，带精确时间，现有 Alpaca 账号即可用）；App Store 榜单（免费）；Google Trends（免费、不稳定）。现有 Nasdaq 新闻只覆盖自选股、只精确到日，不能做时间对齐 |
| 自主建立连接 | **部分够** | LLM 和检索工具已有；缺**全局图谱**和**信息全量库 + 向量检索**。图谱初始化是最大的一次性工作量 |
| 基础分析 | **够** | 现有 LLM 分档（glm-5.2 机械 / glm-5.3 推理）足够做候选生成和报告；判断交给规则 |
| 稳定估值 | **够**（数据），**需新建**（引擎） | SEC 财报两边都有；价格历史够；一致预期靠 Muse 快照（只从 2026-10-08 起）。stock-pm 研究模块已有三档估值框架可借用，但需要改造成机械版本 |
| 合理交易 | **够**（规则与回测框架），**有一个部署阻塞** | Muse 规则、回测、纸面跟踪都已有；**Muse 在沙箱、stock-pm 在服务器，两者之间没有同步通道**，这是覆盖层落地的第一阻塞 |
| 复盘补强 | **够** | 主要是存储和每周约 30 分钟的人工确认 |

**最关键的三件事**：①打通 Muse 与 stock-pm 的部署和数据同步；②接入一个全市场、带精确时间的新闻源；③建立全局图谱和主题篮子。三件都做好，第一阶段的逻辑就能闭环。

## 1. 整合后的系统全貌

```
      ▲                                                                                  │
      └──────────────────────────── 信源缺口、权重、图谱、篮子、规则候选 ◀───────────────┘
```

| 环节 | 做什么 | 主要产出 | 属于 | 详见 |
|---|---|---|---|---|
| ① 信息获取 | 行情、公告、财报、预期、新闻、一手数据全部入全量库 | 全量信息库（带实体、时间、向量） | 模块一 | 第三部分第 4 节 |

| ④ 三轨跟踪 | 情绪、资金、基本面各有检查点和截止日 | 跟踪状态 | 模块一 | 第三部分第 6 节 |

### 2.3 LLM

| 档位 | 配置 | 用途 | 评估 |
|---|---|---|---|
| 机械档 | glm-5.2（DashScope 兼容接口） | 抽取、分类、事件抽取 | 够用：说法抽取、实体标注、候选机制生成 |
| 推理档 | glm-5.3，超时 900 秒 | Brain 推理、研究判断 | 够用但慢；只用于少量深度分析 |
| 快速档 | GLM-5.3-Flash | 别名已配置 | 适合大批量抽取，降低成本 |
| 强模型槽 | `STRONG_MODEL_*` 可配置 | 预留 | 需要时可接更强的模型做疑难归因 |
| 基准对比 | `BENCHMARK_MODELS` | 多模型对比 | 可用来评估不同模型的归因质量 |
| 向量嵌入 | **未接** | —— | 缺口：全量库的语义检索需要；DashScope 有嵌入模型，接入简单 |

**对 LLM 的定位**：本设计只让 LLM 做两件事——从文本中抽取结构化"说法"、从回捞的信息中提出候选机制（必须引用信息 id）。**所有判断由规则完成**。所以对模型的要求是"抽取准、不编造"，现有档位足够；模型能力弱一些，影响的是候选的召回率，不会直接造成错误交易。

## 3. 逐项评估

### 3.1 信息怎么拿，够不够全

| 信息类别 | 第一阶段需要 | 现有 | 缺口 | 补齐方案 | 成本 |
|---|---|---|---|---|---|
| 价格（个股、ETF、篮子） | 广域约 1500 只日线 + 高频约 150 只的盘后收盘 | Alpaca SIP 日线；分钟线到 16:30 | 盘后时段；广域股票池 | 分钟线采集窗口延长到美东 20:00；新增广域日线批量任务（Alpaca 多股票请求） | 免费 |
| 公司公告 | 全市场 8-K、10-Q、Form 4 | SEC 8-K Atom 流、companyfacts、Muse Form 4 | 无 | —— | 免费 |
| 财报历史 | 覆盖池全部标的、约 2009 年起 | 两边都有 companyfacts 采集 | 需扩到 150 只 | 扩展 Muse `fetch_financial_facts` 的股票清单 | 免费 |
| 一致预期 | 覆盖池每日快照 | Muse yfinance 快照（30 只，10-08 起） | 扩池；无历史；yfinance 非官方 | 扩展抓取清单；接受无历史（估值前瞻版影子运行）；备选付费源 | 免费（备选约每月 30–100 美元） |
| **新闻** | 全市场、带**精确发布时间**、可回溯 | Nasdaq 按股票、只到日、只覆盖自选股 | **关键缺口** | **Alpaca News API**（Benzinga 全市场新闻，精确时间，可按时间窗回溯；现有 Alpaca 账号可用）；Tavily / Exa / Google 搜索做按需补证 | 免费（搜索按量，已有预算控制） |
| 一手数据 | App Store 榜单、搜索趋势、公司官网 | 无 | 缺 | 苹果官方榜单 RSS（每小时）；pytrends（非官方，限频，可能失效）；监控名单官网页面变化 | 免费 |
| 社交 / 大 V | 提及量、关键账号 | 无 | 缺 | 第一阶段**不接**，页面标"未接通"；以独立新闻来源数和搜索趋势代替 | X API 按量付费，暂缓 |
| 资金面 | 成交量、期权、空头、杠杆 ETF | Alpaca 成交量、CBOE 统计、Alpaca 期权、Muse 空头和期权快照 | 融券费率、逐笔、ETF 资金流 | 第一阶段不接，用现有代理 | —— |
| 宏观 | 利率、美元、VIX、商品 | FRED 全部在跑 | DXY 不可用（已有广义美元代理） | —— | 免费 |
| 产业数据 | 合约价、产能、交期 | 无 | 缺 | 不接；靠新闻中的定量表述和公司表态 | 付费源很贵，暂缓 |

**够不够全的结论**：

- **价格、公告、财报、宏观：够。**
- **新闻：现在不够，接入 Alpaca News 后基本够**。这是让"时间对齐"和"回捞"能工作的前提。
- **一手数据：免费的部分能覆盖应用榜单和搜索趋势**，足以支撑 DeepSeek、Meta Muse 这类案例。
- **社交、产业数据：不全**，第一阶段接受这个缺口，由漏检周报持续暴露它的代价，再决定是否付费。

|---|---|---|---|

| 08:05 | 新闻、8-K、榜单、搜索趋势入全量库；实体标注；向量化 | SEC Atom、glm-5.2 / Flash 抽取 | Alpaca News、榜单、趋势采集；嵌入；pgvector |

| 08:20 | 每个异常回捞 72 小时全量库；不足时用 Tavily / Exa / Google 按实体补搜 | `external/*` 搜索 | 回捞检索 |
| 08:30 | glm-5.3 对每个异常提出 ≤ 5 个候选（必须引用信息 id）；规则打分；隐含幅度检验 | LLM、Brain 暴露 / 同行对照 | 打分规则、图谱 |
| 08:45 | 直接暴露的持仓 / 候选触发 Brain 增量运行 | Brain | 触发器 |
| 09:30 | 三轨跟踪更新 | —— | 跟踪任务 |
| 10:30–12:00 | 财报、预期同步 → 估值重算 | Muse 数据 | 估值引擎、同步通道 |
| 12:30–13:00 | T+1 复盘打标；系统日志 | 预测打脸机制 | 案例库 |
| 20:00 | 盘前复核 → 覆盖层 → 盘前计划 | —— | 覆盖层、仓位规则 |
| 20:55 | Muse 执行 | Muse | 读覆盖层 |

**计算和 LLM 预算估计**（第一阶段）：

- 每天异常约 5–20 个；每个异常 1 次候选生成（推理档）+ 若干抽取（机械 / 快速档）；
- 新闻每天约数千条（全市场），但只对**覆盖池相关**和**监控实体相关**的条目做 LLM 抽取，约数百条，用快速档；
- Brain 增量运行每天 0–3 次；
- 按 DashScope 的价格，这个量级的日成本很低（远低于数据付费的量级）；主要约束是 **glm-5.3 的耗时**，必须在 20:00 前完成，因此候选生成要并行、要有超时降级（超时 → 该异常标"待分析"，不阻塞其他步骤）。

### 3.3 估值系统怎么建

**数据够不够**：

| 输入 | 来源 | 够不够 |
|---|---|---|
| 财报历史（周期归一化需要 7–10 年） | SEC companyfacts（约 2009 年起） | 够 |
| 本股 5 年倍数分位 | 价格（Alpaca SIP 历史约 2016 年起）+ 财报 | 够 |
| 一致预期（前瞻） | Muse yfinance 快照 | 当期够；**无历史**，前瞻版无法回测 |
| 稀释股本、分部 | `research/financials.py` 已有处理 | 够 |

**建法**：

1. **放在模块二**（Muse 侧，或作为共享库被 Muse 调用），不放在 stock-pm 的研究主路径，避免和 `FORBIDDEN_VALUATION_KEYS` 冲突。
2. **借用 stock-pm `research/financials.py` 的财务规范化**（稀释股本、利润率分离、一致预期前瞻 EPS）和 `research/valuation.py` 的类型框架思路（半导体用周期 PE、能源用归一化盈利），但**去掉 LLM 假设和代理研究**，改成第三部分第 2.2 节的固定算法。
3. **先做 TTM 版**（可严格回测），一致预期版影子运行一个财报季。
4. 每天输出 `valuation_ranges`，带方法版本、参数版本、变化分解。

**需要注意的一个现有矛盾**：stock-pm 研究模块现在会产出悲观 / 中性 / 乐观的**目标价**（`round_target`、`display_target`），而 Brain 禁止目标价。新的机械估值引擎上线后，建议研究模块的目标价只作为"研究参考"展示在研究详情页，**交易只认机械估值引擎的结果**，避免同一只股票出现两个"价值"。这需要你确认。

**结论**：数据够，借用代码可以缩短开发；主要工作是**五种类型的算法实现、回测、和 V1 规则验证**。

### 3.4 交易逻辑怎么做

| 组件 | 现有 | 需要改 |
