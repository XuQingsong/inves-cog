# 晴雨表需求 v1.0（2026-11-01）

> 由晴雨表 Demo（`docs/phase2/demo/barometer/`，原型）定稿为正式需求。总纲见 `phase2-plan.md` §3；数据见 §2。
> 定位（用户 2026-10-31、11-01）：**市场体温计**——如实量出市场正在发生什么，不预测涨跌；只提示，不改交易。
> 原型文件保留作参考：计算 `comp.py`，页面 `build.py` / `index.html`。正式实现以本文为准。

## 1. 读数结构

### 1.1 两侧综合读数（0–100）

- **恐惧侧（压力）**、**贪婪侧（过热）**各一个综合读数。
- 每个指标按事先写定的“平常值 → 极端值”线性折算为 0–100（低于平常值记 0，高于极端值记 100）；方面分 = 所含指标平均（缺数据的指标不计入，页面标缺）；综合 = 方面平均。
- 不设单项触发、不设升降档或“出清确认”规则；底层数据回到平常，读数当天随之回落。

期权指标（做市商 Gamma 敞口、翻转位、0DTE 占比、偏度、客户投机性看涨）从生产采集起前向积累；满 1 年后按同一方法登记进入“资金与杠杆”“多头与杠杆”，此前只在放大器面板展示、不计入读数。不购买期权历史数据（用户 2026-11-01）。

### 1.4 档位与钟摆

- 恐惧侧：平静 <7 ≤ 正常波动 <15 ≤ 偏紧张 <30 ≤ 紧张 <45 ≤ 恐慌。
- 贪婪侧：冷静 <15 ≤ 升温 <30 ≤ 偏热 <45 ≤ 过热 <60 ≤ 狂热。
- 分界按 2018 年以来分布划定（约第 50/75/90/97 百分位）；资金面全部接入后统一重新校准一次并登记，之后不再按结果调整。
- 钟摆七阶段（马克斯）：取档位更高的一侧——恐惧侧 偏紧张/紧张/恐慌 = 谨慎/悲观/绝望；贪婪侧 偏热/过热/狂热 = 乐观/兴奋/狂热；其余为理性。两侧同时到“偏紧张/偏热”以上标“剧烈摆动”。
- 钟摆连续位置 = 贪婪侧连续档位 − 恐惧侧连续档位（各自“正常”以下记 0），用于画摆锤角度。

### 1.5 上涨的性质

- 短期热度 = 超买、连续上涨、情绪普涨的平均；堆积程度 = 多头与杠杆、获利盘的平均。
- 判定：堆积 ≥45 且短期 ≥40 → **堆积型过热**（遇利空易集中兑现）；堆积 ≥45 且短期 <40 → **堆积未释放**；贪婪 ≥25、短期 ≥ 堆积 +25 且堆积 <25 → **超卖反弹型**；否则不标。
- 空头回补暂无历史数据（空头持仓仅 27 只、两周一次），扩到 59 只后作为超卖反弹的佐证展示。

### 1.6 放大器与杠杆面板（展示，不计入读数，期权项除外的均已在读数中）

- 趋势基金关键位：QQQ、SPY 距 50/100/200 日线与半年低点。
- 杠杆 ETF 当日收盘调仓额与 20 日净申购；融资余额与同比（标截至月份）；杠杆基金/资管期货净头寸（标截至周二、周五公布）；回购利率差；美元净流动性。
- 期权（前向积累）：SPX/SPY/QQQ 做市商 Gamma 敞口与翻转位、看涨墙/看跌墙、0DTE 占比、偏度、个股看跌看涨。
- 背景：席勒市盈率、AI 链相对大盘、2 年美债半年变化。

## 2. 数据与时点

- 全部数据来自生产 `flows.*` 与 `ingest.*`（见 `phase2-plan.md` §2）；每个值取“公布时间 ≤ 计算时点”的最新值，周/月频数据页面标“截至日期”。
- 计算时点：收盘后 16:45 ET 出当日正式读数；盘中每 15 分钟出临时读数（只用盘中可得指标，周/月频沿用最近值），页面标“盘中·延时 15 分钟”。
- 历史读数 2018 年至今一次性回算入库，回算与每日计算用同一代码。

## 3. 输出

- 表 `flows.barometer_daily`：date, asof, fear, greed, fear_level, greed_level, stage, pendulum, short_heat, accumulation, nature, dims（jsonb：各方面分）, inputs（jsonb：各指标原值与截至日期）, missing（缺数据指标列表）, code_rev。
- 表 `flows.barometer_intraday`：同上，按 15 分钟。
- 首页“市场状态”改为晴雨表结论（只保留一套说法）；晴雨表专页见 §4。
- 交易侧只读 stage、fear_level、greed_level、nature 四个字段，先影子记录（`phase2-plan.md` §4）。

## 4. 页面需求

原型的结构（钟摆 + 两侧 + 七阶段 + 分项 + 轨迹 + 历次对照）保留，视觉需重新设计（用户 2026-11-01：“还不够惊艳”）。设计方向：

1. **一屏讲完今天**：首屏只有一个主角——大尺寸钟摆。摆锤角度、光晕颜色与强度随读数变化；加载时有一次摆动后停在当天位置的动画。
2. **原因长在钟摆上**：两侧各方面做成环绕钟摆的弧形能量段（恐惧侧在左、贪婪侧在右），分数越高越亮、越饱和；点击某段展开它的指标与原值。不再用一排排卡片和进度条。
3. **一句话结论**：钟摆下方一行大字讲清“现在在哪、因为什么、离哪里还有多远”，例如“谨慎 · 纳指单日 −3.5% 拉响下跌冲击，杠杆 ETF 收盘被迫卖出 107 亿；距 200 日线仅 1.8%”。
4. **杠杆做成“压力仓”**：融资余额、杠杆 ETF、期权、期货杠杆基金四层堆叠，像油箱刻度一样显示满到哪，旁边标触发线（跌破 200 日线、Gamma 翻转位）。
5. **时间轴是心电图**：底部全宽镜像波形，上方贪婪（红）、下方恐惧（绿），标注历次事件；拖动即回放钟摆。
6. **视觉系统**：深色底、金色主色、红绿只用于两侧语义；标题宋体、数字等宽；动效克制（钟摆、计数、超过“紧张/过热”时轻微呼吸光）。
7. 1280 宽度一屏内看完首屏；所有数值标截至日期，缺数据明示；不出现内部编号、参数名、下单按钮、目标价、“实时”。

视觉稿先出高保真原型（替换 `docs/phase2/demo/barometer/index.html`），用户确认后再进生产页面开发。

## 5. 检验

- 紧张：2018-02、2018-Q4、2020-03、2022 三段、2023-03、2024-08、2025-04、2026-10 都读到“紧张”以上；2025-04-09 反弹、04-14 以后应随数据回落。
- 过热：2018-01、2020-08、2021-02、2023-06、2024-07、2026-05/06 读到“过热”以上；2026-06 存储周期显示“堆积型过热”→“堆积未释放”。
- 熊市反弹不得读成“狂热”：2022-07/08、2022-11（应为“超卖反弹型”）。
- 平静：2017、2019 大部分、2026-09 加息前后。
- 生产回算与原型 `comp.py` 在共同指标上逐日一致（差异 < 0.5 分），差异须能解释（数据源不同）。
