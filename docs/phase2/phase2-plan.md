## 0. 二期四条主线及关系

```
            ┌──────────────────────────────────────────┐
            │  D 数据与信息底座（核心）                    │
            │  历史回补 + 每日前向采集 + 衍生指标，全部按公布时点入库 │
            └───────┬───────────────┬──────────────────┘
                    │               │
          ┌─────────▼─────┐   ┌─────▼────────────┐
          │ M 市场晴雨表     │   │ R 回测             │
          │ 恐惧/贪婪两侧综合 │   │ 规则 A 基线、v19、候选 │
          └─────────┬─────┘   └─────┬────────────┘
                    │  只提示/影子      │ 证据
                    └──────► V 交易规则 v19 ◄──┘
```

- D 是其他三条的前提：晴雨表的每个指标、回测的每一天，都只能用 D 里“当时已公布”的数据。
- M 只提示，不改交易；接入交易只能走“影子记录 → 回测证据 → 用户批准”。
- R 用的是与线上同一套规则代码；V（v19）先在 R 中验证，再影子运行，最后由用户批准切换。

## 1. 硬约束（继承一期 + 二期新增）

1. 模块一（感知）与模块二（交易）严格分开；二期新增数据只进感知侧，交易侧只能读晴雨表的结论字段，且先影子。
2. **按公布时点（PIT）**：每条数据记三个时间——数据所属日（如 CFTC 的周二持仓）、公布时间（周五 15:30 ET）、入库时间。回测和历史检验只能用“公布时间 ≤ 当天决策时点”的值。
3. **历史与前向同一口径**：回补的历史与每天新采的数据进同一张表、同一套解析代码；历史是用公布后的修订值还是首发值，逐个来源写明（见 §2.6）。
4. 缺数据必须明示，不能显示成 0 或“无风险”。
5. 原始文件留档（来源 URL、抓取时间、哈希），任何衍生值都能追溯到原始文件并重算。
6. 二期不得影响一期线上进程与规则 A 结果：独立 schema、独立定时任务、独立失败隔离；一期 `ingest.*` 只读。
7. 页面不出现内部编号、参数名；不出现下单按钮、目标价、“实时”。延时数据标“延时 15 分钟”“截至某日”。

### 2.6 质量规则

- 每个来源写明：首发值还是修订值、节假日处理、拆分/合股处理（ProShares 有拆分历史文件）。
- 回补与前向在重叠期必须对得上（如 Cboe 每日接口与历史 CSV 在 2019-10 前后、OCC 与 Cboe 链的持仓）。
- 每日核对：份额变化超过 ±30%、持仓为 0、期权链合约数骤降，标“待核”，不进衍生指标。
- 页面每个资金面数值旁标“截至日期”；超过应有时效的标黄。

## 3. 市场晴雨表（M）

定位：**市场体温计**，量正在发生的事，不预测。（用户 2026-10-31、11-01 多次强调）

### 3.1 读数结构

- **恐惧侧（压力）** 与 **贪婪侧（过热）** 各一个 0–100 综合读数。每个指标按事先写定的“平常值 → 极端值”线性折算 0–100；方面分 = 指标平均；综合 = 方面平均。不设单项触发、不设升降档规则；数据回到平常，读数当天随之回落。
- 恐惧侧方面：下跌冲击、恐慌情绪、债市信用、超卖扩散、去杠杆，**新增“资金与杠杆（压力）”**：杠杆基金快速转空、杠杆 ETF 收盘卖出额、ETF 赎回、客户看跌激增、Gamma 转负且跌破翻转位、回购紧张、净流动性收缩。
- 贪婪侧方面：超买、连续上涨、多头与杠杆、获利盘、情绪普涨，**“多头与杠杆”扩充**：融资余额增速、杠杆 ETF 份额增长、客户投机性看涨、期权看涨持仓分位、资管净多分位、空头持仓低位。
- **上涨的性质**：短期热度（超买、连续上涨、情绪普涨）× 堆积程度（杠杆、获利盘、期权看涨堆积）。右下“超卖反弹型”、右上“堆积型过热”、左上“堆积未释放”。
- **放大器面板**：趋势基金关键位（50/100/200 日线、前低）、Gamma 翻转位与看跌墙、杠杆 ETF 今日调仓额、追加保证金风险提示（融资余额高位 + 指数跌破关键位）。
- 档位按 2018 年以来分布划分（恐惧侧 7/15/30/45，贪婪侧 15/30/45/60），资金面指标接入后重新校准一次并登记。
- 周/月频数据按公布日计入，页面标“截至日期”。

## 5. 回测（R）

### 5.1 原则

1. 调用线上同一套规则 A 打分（M3）与纸面执行（M4）代码，不另写；v19 也写在同一套代码里，用开关区分。
2. 按日推进，每天只给规则看“当天收盘前已公布”的数据（§1.2 的公布时点）；财报按 SEC 提交时间生效；股票池按当时成员。
3. 成交时序与成本同纸面账户：收盘后出信号，次日开盘价成交，计佣金与滑点；限价单按次日最低价判断是否成交。
4. 回测写独立 schema `backtest`，独立进程，不碰一期结果。
5. 参数事先登记；第一轮之后只允许统一修改一次并写明理由；禁止在同一段历史上反复调参。
