## 1. 目标与范围

### 1.1 要解决的问题

1. **市场在动，但基本面慢**：消息、情绪、资金每天在变；公司基本面按季度变化。系统要判断价格的变化是否对应基本面的变化，两者背离时给交易提供依据，而不是跟着情绪追涨杀跌。
2. **异常要能被看到**：不管有没有新闻，股价异常（个股、板块、主题、大盘）都要被发现。
3. **源头要能被找回**：引发异常的源头信息常常当时看起来很普通（一条榜单变化、一位分析师的爆料），不能被过滤掉。
4. **连接要讲证据**：事后能找一百种理由，系统要用当时可得的证据给出候选解释和置信度，区分"市场在按这个逻辑交易"和"这个逻辑在经营上成立"。
5. **持续跟踪**：情绪、资金、基本面各自跟踪到有结论为止。
6. **估值和交易**：所有标的都有评分和估值；仓位、止损止盈有逻辑；突发系统性事件下不机械止损。
7. **用户看得懂**：系统做了什么、没做什么、为什么，都能看到。
8. **自我闭环**：每个异常都变成案例，系统通过复盘逐步具备感知能力。

### 1.2 第一阶段目标（以天为单位，允许延迟）

| # | 能力 | 判断标准 |
|---|---|---|
| A1 | 感知股价异常 | 每个交易日收盘后（含盘后收盘价），发现所有覆盖标的和主题篮子的异常 |
| A2 | 自主建立符合逻辑的连接 | 对每个异常自动给出候选解释、证据和置信度，无需人工发起 |
| A3 | 基础分析 | 每个异常有一份标准化的解释报告：冲击分解、影响范围、跟踪清单 |
| A4 | 稳定的估值体系 | 所有标的每天有可复现的估值区间；没有基本面变化时价值不动 |
| A5 | 合理的交易行为 | 交易由规则 A 机械产生，每个动作和"不动作"都有理由 |
| A6 | 复盘补强 | 每个异常都变成案例，案例沉淀为模式、权重和先兆特征，按规则晋级 |

 行情 / 新闻 / SEC ──▶ │ ① 信息获取 ─▶ ② 异常发现 ─▶ ③ 建连归因 ─▶ ④ 三轨跟踪          │

                      │        规则：价格不改基本面 / 传闻隔离 / 慢层变化要证据         │
                      └───────┬──────────────────────────────┬─────────────────────┘
                              │ 价格结构层 marketstate        │ 覆盖层 overlay（只收紧）
                              │（只用价格，可回放）           │ 影子信号 X1–X4（只记录）
                      ┌───────▼──────────────────────────────▼─────────────────────┐
                      │            模块二：估值与交易（规则 A 在本项目内重写）           │
                      │ ⑤ 估值区间 v1.1（只展示） ⑥ 规则 A：四本账 → 红线 → 分层 → 订单 │
                      │                           A+（默认关闭）                     │
                      └───────────────────────────────┬─────────────────────────────┘
                                                      ▼
                      ⑦ 复盘补强：案例 → 模式 / 权重 / 图谱 / 先兆 / 规则候选 → 治理流程
```

两个模块之间**只有三条通道**，方向都是模块一 → 模块二：

| 通道 | 内容 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 覆盖层 | 冷静期、撤单（第 11.2 节） | 暂停新买和加仓、撤未成交买单 | 新增买单、提高数量、卖出 |
| 价格结构层 | 系统性冲击标志、个股剩余涨跌、篮子广度（第 11.3 节） | 第一阶段只展示；A+ 的 S10 读取 | 读新闻、读 LLM、读估值 |
| 影子信号 | X1–X4（第 11.4 节） | 写入影子 schema，供复盘评估 | 进入任何订单 |

### 2.2 快慢机制：三个时钟

| 层 | 内容 | 变化速度 | 能影响什么 |
|---|---|---|---|
| 快 | 价格、资金放大特征、叙事热度、榜单、搜索 | 天 | 异常发现、情绪轨道、资金轨道、时机账、冷静期 |
| 中 | 一致预期修订、公司 8-K 表态、产业数据 | 天到周 | 基本面轨道、估值区间（预期变化 > 3% 时）、背离标签 |
| 慢 | 季度财报（10-Q / 10-K）、分部盈利、经"已验证"门槛确认的基本面结论 | 季度 | 质量账、成长账、持有资格、估值类型、分层 |

**核心约束**：只有基本面轨道能改估值；情绪和资金只能影响时机、冷静期和标签；价格只影响估值区间里的"位置"，不改区间本身。

### 2.3 原则

**归因不确定下的决策**：系统不可能在当下确定因果。本设计不追求"猜对原因"，而是追求"原因不确定时也做对决策"。

| 决策 | 依赖什么 | 是否需要知道"真正原因" |
|---|---|---|
| 值多少（估值区间） | 财报、一致预期 | 不需要 |
| 能不能买（规则 A 门槛） | 四本账 | 不需要 |
| 冷静期 | 是否有"直接暴露、正在核查"的事件 | 需要，但错了只是少买几天 |
| 止损复核（S10，默认关闭） | 价格结构：下跌是否主要来自市场 β | 不需要新闻归因 |
| 研究优先级 | 归因候选、暴露、置信度 | 需要，但错了只浪费研究时间 |

归因错了的代价被限制在"冷静期多停几天"或"研究资源浪费"，不会直接变成一笔交易。

| # | 原则 | 含义 |
|---|---|---|
| P1 | 研究与交易单向依赖 | 交易模块不读新闻、LLM 输出和估值；只读行情、财报、覆盖层标记、价格结构层 |
| P2 | 覆盖层只能让交易更保守 | 暂停新开、撤销买单都是"少做"；任何"多做"或"少卖"（例如 S10）必须先回测、批准 |
| P3 | 离散快照 | 覆盖层按版本发布；缺失时交易照常运行并标注 |
| P4 | 新规则走治理流程 | 一次一条、PIT 回测、与定版对比、批准 |
| P5 | 状态不压缩成一个分 | 消息真实性、叙事传播、市场关联、经营传导、交易状态分开展示 |
| P6 | 未知必须有终点 | 每个待核查问题有截止日，到期必须落到"支持 / 反证 / 条件风险"之一，不能自动续期 |
| P7 | 诚实覆盖 | 没接通的数据显示"未接通"；转载数量不等于独立证据数量；不生成模拟数值 |

### 2.4 估值与交易解耦（硬约束）

| # | 约束 | 怎么保证 |
|---|---|---|
| H1 | 交易模块只读：行情、第 9 节规格需要的财报字段、Form 4、VIX、`earnings_events`、账户状态、覆盖层限制标记、价格结构层 | 输入清单写进配置，评审核对 |
| H2 | 估值结果存放在独立 schema `valuation_v1` | 交易服务的数据库账号**没有**该 schema 的读权限 |
| H3 | 代码层面不允许依赖 | 门禁测试：交易模块不得引用估值模块；订单理由不得出现"悲观 / 中性 / 乐观 / 目标价 / p= / 估值区间" |
| H4 | 依赖方向只能是"估值 → 读交易" | 估值模块可以只读订单和持仓做影子对比；反向禁止 |
| H5 | 影子记录 | 估值模块每天记录"如果 V-T1 / V-T2 / V1 / V2 / V3 生效会有什么不同"，只写估值 schema |
| H6 | 启用条件 | 收紧类（V-T1、V-T2）：至少一个财报季的影子数据 + 历史评估 + 用户批准；放宽或改仓位类（V1–V3）：至少两个财报季 + 回测 + 批准。之前任何估值规则都不能影响订单 |
| H7 | 与外部系统的关系 | 本项目不依赖 stock-pm 或 Muse 的代码；估值结果只在本项目 `/paper/*` 页面显示 |

### 2.5 鲁棒性机制

| # | 机制 | 防止什么 |
|---|---|---|
| R1 | 交易动作依赖基本面和规则，归因只影响冷静期与研究 | 错误归因直接导致错误交易 |
| R2 | 价格先行的异常发现，不依赖新闻 | 新闻没抓到就看不到异常 |
| R3 | 信息全量保存 + 异常触发回捞 | 源头被当作普通信息丢掉 |
| R4 | 一手数据源监控（榜单、搜索、官网、SEC） | 源头不在新闻里 |
| R5 | 多候选 + 双置信度 + 按渠道的隐含幅度 | 事后编故事、单一归因 |
| R6 | "原因未明"有固定动作 | 不知道原因时乱动或装作知道 |
| R7 | 三轨分离，只有基本面轨道改估值 | 情绪和价格污染估值 |
| R8 | 覆盖层只收紧；放宽动作要先回测；硬线不受影响 | 系统出错时放大亏损 |
| R9 | 完整性不变量：每个超过阈值的异常、每条高优先级信息都有处置结论，没有的标红 | 静默遗漏 |
| R10 | 截止日不续期 | 永远"分析中" |
| R11 | 归因事后打标（二次命中检验）与校准 | 系统自我感觉良好 |
| R12 | 历史案例回放作为回归测试 | 改版后能力退化 |
| R13 | 数据源健康 + 覆盖自检 + 数据缺口不静默 | 数据断了还以为市场平静；缺数据被当成 0 分 |
| R14 | 故障降级：感知、估值、覆盖层任一停摆，交易照常运行并标注 | 单点故障 |
| R15 | 价格结构层只用价格、可回放 | 模块之间靠不可回测的信号相互影响 |

### 2.6 独立项目与借鉴的设计

本系统是一个**独立项目**：

- 全部代码、测试、配置、数据库迁移都在本仓库 `XuQingsong/inves-cog`；
- 不导入、不调用 stock-pm 或 Muse 的代码，不读写它们的数据库，部署上也不依赖它们；
- Muse 只用于三件事：一次性导入历史数据（一致预期快照、Form 4、VIX）；v18 标准答案；规则 A 中规格没写明的计算细节以 Muse 源码为参照（在本项目内重写，不拷贝）。

stock-pm 里有一些已经验证过的设计思路，本项目**借鉴思路、自己实现**：

| 设计思路 | 本项目里在哪实现 |
|---|---|
| 价格不能改写基本面 | 估值三档不读现价（I17）；只有基本面轨道能改估值（第 2.2 节）；最初用于发现异常的价格变化不能再作为经营证据（第 6.12 节） |
| 传闻隔离 | 真实性维度（第 6.12 节）；未核实的内容只计入叙事维度，不能作为"已验证"的证据（第 7.3 节） |
| 慢层变化要证据、不能被单条新闻带偏 | "已验证"门槛（第 7.3 节）、截止日不续期（第 7.2 节）、转载不算独立证据（第 6.3 节） |
| 连接要有证据阶梯 | 图谱关系状态：候选 → 观察到 → 有支持 → 已确立（第 6.11 节） |
| 信源分级 | 1–4 级（M1 FR-M1-09） |
| 价格背离 | 背离标签（第 7.4 节） |
| 预测要能被打脸 | 案例 T+1 / T+5 / T+20 打标（第 13 节） |

## 3. 标的池与市场结构

### 3.1 四层市场主体

| 层级 | 主体与成员 | 用途 |
|---|---|---|
| L1 市场整体 | SPY、QQQ、IWM、广度、利率、美元、信用、VIX | 区分整体风险、风格因素与局部异常 |
| L2 一级行业 / 板块 | 第 3.3 节的板块及行业 ETF | 相对强弱、内部广度、集中度 |
| L3 细分产业与主题 | 业务组（HDD、CPU、数据中心电力……）与叙事主题、关系篮子（OpenAI 合作方） | 业务组按经营暴露归类；叙事主题不冒充统一业务 |
| L4 公司与经营节点 | 公司、分部、产品、客户、供应商、核心指标 | 具体暴露和经营传导，对接基本面档案和交易 |

规则：

- 同一公司可属于多个篮子；成员和权重带生效时间。
- 组内统计至少给出：成分覆盖率、等权和市值加权表现、异常成员比例、离散度；**汇总按去重公司计算**，同一股票不能经 ETF 和主题重复贡献。
- **扩散只能逐层向上**：L4 异常先更新 L3；有行业广度支持才扩大到 L2；L1 状态转换需要宽基 + 广度 + VIX / 信用的独立证据。
- **反向只做提示**：L1 冲击可以对 L4 生成"背景风险检查"，不能直接判定所有公司盈利下降。

## 4. 信息获取与数据质量

### 4.1 信源（定稿）

| 项 | 做法 | 覆盖 |
|---|---|---|
| 新闻 | Alpaca News API（Benzinga），全市场，精确发布时间，入全量库 | 全市场 |
| 补证搜索 | Tavily / Exa / Google CSE，按实体和时间窗按需调用，每天调用次数有上限（参数表 `search_daily_budget`，初始 200 次） | 异常回捞时 |
| 公告 | SEC 8-K Atom 流、按公司 8-K（含 Item 2.02、7.01、8.01）、Form 4 | 全市场（Form 4 先覆盖标的池） |

| 行情 | 分钟线采集窗口延长到美东 20:00（拿盘后收盘）；广域日线批量任务 | 标的池 + ETF 做分钟线；广域只做日线 |
| 宏观 | FRED（CPI、非农、2 年期、VIX、WTI、广义美元）、美联储 / EIA 新闻稿 | —— |
| 资金面 | Alpaca 成交量、CBOE 期权统计、FINRA 空头（每月两次） | —— |
| 全量库 | PostgreSQL + pgvector + DashScope 嵌入；实体和时间索引 | 全部入库信息 |
| 财报 | SEC companyfacts + submissions，按申报日可见（PIT） | 标的池 59 只 |
| 一致预期 | 每日快照（EPS 当年 / 次年、营收、修订家数、目标价） | 标的池 59 只 |

**监控实体清单**由图谱自动生成：每个篮子的关键上游主体，包括非上市公司（OpenAI、Anthropic、DeepSeek）、关键产品（Muse、ChatGPT、Gemini）和关键数据（HDD 合约价）。

**第一阶段不接**：X / 社交、融券费率、逐笔数据、产业价格数据（合约价、交期）、付费一致预期历史。页面如实显示"未接通"，代价由漏检周报暴露，再决定是否付费。

### 4.2 财报事件时间（新增）

**新表** `earnings_events`，每次财报发布一行：

| 字段 | 定义 |
|---|---|
| `ticker`、`accession` | 8-K 的申报号 |
| `item` | `2.02`（Results of Operations） |
| `accepted_at` | SEC 接收时间（美东） |
| `session` | `pre`（09:30 前）/ `intraday` / `post`（16:00 后） |
| `reaction_day` | `pre` 或 `intraday` → 当日；`post` → 下一交易日 |
| `ref_close` | 发布前最后一个收盘价 |
| `fiscal_period` | 对应的财季；10-Q / 10-K 申报后回填 |

- **所有"财报日跳空"判断（B5、S2、S4）只用 `reaction_day`**；10-Q / 10-K 申报日不得作为反应日（I28）。
- 规则 A 的四本账仍按 10-Q / 10-K 申报日更新（M-02 不变）：财报发布时 XBRL 数字还不可得，等 10-Q 生效才进打分。
- 来源：SEC submissions 接口的 8-K `items` 字段（可回放历史）；缺失时用 Alpha Vantage 财报日历补，标 `earnings_event_fallback`；两者都没有，健康码 `earnings_event_missing`，依赖它的规则当期不触发。

### 4.7 运行环境与需确认的资源

- 独立部署：本项目自己的服务和 PostgreSQL 数据库（库名 `inves_cog`，含 pgvector）；部署机器由开发确定；不部署 Muse 或 stock-pm 的代码。
- 需确认：Alpaca、Tavily、Exa、Google CSE、SEC 访问身份、Alpha Vantage、DashScope、两个 LLM 的接入方式（以环境变量提供，不需要把 key 写进文档）；部署机器的 CPU、内存、磁盘能否承载广域日线和向量库。
- **LLM 只用两个模型**，按任务分档，分档写死在配置里（I37）：

| 档 | 模型 | 任务 | 超时 | 失败时 |
|---|---|---|---|---|
| 困难 | `glm-5.3` | 异常的候选机制生成（建连）；图谱种子和美元暴露的起草；分部名称 → 图谱节点映射的起草 | 900 秒 | 该任务标"待分析"，不降级到另一个模型，不阻塞其他步骤 |
| 其他 | `deepseek-v4.1-flash` | 说法抽取、实体标注、信源和时间字段抽取、新闻去重辅助、系统性事件类型标签、摘要和页面一句话 | 120 秒 | 重试 2 次，仍失败标"抽取失败"，该条信息只走规则检索 |

- 不允许出现第三个模型；困难档任务不得改用 `deepseek-v4.1-flash` 省时间，其他档任务也不得升级到 `glm-5.3`。向量嵌入（DashScope 嵌入模型）不是对话 LLM，不受本条限制。
- **LLM 只做两件事**：从文本抽取结构化"说法"（含标签），从回捞信息中提出候选机制（必须引用信息 id）。所有判断由规则完成。
- 每天约 5–20 个异常、数百条需要抽取的信息；主要约束是 `glm-5.3` 的耗时，候选生成必须并行、有超时降级。

## 5. 模块一 · 异常感知（日级）

### 5.1 四层剩余涨跌

不用"涨跌超过 5%"这种固定阈值。每只股票、每个篮子每天计算：

```
剩余涨跌 = 实际涨跌 − β市场 × 大盘涨跌 − β行业 × L2 涨跌 − β主题 × L3 篮子涨跌
```

β 用过去 120 个交易日滚动估计；历史不足时用同行差值并降级，不伪造统计显著性。

| 层次 | 看什么 | 例子 |
|---|---|---|
| 大盘 | QQQ / SPY 相对自身波动 | OpenAI 传闻当天 QQQ 异常下跌 |
| 主题篮子 | 篮子相对大盘的剩余涨跌 | "AI 算力"剩余 −3σ；"CPU"剩余 +3σ |
| 个股相对篮子 | 个股相对所属篮子的剩余 | AMD 相对 CPU 篮子正常 → 是整个篮子在动 |
| 篮子内部离散 | 一起动还是个别动 | CPU 篮子 4 只里 4 只同向 → 主题级事件 |

**两个时段分别算**：收盘到收盘、收盘到盘后收盘（美东 20:00）。盘后暴跌在北京时间次日 09:15（夏令时；冬令时 10:15）的异常清单里就能看到。

**多日累积异常**：连续 3–5 日同向剩余累积超过阈值也算异常。这类"阴跌 / 缓涨"单日不明显，往往是资金持续进出。

### 5.2 三条发现路径

任一触发即建立异常，不要求三条同时通过：

| 路径 | 条件 | 解决的问题 |
|---|---|---|
| A 总冲击 | 一组股票原始收益同步异常（≥ 该组自身历史波动 3 倍，且同向 ≥ 60%） | 整组一起跌、但剔除大盘后个股剩余近零（QQQ 和 AI 股同跌）不会被漏掉 |
| B 相对异常 | 个股剩余 ≥ 3σ，或相对同行 ≥ 4% | 局部的个股或环节事件（HDD） |
| C 因子自身异常 | 宽基、行业、风格或跨资产代理相对自身历史异常 | 市场 / 风格冲击，随后追踪成分 |

成交量 ≥ 3 倍均量只作描述，不单独触发。

### 5.3 核对、聚类与归层

1. **数据质量先核对**：报价来源、复权、拆股、交易时段、异常成交条件；缺数据标"待核验"，不生成"流动性崩溃"之类结论。
2. 同一时段内方向一致的异常按时间同步聚类，再用图谱和四层主体解释成员；不先限定"同一标签"。
3. 簇级结构判定推广 `peer_pattern`：公司特有 / L3 环节 / L2 行业 / L1 市场。
4. ETF 与成分股不重复计数；三条路径命中同一对象只算一个异常，保留各入口。
5. 每个参照标注"是否可能同受该事件影响"；受影响的参照不能充当"未受影响"的对照。

### 5.4 冲击分解

```
总剩余涨跌 = 事件可解释部分 + 资金放大部分 + 未解释部分
```

| 部分 | 怎么估 |
|---|---|
| 事件可解释 | 按渠道的隐含幅度检验（第 6.7 节）给出的事件影响上限换算成涨跌幅；检验结果为"无法检验"时记为 0，并在报告里标明 |
| 资金放大 | 超出事件可解释部分、且同时出现第 5.5 节资金放大特征的部分 |
| 未解释 | 剩下的部分 |

三项之和必须等于当日剩余涨跌（允许 0.1 个百分点舍入，I23）。分解不精确，但它把"消息被资金利用并放大"这件事显式记录下来，供复盘统计。

### 5.5 资金放大特征（只用免费或现有数据）

| 类型 | 特征 | 数据 |
|---|---|---|
| 轧空 | 空头占流通股比例高；回补天数高；上涨伴随成交量 > 3 倍均量；跳空高开；看涨期权持仓和隐含波动率同升；上涨发生在利空或无消息时 | FINRA 空头（约两周滞后）、CBOE 期权、日线 |
| 踩踏 | 拥挤度高（6 个月涨幅前 10%，篮子内部相关性上升）；跳空低开 + 放量；篮子广度坍塌（> 80% 同跌）；看跌隐含波动率跳升、偏度变陡；随后数日快速回吐 | 日线、篮子相关性（自算）、CBOE |
| 杠杆 / 被动 | 相关杠杆 ETF 规模和当日涨跌；指数调整日；期权到期日 | ETF 日线、日历 |
| 情绪放大 | 叙事热度（来源数、搜索、榜单）上升速度远快于基本面证据 | 情绪轨道 |

输出：每个异常一个资金放大类型候选（轧空 / 踩踏 / 杠杆被动 / 情绪放大 / 无）及特征明细。**只描述**，不进估值，不单独触发交易；用于冲击分解、复盘统计和先兆特征。

**资金面信号分级**：

| 信号 | 验证状态 | 用法 |
|---|---|---|
| 内部人公开市场买入（Form 4，代码 P） | Muse 已验证有效 | 规则 A 首笔加成（M-36）；基本面核查的正面证据 |
| VIX 恐慌区 | Muse 已验证有效 | 规则 A 恐慌闸门（M-63）；系统性冲击判定 |
| 8-K 指引变化 | 上调弱正，下调样本不足 | 一级信源事实 |
| 大额成交、期权墙、Put/Call | 未验证 | 只展示 |
| CMF / OBV"吸筹 / 派发" | **同类量能信号已被 Muse 证伪** | 降为纯展示，文案不得出现"吸筹 / 派发"判断 |

由同一成交序列算出的多个指标（CMF、OBV、tick rule、成交量倍数）**只算一个通道**。不能凭跌幅或 Put 持仓认定"机构卖出""做市商对冲"等具体行为。

### 5.6 异常类型候选（C2 的起点）

| 类型 | 典型组合 |
|---|---|
| 事件冲击（基本面型） | 隐含幅度相容；一级 / 二级信源；暴露梯度明显 |
| 叙事 / 估值冲击 | 隐含幅度不相容；叙事证据强；资金放大特征明显；之后快速回吐 |
| 轧空 | 空头集中 + 无消息或利空下放量上涨 |
| 踩踏 | 拥挤 + 广度坍塌 + 跳空放量 |
| 主题轮动 | 一个篮子跌、另一个篮子涨，大盘平稳 |
| 宏观 / 流动性 | 大盘层异常；利率、美元、VIX 同步；无单一事件 |
| 原因未明 | 以上都不成立 |

第一阶段只给类型候选和理由，准确率由复盘统计，不作为交易依据。

### 5.7 输出对象

```
anomaly_id, 交易日, 时段(收盘/盘后/盘前复核), 触发路径[A/B/C/累积],
层次(L1–L4), 篮子, 成员[ticker, 涨跌%, 剩余%, 成交量倍数],
起点时段, 扩散路径, 方向, 数据质量核对结果, 检测覆盖率, 缺失资产,
冲击分解, 资金放大类型候选, 异常类型候选, 处置状态
```

**关键点**：哪怕当时一条新闻都没抓到，异常也会被发现，并进入"已发现·原因未明"状态。

## 6. 模块一 · 源头捕获与建连

### 6.1 源头常常不是新闻

| 案例 | 源头 | 新闻什么时候出现 |
|---|---|---|
| DeepSeek（2025-01，真实） | R1 模型一周前发布；周末登顶 App Store 免费榜，社交扩散 | 大跌当天及之后，新闻在解释已经发生的下跌 |
| Meta Muse 登顶 | App Store 榜单 | 晚于榜单变化 |
| OpenAI ARR 传闻 | 分析师 / 媒体爆料（四级信源） | 本身就是新闻，但信源弱 |
| 东芝扩产 | 公司公告 / 媒体 | 同步 |

所以要直接监控一手数据。**一手数据突变本身就是信号**：监控实体的榜单名次跳升 > 20 名、搜索热度 > 自身 3 倍历史、官网发布新产品，即使没有新闻报道，也直接进入关注队列。

### 6.2 信息不删除：回捞

**问题根源**：按重要性打分、低分丢掉。"Muse 登顶"在当下看起来就是一个 App 排名变化，很可能被打低分。

**回捞规则**：每出现一个异常，用异常的成员、篮子、关联实体、上下游主体生成检索条件（规则 + 向量检索），**在全量库里重新检索异常起点前 72 小时到当前的全部信息**，按与异常的相关性重新排序。当时排在后面的"Muse 登顶"，会因为"CPU 篮子异常 + META 异常 + Meta 系应用榜单变化"三者的实体重合被捞回来。全量库不足时，用补证搜索按实体和时间窗补搜。

**漏报控制**：每天 3 条探索名额；每周随机抽样 20 条被丢弃的信息人工复核，后来证明重要的计入漏检评价（第 13.4 节）。

**覆盖自检**：每天统计有多少异常找到了候选、多少是"原因未明"。原因未明的比例持续上升 → 数据源健康页报警。

### 6.3 说法与鉴伪

- 信息抽取生成具体"**说法**"：谁、何时、对哪个实体 / 变量 / 机制、提出什么变化；量化值、兑现期、确定性和出处分开保存。原文不支持的字段保持未知。
- **传闻拆成两件事**："某来源发表了该说法"是传播事实，可以核实，进叙事维度；"该说法的内容属实"必须独立验证，未验证前只计入叙事维度，不能作为经营传导的证据。
- 鉴伪检查：原始出处、完整表述、发布时间、首次取得时间、是否旧闻重发、传播关系、独立来源数（按来源根去重）、反方材料。
- **晚于异常起点的报道可以解释后续传播，不能解释之前的下跌**。
- 重要性队列（决定 LLM 预算先花在哪）：① 持仓的经营证伪或风险越限；② 直接量化的经营变化；③ 异常中的新解释；④ 可能改变产业关系的新机制；⑤ 普通重复背景。真实性与优先级独立：官方重大信息即使传播很低也必须核验。

### 6.4 弱信号累积

没有价格异常时，也要能发现分散的小信息拼起来的变化（招聘、认证、设备安装、客户调整……）。

- 观察窗 30 个交易日内，≥ 3 个不同来源根、覆盖 ≥ 2 个不同阶段的线索指向同一经营变量，且没有直接反证 → 建立"假设中"的联动事件和补证任务。
- **只提高研究优先级**，不升级真实性、不改基本面结论、不进覆盖层。

### 6.5 自主建连的分工

| 步骤 | 谁做 | 约束 |
|---|---|---|
| 回捞候选信息 | 检索 | 72 小时窗口，全量库 |
| 提出候选机制 | LLM | 必须引用回捞到的信息 id；无引用的候选被丢弃（I23）；每个异常最多 5 个；另加固定的"无事件 / 资金面"默认候选 |
| 证据打分 | **规则** | 第 6.6 节 |
| 隐含幅度 | **规则** | 第 6.7 节；美元暴露只能来自带信息 id 的图谱边 |
| 影响范围 | 图谱 + 规则 | 直接 / 间接 / 概念关联 / 纯共振 |
| 新连接入库 | 系统起草 | 新边一律从"候选"开始，升级走证据阶梯 |

**LLM 负责"想到"，规则负责"判断"**。新机制能被提出来（"智能体多任务 → CPU 需求"），但不会因为 LLM 说得像样就被当真。

### 6.6 证据打分

| 证据 | 怎么算 | 初始权重 |
|---|---|---|
| 时间对齐 | 信息首次可得时间 vs 异常起点（日级：按交易日和盘前 / 盘中 / 盘后三个时段；有分钟数据时细化）。早于或同时 → 高分；晚于 → 0 | 20% |
| 暴露梯度 | 图谱给每个成员一个暴露度；暴露度和剩余涨跌的秩相关 | 20% |
| 篮子特异性 | 预期受影响的篮子动了，预期不受影响的对照篮子没动（CPU 涨、GPU 不涨） | 15% |
| 叙事证据 | "事件 + 受影响对象"共同出现的独立来源数（按来源根去重） | 15% |
| 隐含幅度 | 第 6.7 节 | 15% |
| 替代解释排除 | 同时段是否有成员自身财报、指引、评级、宏观数据 | 15% |

输出两种置信度，**分开展示**：

- **市场归因置信度**（高 / 中 / 低）：市场是不是在按这条逻辑交易；
- **基本面成立度**（待验证 → 由基本面轨道更新）：这条逻辑在经营上是否成立。

**这正好回答"它怎么知道 CPU 上涨是 Muse 登顶带来的"**：它不"知道"，而是判断"市场正在按这个叙事交易"的证据有多强，同时判断"这个叙事在经营上能不能撑起这么大的市值变化"。两件事分开回答。

### 6.7 隐含幅度检验（按渠道）

这是把"这条消息禁不禁得住推敲"机械化的工具。v1.0 起**按传导渠道分别计算**。

**市场侧**：

```
市场隐含的年盈利变化 ΔE_mkt ≈ 市值变化 ÷ 当前 PE（TTM；有一致预期时同时给 NTM 口径）
```

成长类标的另给一个读法：用估值 v1.1 的隐含增速（第 8.5 节），显示"市场把隐含增速从 X% 调到 Y%"。

**事件侧**：事件可能带来的年盈利变化上限 `ΔE_evt`，**按渠道分别计算**，只用图谱边上带信息 id 的美元暴露（第 6.11 节）：

| 渠道 | 上限公式 | 美元暴露来源 |
|---|---|---|
| 直接收入 | 受影响收入 × 收入变化上限 × 增量利润率 | 收入占比、客户集中度（10-K） |
| 订单 / 积压 | 依赖该主体的订单积压或剩余履约义务（RPO）× 延期或取消比例上限 ÷ 兑现年数 × 增量利润率 | 10-Q / 10-K 的 RPO 披露、8-K 合同公告、带信息 id 的报道 |
| 供给 / 价格 | 受影响收入 × 价格变化上限 × 增量利润率 | 新闻中的定量表述、产业数据（未接通时缺项） |
| 融资 / 对手方 | 对手方相关的应收、预付、承诺金额 × 违约或延期比例上限 | 同上 |
| 估值倍数 | 没有盈利上限 | —— |

"变化上限""比例上限""增量利润率"是**登记参数**（第 17 节），按信源等级分档（四级传闻的比例上限低于已核实事实），不由 LLM 临场给数。LLM 可以提出"还有哪条渠道"并引用材料，但数字只能来自带信息 id、状态 ≥"观察到"的图谱边。

**判定**：比值 `R = |ΔE_mkt| ÷ ΣΔE_evt`（各渠道之和）。

| R | 结论 | 含义 |
|---|---|---|
| ≤ 1.5 | 相容 | 当期盈利渠道能解释幅度 → 进基本面核查 |
| 1.5–5 | 部分相容 | 部分可解释，其余可能是倍数 / 长期预期 / 资金放大 → 进基本面核查 |
| > 5 | 不相容 | 当期盈利渠道解释不了幅度 |
| 缺美元暴露 | **无法检验** | 不得记为"不相容"；在图谱补暴露任务里登记 |
| 部分渠道缺美元暴露 | 已知渠道 R ≤ 1.5 → 相容；否则**无法检验** | 缺失渠道只会让上限变大，所以已知渠道不够解释时不能下"不相容"的结论 |

**"不相容"不等于"情绪"**：它只说明"不是当期盈利冲击"，候选仍包括估值倍数、长期增速预期、对手方风险、资金放大。"情绪性折价 / 溢价"标签**只能由三轨在截止日的结论给出**（第 7.4 节），不能由隐含幅度直接生成（I30）。

**用法**：结论进入证据打分（15%）、冲击分解和异常类型候选；不直接改估值，也不直接触发交易。

### 6.8 市场确认与市场指纹

声明"市场正在按这条逻辑交易"（生命周期进入"市场确认"）须同时列出：

1. 可取得的最早说法或传播时间；
2. 随后对应对象的异常响应；
3. 至少一个独立于价格的传播或交易证据（报道、卖方点评、搜索量、去重后的社交来源）；
4. 市场 / 行业参照和同期替代解释。

缺任一项时只显示"关联候选"。

**四项市场指纹**（用来排除明显不相容的解释，不保证识别唯一原因）：暴露梯度（暴露越直接反应越强）、无暴露对照（不暴露的参照表现不同）、时序相容、反证响应（官方否认后反应减弱）。

**共识度**（独立来源数、搜索量相对自身历史、卖方点评；社交未接通）只说明"资金在按这条逻辑交易"，只写市场层，不能作为基本面证据。

### 6.9 二次命中检验（新增）

用户的判断方法是："如果这个连接得到市场共识，说明它是市场和资金的共同反应。"系统用一个可执行的检验来做这件事：**同一叙事的后续信息，是否让同一批股票按预期方向再动一次。**

1. **登记预测指纹**：每个市场归因置信度 ≥ 中的候选，在建立时登记：
   - 关联实体（例如 OpenAI、Meta Muse）；
   - 预期受影响的篮子和方向（例如"OpenAI 正面消息 → 合作方篮子上涨"）；
   - 对照篮子（应不动的）。
2. **识别后续信息**：跟踪期内，全量库中出现与同一候选实体相关、且首次可得时间晚于原异常的新信息（官方回应、后续数据、新爆料），按信息 id 记录。
3. **测量响应**：该信息反应时段内，预期篮子的剩余涨跌（第 5.1 节口径）：
   - 方向符合且 ≥ 1σ，对照篮子 < 1σ → **命中**；
   - 方向相反且 ≥ 1σ → **反证**；
   - 其他 → **无响应**。
4. **结论**（只写市场层，不改估值）：

| 状态 | 条件 |
|---|---|
| 市场归因·确认 | ≥ 1 次命中且 0 次反证 |
| 市场归因·否定 | ≥ 1 次反证，或连续 2 次无响应 |
| 市场归因·未检验 | 跟踪期内没有后续信息 |

同一来源根的转载只算一次后续信息；后续信息本身由价格异常回捞得到的，必须满足"首次可得时间早于该次响应"。

这个结论同时是归因事后打标的主要依据（第 13.3 节），让"高置信组的命中率是否高于中置信组"有可计算的分母。

### 6.10 原因未明

所有候选的市场归因置信度都低 → "**已发现·原因未明**"：

- 不做任何估值变动、不触发冷静期；
- 若涉及持仓且幅度大，在系统日志提醒用户人工看一眼；
- 每天回捞一次新信息，持续 5 个交易日；
- 交易端只按规则 A 运行。

| 状态 | 候选 → 观察到 → 有支持 → 已确立 |
| 支持 / 反对证据 | 证据 id，必须有来源和时间 |

- **市场共振和叙事不能升级成经营传导**，除非有经营证据。
- 估值倍数类机制只到市场层，不能触发基本面核查。
- 种子：LLM 从 10-K 的客户、供应商、竞争、RPO 段落抽取初稿，用户按篮子批量审核；每条种子都从"候选"开始；价格共振不能把关系升到"已确立"。
- 美元暴露优先补齐关系篮子（OpenAI 合作方）和集中度高的客户关系。缺暴露的边在隐含幅度检验中给出"无法检验"，并进入补暴露任务。

### 6.12 联动事件

**新表** `linkage_events`（市场级父对象）：入口（现象 / 信息 / 弱信号）和首次发现时间；说法列表；传导链（引用 `linkage_relations`）；竞争解释（各自证据得分、隐含幅度、二次命中状态）；影响范围（ticker、方向、机制、暴露类别、加入 / 退出理由）；五维状态及历史；生命周期；跟踪清单；关联异常。

**基本面结论只来自规则**：联动事件不会直接改任何标的的基本面结论；一只标的的基本面是否变化，只由基本面轨道按第 7.3 节的"已验证"门槛判断，财报和一致预期仍各自按 M2、M5 的规则更新。

**链条强度不高于最弱环节**：市场确认不替代消息真实性；消息真实不替代对具体公司的盈利传导；最初用于发现异常的价格变化，不能再次作为经营证据。

**五个状态维度**（不压缩成一个分）：

| 维度 | 状态值 | 改变依据 |
|---|---|---|
| 消息真实性 | 未核实 / 部分核实 / 核实 / 修订 / 证伪 | 原始来源、披露、可信反证 |
| 叙事传播 | 初现 / 扩散 / 稳定 / 衰减 / 重新活跃 | 独立来源数、搜索、榜单 |
| 市场关联 | 待观察 / 共振 / 部分符合 / 分化 / 脱钩；二次命中状态 | 时间、相对表现、参照、指纹、二次命中 |
| 经营传导 | 待验证 / 局部支持 / 支持 / 冲突 / 失效 | 业务暴露、预期修订、一级信源、产业数据 |
| 交易状态 | 风险释放 / 初步修复 / 持续确认 / 修复失效 | 价格结构、量能 |

**生命周期**：

| 阶段 | 进入条件 | 系统里发生什么 | 覆盖层 |
|---|---|---|---|
| 已发现 | 异常、可信事件或弱信号触发 | 无 | 无 |
| 假设中 | 最优候选的证据得分 ≥ 0.5 | 生成市场假设（候选） | 无 |
| 市场确认 | 满足第 6.8 节四项 | 市场归因写入处置卡 | 直接暴露、机制非估值倍数类的标的：**冷静期** |
| 基本面核查中 | 机制为供给 / 需求 / 竞争 / 客户融资类 | 跟踪清单、约束核查表；传闻内容只计入叙事维度 | 冷静期持续 |
| 已验证·有影响 | 达到第 7.3 节门槛 | 基本面轨道为"支持"，背离标签生效 | 暂停新开，直到下次财报进入四本账；X1 影子信号 |
| 已衰减·无影响 | 截止日证据不足 | 假设关闭；三轨给出标签 | 解除 |
| 已证伪 | 官方否认、事实矛盾 | 假设关闭；下调该信源根的可信度记录 | 解除 |

传闻被证伪后，其内容退出经营依据，但已发生的价格冲击和传播记录保留。

## 7. 模块一 · 持续跟踪

### 7.1 三条轨道、三个时钟

| 轨道 | 指标 | 频率 | 状态 | 影响什么 |
|---|---|---|---|---|
| **情绪** | 独立来源数、搜索热度、榜单名次持续性、语气 | 每日 | 初现 → 扩散 → 稳定 → 衰减 → 重新活跃 | 冷静期、标签；**不改估值** |
| **资金** | 篮子剩余累计、**回吐比例**（5 / 20 日回吐初始冲击的百分比）、相对强弱、成交量相对均量、期权隐含波动率和偏度、二次命中 | 每日 | 冲击中 → 消化中 → 已消化 / 延续 → 反转 | 时机账（规则 A 已有）、标签；**不改估值** |
| **基本面** | 一致预期衍生指标（F2）、分部盈利（F1）、公司表态、8-K、关键经营数据（应用 DAU 代理、资本开支指引、合约价）、下一份财报 | 每周 + 事件触发 | 待验证 → 局部支持 → 支持 / 冲突 → 失效 | **唯一能改估值的轨道**（通过一致预期和财报） |

### 7.2 跟踪清单、截止与重新激活

- 每段关键连接生成可验证的问题、所需指标、来源、预计验证窗口、截止日。"有任务"不等于"有证据"。
- 截止日取：官方发布日（下次财报）、采购 / 交付周期、最长 20 个交易日，三者先到者。
- **到期必须三选一**：支持 → 更新关系；反证 → 失效；仍未知 → 转"条件风险"（保留标签，解除冷静期，但该路径不能作为加仓依据）。不能自动续期。
- **重新激活**只能由重大新原始证据、新的异常范围或接近经营兑现期触发；普通转载不能重启时钟。
- 研究资源优先级：持仓风险 > 近期候选 > 可改变驱动因子的关键环节 > 重大未知异常。

### 7.3 "已验证"门槛与经营约束核查

满足其一即"已验证"：

| 证据 | 门槛 |
|---|---|
| 公司一级信源 | 8-K 指引变更、财报电话会定量表述 |
| 预期修订 | 覆盖分析师 ≥ 30% 同向修订，且当年 EPS 共识较事件前变化 ≥ 3% |
| 产业数据 | ≥ 2 个独立来源根的二 / 三级信源定量数据同向 |
| 竞争对手一级信源 | 经图谱映射到本公司驱动因子 |

**不能作为证据**：股价、资金流、共识度、社交热度、单一四级信源、已证伪信号、同源转载、二次命中结论（它只证明市场在交易这个逻辑）。

供给或需求类事件进入核查后，跟踪清单必须包含**约束核查表**（以东芝扩产为例）：新增供给规模占需求增量的比例、投产时间与良率爬坡、产品代际、需求吸收能力、订单 vs 可交付、价格传导。结论只有四种：可计算且冲击有限 / 可计算且冲击实质 / 约束不清但有上下界（保持核查中）/ 关键约束冲突（转条件风险）。

### 7.4 背离标签

| 标签 | 价格 | 一致预期 | 基本面轨道 | 联动事件 | 含义 |
|---|---|---|---|---|---|
| 情绪性折价 | 大跌 | 未下修 | 未变 | 已衰减 / 已证伪 / 估值倍数类 | 候选买入观察 |
| 合理重定价 | 大跌 | 显著下修，或 8-K 下调指引 | 支持（不利方向） | 已验证·有影响 | 不买；持仓按规则 |
| 滞后风险 | 小跌或未跌 | 显著下修 | 支持（不利方向） | 已验证·有影响 | 持仓风险提示 |
| 情绪性溢价 | 大涨 | 未上修 | 未变 | 估值倍数类 | 不追 |
| 基本面驱动上涨 | 大涨 | 显著上修 | 支持（有利方向） | 已验证（正向） | 正常走规则门槛 |

初始阈值："未下修" = 当年 EPS 共识较 7 天前 > −2% 且下修家数 ≤ 上修家数；"显著下修" = ≤ −3%，或近 7 天下修家数 ≥ 覆盖家数 30%。一致预期快照满 90 天后重新标定。

标签只在截止日或"已验证"时由规则给出，第一阶段**只展示、只进影子信号**。

### 7.5 三轨组合的含义

| 情绪 | 资金 | 基本面 | 解读 |
|---|---|---|---|
| 衰减 | 已回吐 > 50% | 未变 | 冲击已消化 |
| 衰减 | 未回吐 | 未变 | 价格新均衡，可能有未被看到的信息 → 回捞 + 提高研究优先级 |
| 扩散 | 延续 | 开始修订 | 基本面开始兑现 → 估值随预期移动 |
| 衰减 | 延续 | 冲突 | 价格和基本面背离 → 背离标签 |

## 8. 模块二 · 估值区间 v1.1

### 8.1 定位与终局

**回答的问题**：按固定方法，这只股票现在大概值多少，当前价格处在什么位置。

- 输出悲观 / 中性 / 乐观三档每股价值、位置 p；成长类另给"现价隐含增速 vs 一致预期增速"。
- 不使用 LLM 假设、不使用研究观点、不随新闻和价格调整。
- **第一阶段不参与任何交易决策**（H1–H7）。

**关于"沿用 Muse 打分，还是另建估值"的结论**：

| | Muse 估值账（打分） | 估值区间 |
|---|---|---|
| 起点 | 现价 | 财报 + 一致预期 + 本股倍数历史 |
| 回答 | "按现价，倍数在固定刻度上算便宜吗" | "价格离价值有多远、还有多少空间" |
| 优点 | 机械、可回测，有 v18 的结果支撑 | 能回答空间，能用于仓位和减仓 |
| 缺点 | 刻度跨行业通用；只用 TTM（周期股在景气顶点看起来最便宜）；只给分数不给空间 | 一致预期没有历史，前瞻版不能回测 |

两者都不单独采用。**终局**：

1. **规则 A 管"能不能买"**：红线、四本账、分层门槛不变。
2. **估值区间管"买多少、拿多久、何时减"**。
3. **B1（成长调整估值分，第 10.3 节）是过渡**：在估值区间修好成长类、影子达标之前，用 B1 解决"高成长股被绝对倍数挡死"。V1 采纳后 B1 退役。
4. **进入交易的顺序：先收紧、后放宽**（第 8.8 节）。收紧类风险低，TTM 口径可以 PIT 回放；放宽类（便宜时多买）放在后面。
5. **价格不改价值**：区间只随财报、一致预期、倍数历史变化，不随股价变化。这是防止"价格涨了就把估值往上调"的追涨机制。

### 8.2 类型判定

每次新财报生效时判定；类型变化需要**连续两期**满足才切换；允许人工指定，留痕并注明理由。

| 顺序 | 类型 | 条件 | 预计归类（示意） |
|---|---|---|---|
| 1 | 金融 | 银行、保险、券商（SIC 代码）；V、MA 不算 | JPM |
| 2 | 未盈利成长 | `ni_ttm` ≤ 0（或 `fcf_ttm` ≤ 0 且营业利润率 < 5%），且 `rev_growth` ≥ 15% | CRWV、BE、GAAP 亏损的网络安全公司 |
| 2b | 困境（不估） | 未盈利且 `rev_growth` < 15% | 页面显示"不估值：亏损且无增长" |
| 3 | 周期 | 周期子行业（存储、半导体设备、能源、机械），或近 10 年至少 2 年 EPS 同比下滑超过 50% 且毛利率波动 ≥ 15 个百分点 | MU、SKHY、WDC、STX、SNDK、AMAT、LRCX、KLAC、ASML、XOM、CVX、CAT |
| 4 | 成长 | 3 年营收复合增速 ≥ 15%，且（一致预期次年 EPS 增速 ≥ 15% 或 `rev_growth` ≥ 15%） | NVDA、AVGO、AMD、MRVL、PLTR、META、NFLX、ANET、VRT、GEV、LLY、NOW、COHR、LITE、CEG、PANW、CRWD 等 |
| 5 | 稳定 | 其余 | AAPL、MSFT、COST、WMT、HD、JNJ、V、MA、ETN、QCOM、DELL、FTNT 等 |

### 8.3 公共输入

| 输入 | 来源 | 说明 |
|---|---|---|
| TTM 财务 | 第 9.2 节财报字段 | 与交易共用采集，但估值模块**单独读原始数据**，不读交易模块的计算结果 |
| 一致预期 | `eps_ntm`（当年和次年 EPS 按剩余月份加权）、次年 EPS 增速、未来 12 个月营收 | 缺失时降级 |
| 本股倍数历史 | 过去 10 年每日 TTM PE（只取 EPS > 0 的日子），去掉最高和最低各 2.5% 后取分位 | 不足 5 年用板块篮子中位数 |
| 年度序列 | 近 10 个财年营收、净利润率、EPS | 周期类用 |
| 股本 | 稀释股本 | 未盈利成长类悲观档加 5% 稀释 |

### 8.4 五种算法

记号：`E` = 定价用 EPS；`P25 / P50 / P75 / P90` = 本股 10 年 TTM PE 分位；`clamp(x, a, b)` = 把 x 限制在 [a, b]。

**稳定类**

- `E = 0.5 × eps_ttm + 0.5 × eps_ntm`（没有一致预期时 `E = eps_ttm`）。
- PE 法：悲观 = `E × 0.90 × P25`；中性 = `E × P50`；乐观 = `E × 1.05 × P75`。
- 自由现金流法：每股自由现金流 ÷ 要求收益率（悲观 6.0%、中性 4.5%、乐观 3.5%）。
- 结果 = 0.7 × PE 法 + 0.3 × 自由现金流法（每档分别加权）。两法中性值相差超过 40% → 置信度降一档。

**成长类（v1.1 改为三年衰减）**

- 基础增速 `g` = min（一致预期次年 EPS 增速，3 年营收复合增速，**60%**）；没有一致预期时用 min（TTM EPS 增速，3 年营收复合增速，60%）。百分数记法，例如 35% 记 35。
- 三年后的前瞻 EPS：`EPS₃ = eps_ntm × (1 + g) × (1 + 0.75g) × (1 + 0.5g)`（增速逐年衰减）。
- 退出 PE：`clamp(12 + 0.6 × 0.5g, 15, 上限)`，且不超过本股 `P90`。`0.5g` 是第三年的增速。
- 价值 = `EPS₃ × 退出 PE ÷ 1.10³`（按 10% 折回今天）。

| 档 | 增速 | 退出 PE 上限 |
|---|---|---|
| 悲观 | `0.5 × g` | 30 |
| 中性 | `g` | 35 |
| 乐观 | `min(1.25 × g, 75)` | 40 |

- **现价隐含增速**：令中性公式的价值等于现价，反解 g（不受 60% 上限约束，超出时注明"超出 g 上限"）。
- 为什么改：v1 的一年期公式让乐观值最多约为 `eps_ntm × 48`。TTM PE 上百的高成长股（AMD 173、LITE 613）只要次年 EPS 没有翻几倍，就必然"高于乐观"，估值参考对 AI 链高成长股失去意义。三年衰减模型对增速 35% 左右的公司结果与 v1 基本一致（见 8.7 的 NVDA 算例），只放宽了真正高增速公司的上限。

**周期类**（归一化盈利，避免"景气高点 PE 最低"的陷阱）

- 常态净利率 `m*` = 近 10 个财年净利润率中位数（至少 7 年；不足用板块参数，置信度降一档）。
- 常态营收 `R*` = 近 3 个财年营收均值；10 年营收复合增速 > 8% 时再乘 `(1 + 复合增速)`。
- 常态 EPS = `m* × R* ÷ 稀释股本`。
- 悲观 = 常态 EPS × 0.85 × PE 低档；中性 = 常态 EPS × PE 中档；乐观 = 常态 EPS × 1.15 × PE 高档。

| 周期子行业 | PE 低 / 中 / 高 |
|---|---|
| 存储（HDD、NAND、DRAM） | 9 / 13 / 17 |
| 半导体设备 | 14 / 19 / 25 |
| 能源 | 9 / 12 / 15 |
| 机械 | 12 / 16 / 20 |

- 附加展示"景气位置"：TTM 净利率相对常态净利率的偏离。

**未盈利成长类**

- 未来 12 个月营收 = 一致预期；没有时用 `rev_ttm × (1 + min(rev_growth, 60%))`。
- EV / 营收倍数按增速分档，再乘 `clamp(毛利率 ÷ 70%, 0.5, 1.2)`：

| 营收增速 | 悲观 / 中性 / 乐观 |
|---|---|
| ≥ 40% | 6 / 10 / 15 |
| 25%–40% | 4 / 7 / 10 |
| 15%–25% | 2.5 / 4 / 6 |

- 股权价值 = EV − 净负债；每股价值按稀释股本，悲观档股本 × 1.05。
- 现金跑道 = 现金 ÷ |TTM 自由现金流|；不足 1.5 年时悲观档 × 0.7，置信度为低。
- 这一类置信度最高为"中"。

**金融类**（银行）

- 合理有形市净率 = `(ROTE − g) ÷ (r − g)`，`g` = 4%；`r` 中性和乐观 10%、悲观 11%；ROTE 用近 5 年均值，悲观 −3 个百分点、乐观 +2 个百分点；限制在 [0.6, 3.0]。
- 每股价值 = 每股有形净资产 × 合理有形市净率。

### 8.5 公共规则与展示口径

- **顺序约束**：悲观 ≤ 中性 ≤ 乐观；不满足时升序重排并标"方法异常"待复核。
- **位置** `p = (价格 − 悲观) ÷ (乐观 − 悲观)`。

| p | 显示 |
|---|---|
| < 0 | 低于悲观 |
| 0–0.35 | 偏低 |
| 0.35–0.65 | 中性 |
| 0.65–1.0 | 偏高 |
| > 1.0 | 高于乐观 |

- **成长类的主指标是隐含增速差** `Δg = 隐含增速 − g`，p 作为辅助一起显示：

| Δg | 显示 |
|---|---|
| ≤ −10 个百分点 | 现价隐含增速低于一致预期 |
| −10 至 +10 | 与一致预期相当 |
| +10 至 +25 | 现价隐含增速高于一致预期 |
| > +25 | 现价隐含增速远高于一致预期 |

- **估值不用当前价**：三档价值只由财报、一致预期、倍数历史决定；价格只用于计算 p 和隐含增速。

### 8.6 更新触发、稳定性与置信度

| 触发 | 更新什么 |
|---|---|
| 每天收盘 | 只更新 p、隐含增速 |
| 新 10-Q / 10-K 生效（按申报日） | 全部重算，包括类型判定 |
| `eps_ntm` 较上次使用值变化 > 3% | 重算 `E`、`g` 相关部分 |
| 每月第一个交易日 | 重算倍数历史分位 |
| 人工改类型 | 重算，留痕 |

**不触发**：新闻、价格异常、资金面变化、LLM 判断。

稳定性：没有新财报时，单次重算中性值变化超过 25% → 新值标"待复核"，新旧同时显示，复核后才替换。每次变化做**变化分解**：盈利变化、倍数变化、类型 / 方法变化、一致预期变化各贡献多少美元。一致预期源失效时自动退回 TTM 口径，置信度降一档，页面标"一致预期缺失"。

**置信度**从"高"开始，每条降一档：倍数历史不足 5 年；没有一致预期；稳定类两法分歧超过 40%；最近两期类型判定不一致；外国申报人只有年度数据。未盈利成长类最高为"中"。

### 8.7 算例（示意数字）

**WDC，周期类**：常态净利率 12%，常态营收 100 亿美元，稀释股本 3.5 亿股 → 常态 EPS 3.43。悲观 3.43 × 0.85 × 9 = 26.2；中性 3.43 × 13 = 44.6；乐观 3.43 × 1.15 × 17 = 67.1。现价 70 → p = 1.07"高于乐观"；景气位置：TTM 净利率 20% vs 常态 12%，景气高位。东芝扩产后股价跌到 55：**区间不动**，p 降到 0.70，页面写"价格回落，估值区间未变：东芝扩产尚未体现在财报或一致预期中"。

**NVDA，成长类**：`eps_ntm` = 6.00；一致预期次年增速 35%，3 年营收复合增速 80% → g = 35。

| 档 | 增速 | EPS₃ | 退出 PE | 价值 |
|---|---|---|---|---|
| 悲观 | 17.5 | 8.67 | 17.25 | 112.4 |
| 中性 | 35 | 12.02 | 22.5 | 203.1 |
| 乐观 | 43.75 | 13.96 | 25.1 | 263.5 |

现价 180 → p = 0.45"中性"；现价隐含增速 31%，Δg = −4，"与一致预期相当"。（v1 一年期公式的结果为 120 / 203 / 250，中性值基本一致。）

**AMD，成长类**（示意，`eps_ntm` 假设为 7.00）：一致预期次年增速和 3 年营收复合增速都超过 60%（假设）→ g = 60。

| 档 | 增速 | EPS₃ | 退出 PE | 价值 |
|---|---|---|---|---|
| 悲观 | 30 | 12.82 | 21.0 | 202.3 |
| 中性 | 60 | 21.11 | 30.0 | 475.9 |
| 乐观 | 75 | 26.32 | 34.5 | 682.2 |

现价 608 → p = 0.85"偏高"；隐含增速 70%（超出 g 上限），Δg = +10，"现价隐含增速高于一致预期"。按 v1 一年期公式，同样输入的乐观值约 334，p 远大于 1。

### 8.8 进入交易的路线

**建议**：估值进仓位，分三步走，每一步都比上一步离订单更近。

1. **第一阶段：并排看、影子算，不动订单**（第 8.12 节）。需求里"仓位要和估值、现价一起看"和"这一版估值不能改仓位管理"并不矛盾：前者靠展示满足，后者靠解耦约束保证。每天把"规则 A 实际给的仓位"和"如果估值参与会给的仓位"并排记录，攒前向样本。
2. **第二阶段：先上收紧类**（V-T1 禁止追价、V-T2 高位降额）。收紧规则出错时，代价是少赚；放宽规则出错时，代价是多亏。估值方法刚改版（v1.1），一致预期还没有历史，先让它只做"刹车"。
3. **之后才让估值放大仓位**（V1 → V2 → V3）。前提是估值区间在历史上（V-A6）和赢家案例上（V-A7）站得住，并且收紧类规则在前向运行里没有系统性错杀。

不建议的做法：一开始就按 p 定仓位（旧版第 19 节的公式）。估值区间里最不确定的正是高成长股，而它们恰好是规则 A 收益的主要来源；一旦估值偏保守，这个公式会同时压低这批股票的仓位，等于把估值的误差直接放大成仓位的误差。

全部先影子运行（H5），按 H6 的条件、经用户批准、走变更提案后才生效。

| 阶段 | 规则 | 性质 | 内容 | 启用条件 |
|---|---|---|---|---|
| 0 | 估值—仓位对照 | 只展示 + 影子 | 第 8.12 节 | 第一阶段交付 |
| 1 | **V-T1 禁止追价** | 收紧 | 置信度不是低，且（p ≥ 1.3，或成长类 Δg > +25）→ 不新开、不加仓 | 第二阶段：历史评估（V-A6、V-A7）+ 一个财报季影子 + 批准 |
| 1 | **V-T2 高位降额** | 收紧 | 置信度不是低，且 p ≥ 1.0 → 新开和加仓的单票上限 × 0.5 | 同上 |
| 2 | V1 估值账口径 | 替换 | 估值账改为 p 的函数：p ≤ 0 → 95、0.5 → 70、1.0 → 40、≥ 1.3 → 10；成长类用 Δg 的同构曲线；B1 退役 | 第二阶段回测 + 两个财报季影子 + 批准 |
| 3 | V2 仓位 | 放宽 / 改仓位 | 首笔和加仓 × 估值系数（p ≤ 0.5 → 1.0；0.5–0.8 → 0.7；0.8–1.0 → 0.4；> 1.0 → 0）；"p < 0 但悲观值在下修"→ 0 | V1 通过后 |
| 4 | V3 按价值减仓 | 改卖出 | p ≥ 1.2 减 1/3，同一估值版本只触发一次；价值上修后重算 | V2 通过后 |

一次只上一条；前一条不过关，不做下一条。V-A7 是硬前提：**任何估值规则如果在历史上会挡掉规则 A 已证明的赢家**（AMD 2026-01-12 的 201 美元建仓），必须在影子报告里明确说明代价。

**目的**：让用户在同一个地方看到"规则 A 给了多少仓位"和"按估值看，这个仓位合不合适"，同时不让估值改动任何订单。

**每只持仓和候选一行**（`valuation_v1` schema，交易模块不可读）：

| 字段 | 定义 |
|---|---|

## 9. 模块二 · 规则 A（Muse v18 规格）

本节把 Muse v18 的全部规则写成与语言无关的规格。重写时**只认这一节**，不参考 Muse 原代码的结构。规格编号 `M-xx`，便于在代码和测试里引用。

### 9.1 总原则

- **M-01 机械化**：从当前价格出发，按打分和规则决定能不能买、买多少、何时卖；**不设目标价**。
- **M-02 PIT**：任何一天的计算只用当天收盘时已经公开的数据。财报按 SEC **申报日**（`filed`）可见，Form 4 按申报日可见。
- **M-03 时序**：信号在收盘后生成，**次日开盘价**成交；同一天先执行卖单、后执行买单。
- **M-04 成本**：每笔成交 0.1%（买入加价、卖出减价）。
- **M-05 最小订单**：成交金额低于当时权益的 0.5% 不下单。
- **M-06 研究性质**：纸面组合，不接券商下单（沿用 Muse 文档的约束：网页只读、不下单）。

### 9.2 输入数据

**日线技术字段**（每只股票每天计算一次）：

| 字段 | 定义 |
|---|---|
| `price` | 收盘价 |
| `price_vs_ma200` | 收盘价 / 200 日均线 − 1，单位 % |
| `ma50_vs_ma200` | 50 日均线 / 200 日均线 − 1，% |
| `ma200_slope20` | 200 日均线 / 20 个交易日前的 200 日均线 − 1，% |
| `mom3`、`mom6` | 相对 63、126 个交易日前的涨跌幅，% |
| `rsi` | 14 日 RSI |
| `dev50` | 收盘价 / 50 日均线 − 1，% |
| `vol_ratio` | 20 日平均成交量 / 60 日平均成交量 |
| `up_share` | 近 60 日"收盘 ≥ 开盘"那些天的成交量占比，% |
| `vol20` | 20 日收益率标准差 × √252 × 100 |
| `vol60` | 60 日收益率标准差 × √252 × 100（只用于分层） |

| `rev_accel_pp` | `rev_q_yoy` − 上一季度的 `rev_q_yoy`，百分点 |
| `eps_ttm` | 最近 4 个季度稀释 EPS 之和 |

| `gross_margin` | TTM 毛利 / TTM 营收，% |
| `gross_margin_change_pp` | 本期 TTM 毛利率 − 一年前 TTM 毛利率，百分点 |
| `fcf_ttm` | TTM 经营现金流 − TTM 资本开支 |

| `fcf_conversion` | `fcf_ttm` / `ni_ttm` |
| `roe` | `ni_ttm` / 股东权益，% |

**每日按价格派生**：`pe = price / eps_ttm`（EPS > 0）；`mktcap = shares × price`；`ps = mktcap / rev_ttm`；`fcf_yield = fcf_ttm / mktcap × 100`；`peg = pe / rev_growth`（增速 > 0）。

**采集要求**：原 Muse 采集有标签遗漏、第四财季推算缺失、companyfacts 滞后等缺陷，重写时必须按第 4.5 节的 D1–D7 实现（复现 v18 时先关闭，单独报告影响）。

**数据质量标记**：

- **M-07 财报过期**：最近营收期间的结束日距当天超过 180 天 → 质量、成长、估值三本账全部置空（不能入场，见 M-30）。
- **M-08 拆股疑似**：（PE < 5 且 PS < 2）或（PS < 3 且毛利率 > 60%）→ 估值账置空，只用其余三本账。

**其他输入**：SPY 日线（黑天鹅）、VIX 日线（恐慌闸门）、Form 4 公开市场买入（代码 P，区分高管 / 其他内部人）。

| M-16 | `current_ratio` < 0.8 | 流动性偏紧 | 只观察（**不**算逻辑死亡；保险、公用事业结构性低于 1） |
| M-17 | PE > 80 且（`rev_growth` < 15 或 `rev_accel_pp` < −10） | 高估值与增长不匹配 | 等价格 |
| M-18 | `rsi` > 80 且 `dev50` > 15 | 短线过热 | 不追高 |

"排除"阻止入场；"不追高"阻止新开仓和加仓；"只观察"和"等价格"在 v18 里**只是标签，不阻止入场**（见 9.13 E5；A+ 的 B7 提案让"等价格"生效）。

### 9.6 分层

- **M-20 分层只在新财报状态生效那天重估**（以及股票首次出现时），平时不变，避免层级天天跳。波动用 `vol60`（缺失时用 `vol20`）。
- **M-21 进攻层**：`vol60` > 55，或未盈利（`ni_ttm` < 0 且 `fcf_ttm` < 0），或（`rev_growth` > 35 且估值账 < 45）。
- **M-22 防守层**：`vol60` < 30 且 `fcf_ttm` > 0 且 `fcf_margin` > 5 且质量 ≥ 70 且成长 ≥ 45 且（`rev_growth` ≥ 0 或为空）。
- **M-23 普通层**：其余。质量或成长为空时不分层（不能交易）。

| 参数 | 防守 | 普通 | 进攻 |
|---|---|---|---|
| 层预算（占总权益，只限制买入） | 30% | 30% | 40% |
| 层预算缓冲 | ×1.25 | ×1.25 | ×1.25 |
| 单票目标上限 `cap` | 12% | 12% | 8% |
| 默认首笔比例 | 50% | 40% | 30% |
| 最多持有只数 | 4 | 6 | 6 |
| 全组合最多持有只数 | 12 | 12 | 12 |

- **M-24 买入额度**：某层可买上限 = 层预算 × 1.25 × 权益。普通层和防守层在全组合投入比例 < 85% 时，可以额外借用进攻层未用额度的 75%。层内市值涨过上限**不强制减仓**，只是不再加新钱。

### 9.7 资格指标

**M-25 成长确定性**（高 / 中 / 低），按点数累加：

- 成长账 ≥ 85 记 2 点，≥ 72 记 1 点；
- `rev_growth` ≥ 30 记 2 点，≥ 18 记 1 点；
- `rev_accel_pp` ≥ 3 记 +1，≤ −8 记 −1；
- `eps_growth` ≥ 20 记 +1，< 0 记 −1；
- 总点数 ≥ 4 为高，≥ 2 为中，其余为低。

**M-26 基本面持有资格分**（0–100，只看基本面趋势和现金质量，不看价格；字段缺失时给括号里的保底分）：

| 项 | 满分 | 分档 |
|---|---|---|
| 季度营收同比 | 15 | ≥ 20→15，≥ 10→12，≥ 0→8，≥ −5→4，否则 0（缺失 8） |
| 营收加速度 | 15 | ≥ 0→15，≥ −10→10，≥ −20→5，否则 0（缺失 0） |
| 毛利率变化 | 15 | ≥ 0→15，≥ −3→10，≥ −6→5，否则 0（缺失 8） |
| 现金流 / 净利润 | 20 | ≥ 1→20，≥ 0.5→15，≥ 0→8，否则 0（缺失 8） |
| 净负债 / 自由现金流 | 15 | ≤ 0→15，≤ 3→12，≤ 5→8，否则 0（缺失 8） |
| 流动比率 | 10 | ≥ 1.5→10，≥ 1→7，≥ 0.8→4，否则 0（缺失 5） |

- `hold_ok`：资格分 ≥ 55。
- `fund_bad`：资格分 < 40，或（季度营收同比 < 0 且毛利率变化 < 0 且现金流 / 净利润 < 0.3 或缺失）。

**M-27 现金跑道**：`fcf_ttm` ≥ 0（或缺失）视为够；否则要求 `cash` ≥ 1.0 × |`fcf_ttm`|。

### 9.8 入场

**M-30 入场门槛**（按层，四本账全部达到才算过线）：

| 账本 | 防守 | 普通 | 进攻 |
|---|---|---|---|
| 公司质量 | 70 | 60 | 50 |
| 成长与预期 | 45 | 55 | 70 |
| 估值 | 50 | 45 | 30 |
| 入场时机 | 50 | 55 | 50 |

- **M-31 进攻层估值修正**：进攻层且成长 ≥ 70 时，用修正后的估值分比较门槛：`min(65, 估值 + max(0, min(20, (rev_growth − 15) / 3)))`。只用于入场判断，不改原始估值账。
- **M-32 进攻层烧钱保护**：进攻层且 `fcf_ttm` < 0 时，额外要求 `rev_growth` ≥ 30 且 `cash` ≥ 1.5 × |`fcf_ttm`|。
- **M-33 `entry_pass`** = 门槛过线 且 M-32 满足 且 没有"排除"类红线。
- 连续过线天数 `consec_pass` 每天累计，不过线归零。

**M-34 新开仓候选**（每天收盘后）：

1. 主候选：`entry_pass`，没有"不追高"，资格分 ≥ 45，有分层，未持有，当天没有挂单，距上次清仓 ≥ 10 个交易日。按排名分从高到低排序。
2. 回补候选：上次是"价格型"退出（见 9.10）；`hold_ok`；普通或进攻层；`dev50` > 0；时机 ≥ 50；估值 ≥ 该层门槛 − 10；距上次清仓 ≥ 10 个交易日。排序分 = 排名分 − 3。
3. **进攻层候选排在最前**，然后是其他层；各组内按排序分降序。
4. 逐个检查：该层只数未满、全组合（持仓 + 当天新开仓挂单）< 12 只（**观察波段仓不计入这 12 只**，它另有最多 3 只的上限，见 M-60 起；2026-10-16 更正，见 M4 Q-M4-11，与 v18 源码一致）；防守层的主候选还要求资格分 ≥ 55；组合回撤刹车（M-62）生效时只允许防守层。

**M-35 首笔比例**：

- 基础 = 该层默认首笔比例；
- 成长确定性高：`min(0.75, 基础 + 0.20)`；中：`min(0.65, 基础 + 0.08)`；低：`max(0.20, 基础 − 0.08)`；
- 回补候选：× 0.8；
- 全组合投入比例 < 55% 且确定性不是低：`min(0.80, 比例 + 0.10)`；
- **M-36 内部人加成**（只对主候选）：信号日前 90 个自然日内有 Form 4 公开市场买入（按申报日），高管 × 1.35、其他内部人 × 1.20，上限 0.80；
- 首笔金额 = 首笔比例 × 该层 `cap` × 权益：额度检查用信号日收盘权益（超出该层买入额度 M-24，含当天已计划的买入，则跳过），实际成交金额按次日开盘时的权益计算；
- **M-37 追高减半**：`dev50` > 15 时，这一笔的金额减半。

### 9.9 加仓（优先于新开仓）

**M-40 分级加仓**，对已持有的股票，要求 `entry_pass`、有分层、当天没卖、没有"不追高"、非 `fund_bad`、距上次卖出 ≥ 10 个交易日、该层还有买入额度；组合回撤刹车生效时只允许防守层。

- 已投比例 = 持仓市值占"该层 `cap` × 权益"的比例（按成交时累计记录）。
- **确认加仓**：已投比例 < 首笔比例 + 0.30 时，满足任一条件 → 加到 `min(0.85, 首笔比例 + 0.30)`：
  - 持有天数 ≥ N 且连续过线天数 ≥ N，其中 N = 3（确定性高或全组合投入 < 60%）否则 5；
  - 回踩：|`dev50`| ≤ 3 且 `price_vs_ma200` > 0。
- **确认补满**：已投比例 < 1 时，满足任一条件 → 加到 1.0：
  - 入场后出现了新一期财报；
  - 持有 ≥ 15 天且连续过线 ≥ 10 天。
- 加仓金额 = 目标比例 × `cap` × 开盘时权益 − 当前市值；同样适用 M-37 追高减半。

### 9.10 卖出（按优先级，命中一条后当天不再检查后面的）

退出类型：基本面退出、价格型退出。只影响回补资格（M-34）。

| 编号 | 规则 | 条件 | 动作 |
|---|---|---|---|
| M-50 | 逻辑死亡 | 命中 M-14 或 M-15；或质量 < 50（防守层）/ < 45（其他）；或成长 < 35（防守层）/ < 40（其他）；进攻层另加 `rev_growth` < 0 或现金跑道不够；或 `fund_bad` | 全部卖出（基本面退出） |
| M-51 | 进攻层灾难止损 | 进攻层，价格 ≤ 持仓期最高收盘价 × 0.60，且 `price_vs_ma200` < 0 | 全部卖出（价格型） |
| M-52 | 纯波段仓规则 | 见 9.11 | —— |
| M-53 | 核心仓上的波段仓止盈 | 持有波段股数 > 0，`dev50` ≥ 阈值；阈值进攻层 = `clamp(0.40 × vol20, 10, 18)`，其他 = `clamp(0.32 × vol20, 8, 14)` | 卖出波段股数，核心仓不动 |
| M-54 | 进攻层翻倍锁利 | 进攻层，价格 ≥ 2 × 持仓均价，且（`dev50` < 3 或时机 < 55），距上次卖出 ≥ 20 天，当前不在减仓阶段 | 卖 25% |
| M-55 | 破位减仓 | 见下表；持有 ≥ 10 天；减仓阶段 < 2；**非恐慌日** | 按下表比例卖出，阶段置 2 |
| M-56 | 警戒减仓（只限普通层） | 入场后出现新财报，且（质量 < 55 或成长 < 50），且 `dev50` < 0；阶段 = 0；**非恐慌日** | 卖 25%，阶段置 1 |
| M-57 | 解除减仓阶段 | 阶段 > 0 时，不再警戒且 `price_vs_ma200` > 0 且 `entry_pass`，连续满足 K 天（防守 / 进攻 5 天，普通 3 天） | 阶段归 0 |

**破位条件**（M-55）：

| 层 | 破位条件 | 减仓比例 |
|---|---|---|
| 防守 | 连续 10 天收在 200 日线下 | 1/3 |
| 普通 | 命中趋势破位红线，或连续 3 天在 200 日线下，或时机 < 35 连续 3 天 | 1/2 |
| 进攻 | 连续 7 天在 200 日线下，或时机 < 30 连续 5 天 | 1/3 |

**M-59 只观察不卖**：分数回落、仓位失衡、层市值超预算，都**不是**卖出理由。只有逻辑死亡，或"新财报走弱 + 趋势跌破"才减仓。

**M-58 冷却期**：核心仓的全部或部分卖出（不含波段卖出）后 10 个交易日内，不对同一只股票做普通新开、回补或核心加仓；波段买卖按各自的间隔规则（2026-10-16 更正，见 M4 Q-M4-8，与 v18 源码和 90 笔标准答案一致）。

### 9.11 波段层

- **M-60 弱势带**：回撤阈值 `dip_dd = clamp(0.55 × vol20, 10, 22)`；偏离阈值 `dip_dev = −clamp(0.18 × vol20, 3, 7)`。进入弱势带 = `drawdown252` ≤ −`dip_dd` 且 `dev50` ≤ `dip_dev`。
- **核心仓波段买入**：已持有、`hold_ok`、非 `fund_bad`、阶段 = 0、波段笔数 < 2、距上次波段 ≥ 10 天、进入弱势带且 `price_vs_ma200` > −8；金额 = 0.20 × `cap` × 权益，不能超过单票 `cap` 和该层额度。止盈按 M-53。
- **观察名单波段（未持仓）**：
  - 防守 / 普通层；进攻层另要求资格分 ≥ 65、`vol20` ≤ 60、现金跑道够；
  - 资格分 ≥ 60；`rev_accel_pp` ≥ −10（加速度明显恶化不接）；同时最多 3 个观察波段仓；距上次清仓 ≥ 10 天；
  - 进入弱势带，并且**已止跌**：5 日涨跌 ≥ −2% 且价格 ≥ 10 日最低价 × 1.03；
  - 深跌（`drawdown252` ≤ −35）需要**两次确认**：第一次止跌只记录日期和价格；5–15 天内再次满足、且价格不低于第一次的 97%，才买；
  - 金额：普通 / 防守 4%，深跌（`price_vs_ma200` < −8）2.5%；进攻层 3%，深跌 2%（占权益）；单票上限：进攻 6%、其他 8%；
  - 站回 50 日线后（距上次波段 ≥ 5 天）补第二笔到单票上限；
  - 止盈：`dev50` ≥ `clamp(0.32 × vol20, 8, 14)` 全部卖出；止损：价格 ≤ 买入均价 × 0.82 全部卖出（价格型）；基本面恶化全部卖出；
  - 纯波段仓不适用 M-54 到 M-57；
  - 一旦该股 `entry_pass`，纯波段仓转为核心仓，已投比例按当前市值折算、上限 0.6。
- 组合回撤 −12% 状态下（M-62），两类波段买入也只允许防守层。

### 9.12 组合风控

- **M-61 黑天鹅**：SPY 单日 ≤ −4% 或 5 日 ≤ −8%（与上次触发间隔超过 10 个交易日才重新触发）→ 之后 3 个交易日暂停所有买入；进攻层持仓各卖 50%（恐慌日不卖）。
- **M-62 回撤刹车**：权益较历史高点回撤 ≤ −8%（非恐慌日、且未处于已触发状态）→ 进攻层持仓各卖 1/3；回撤回到 −4% 以内解除。回撤 ≤ −12% → 只允许买防守层，直到回撤收窄到 −6% 以内。
- **M-63 VIX 恐慌闸门**：VIX ≥ 其过去 252 个交易日的 90 分位（至少 120 天数据）的日子为恐慌日。恐慌日不生成价格型和恐慌型卖出（M-55、M-56、M-61 的减仓、M-62 的 −8% 减仓）。**不受闸门影响**：逻辑死亡（M-50）、灾难止损（M-51）、波段止盈止损。已知风险：样本里没有 2022 年式的阴跌，阴跌市里闸门会让卖出变迟，页面要明示。

### 9.14 两套卖出规则（E2 的说明）

Muse 仓库里其实有**两套不同的卖出规则**：

| | A：v18 回测（`paper_trade_v18_full30.py`） | B：前向纸面跟踪（`paper_tracker.py`，10 月起每天在跑） |
|---|---|---|
| 核心思路 | 看**基本面和趋势**：基本面没坏、趋势没破就拿着 | 看**成本价的固定百分比** |
| 止损 | 没有固定止损。逻辑死亡清仓；跌破 200 日线若干天分批减仓（防守 10 天减 1/3，普通 3 天减 1/2，进攻 7 天减 1/3）；只有进攻层有"高点回撤 40% 且破 200 日线"的灾难止损 | 按层固定：防守 −8%、普通 −12%、进攻 −18%，**碰到就全部卖出** |
| 止盈 | 没有固定止盈。只有波段仓在偏离 50 日线过大时卖出，进攻层翻倍后锁 25% | 按层固定：防守 +15%、普通 +20%、进攻 +25%，**碰到卖 1/3，只卖一次**，剩下的不再止盈 |
| 触发时点 | 收盘后判断，次日开盘成交 | 盘中按 1 分钟线，碰到价线即成交 |
| 恐慌日 | VIX 闸门暂停价格型卖出 | 无闸门 |
| 结果依据 | +49.45% / −12.64% 就是这套规则跑出来的 | 没有回测，只有 10 月以来的前向记录 |

**同一只股票在两套规则下的不同结果**（示意）：普通层股票，成本 100 美元，之后先跌到 87、再涨到 125。

- **规则 A**：跌到 87 时基本面没坏、还在 200 日线上方，**不卖**；如果跌进弱势带还可能加一笔波段仓。涨到 125 时核心仓继续持有，波段仓在偏离 50 日线过大时卖出。
- **规则 B**：跌到 88（−12%）盘中触发止损，**全部卖出**，后面的反弹完全错过。如果没跌到 88，涨到 120 时卖出 1/3，剩下的 2/3 不再有止盈。

两者的取舍：

- A 能拿住正常波动里的好公司，这是 v18 收益的主要来源；代价是在"基本面还没体现、价格先走坏"的阶段卖得慢。
- B 对单笔亏损的控制更直接、更容易理解；代价是在高波动的成长股上容易被正常回调洗出去，而且没有回测证明它更好。

**问题在于**：现在 Muse 的回测成绩是 A 跑出来的，每天的纸面组合却按 B 在运行。两者的成绩不能互相印证；如果把 v18 的 +49% 当作纸面组合的预期，会误导判断。

**已定**：重写后统一按 A 执行（第 9.10 节）。B 不丢掉，把"固定止损"作为 A+ 提案 S9，用同一套数据回测"A 加上固定止损"与"纯 A"的对比，结果更好再并入。现有 B 的前向记录保留，作为历史存档。

**S10 价格结构止损复核（v1.0 新增）**

这是"战争、关税、疫情等突发系统性事件导致跌破止损线时，不机械执行"的实现。它是规则 A 的 VIX 恐慌闸门（M-63）在个股层面的推广，**只用价格结构判断，不用新闻归因**，所以可以做历史回放。

- **作用对象**：价格型卖出 M-51、S2 的前两款（均价 × 0.75、200 日线）、S3、S9；以及恐慌闸门未覆盖的日子里的 M-55。
- **复核资格**（信号日收盘计算，全部满足；数据来自价格结构层 `marketstate`，第 11.3 节）：
  1. **系统性冲击**：`shock_flag = true`，即（SPY 5 日涨跌 ≤ −5%，或 VIX ≥ 自身 252 日 80 分位）且全市场广度坍塌（标的池 + 广域集合中 5 日下跌的比例 ≥ 70%）。
  2. **下跌主要来自 β**：该股 5 日剩余涨跌（剔除市场和 L2 板块 β）≥ −1.0 × 其 5 日剩余波动。
  3. **不是公司事件**：过去 5 个交易日没有该股的财报反应日，也没有触发 S4。
  4. **基本面没坏**：不满足任何 M-50 条件；最近一期财报没有新触发 S1。
- **动作**：原规则要卖出的数量**减半执行**；剩余部分设二级线，价格较信号日收盘再跌 9%（进攻）/ 6%（普通）/ 4%（防守）→ 卖出剩余；复核期最长 5 个交易日，到期重新按原规则判定。同一持仓在同一次冲击（`shock_flag` 连续为真的区间）里只能复核一次，不能续期。
- **硬线不受复核**：M-50 逻辑死亡；S4 财报跳空；单票浮亏 ≥ 总权益 1.5% → 原规则全额执行。
- **与新闻归因的关系**：第一阶段 S10 不读任何新闻或 LLM 结论；系统性事件类型标签（第 11.3 节）只写进 S10 的影子记录。以后如果加入归因，只能作为**收紧**条件（例如"关税事件对该公司为直接成本暴露"→ 取消复核资格），不能作为放宽条件。
- 回放样本：2020-03、2022 年、2024-08-05、2025-04 关税冲击。

第二阶段回测时一并处理第 18.2 节的回测方法改进。

### 10.7 高成长股在 A+ 下会怎样（按 2026-10-09 数据推演，示意）

| 标的 | 规则 A | A+ | 估值参考 v1.1（示意） |
|---|---|---|---|
| AMD | 已持有，不再加仓 | B1 34 过线；原始估值分 < 20 → B3 管理（单票按 4%，已超出则不加）；`dev50` 15% > 10%，按 B4 等回踩；S1 / S4 时先减 | 偏高；隐含增速略高于一致预期（第 8.7 节） |

| BE | 数据缺口，无打分 | 先修数据（D3、D5）；B1 29 差 1 分，**不买**，观察 | 未盈利成长类，置信度最高为中 |
| VRT | 时机和趋势不过 | 不变：等趋势修复。A+ 不是放松所有标准，只放松"用错了尺子"的地方 | —— |
| GEV | 普通层估值 41.4 < 45 | B1 65 过线，按普通层常规仓位（B9 调节）试仓 | —— |

## 11. 桥：模块一 → 模块二

### 11.1 覆盖层契约

系统每个交易日北京时间 **20:00** 起做盘前复核，**20:30 前**发布：

- HTTP 只读接口：`GET /api/linkage/overlay?date=YYYY-MM-DD`
- 文件：`event_overlay_YYYY-MM-DD.json`

```
version, generated_at, source_events_asof, params_version
tickers: {
  "<TICKER>": {
    linkage_events: [id, 生命周期, 五维状态, 机制, 暴露类别],
    cooling_off: bool,              # 第一阶段唯一生效的字段
    first_lot_multiplier: 1.0,      # 第一阶段恒为 1.0（核查期首笔减半为影子信号 X2）
    divergence_tag: 情绪性折价|合理重定价|滞后风险|情绪性溢价|基本面驱动上涨|null,  # 只展示
    stop_review_eligible: false,    # 第一阶段恒为 false；S10 由价格结构层判断，不走覆盖层
    reason: 中文说明（可追溯到联动事件和证据）
  }
}
market: { risk_level: 正常|警戒|危机, l1_state, systemic_events: [...] }
```

覆盖层由规则生成，只读联动事件的结论；属于"桥"。

### 11.2 第一阶段生效：冷静期 + 撤单

1. `cooling_off = true` → 不生成该股的新买和加仓，`skipped` 写"事件冷静期：联动事件 xxx"（N5）。
2. 当日覆盖层把某只股票设为冷静期，而它已有未成交买单 → **撤单**。这是"接刀漏洞"的修补：盘后暴跌的股票，次日开盘低于触发价时会按开盘价自动成交。
3. 覆盖层缺失或过期（`generated_at` 早于当日 18:00）→ 交易照常运行，盘前计划写"覆盖层未接通"。
4. 覆盖层**只能删除买单或减小数量**，不能新增买单、不能提高数量、不能卖出（I24）。

**冷静期的范围**：只给"直接暴露、机制非估值倍数类"的标的。主题连带（估值倍数类）不冻结——把所有沾边的股票都冻结，系统就会被情绪带着走。

上线后报告"被撤单 / 跳过的股票此后 5 / 21 日表现"，评估错误阻断的成本。

### 11.3 价格结构层（第一座可回测的桥）

**为什么先建这座桥**：模块一的新闻归因、LLM 候选、叙事热度没有历史版本，无法做 PIT 回测；任何依赖它们放宽交易的规则都无法验证。而价格结构（剩余涨跌、广度、VIX）**完全由价格算出、可以回放到任意历史日期**。所以模块一影响模块二，先从价格结构开始；新闻归因只做研究、展示和收紧。

**包** `inves_cog.marketstate`：只依赖 `ingest` 的行情，不依赖 `perception`、LLM、估值；`trading` 和 `perception` 都可以读它（I01）。

每天收盘后输出：

| 字段 | 定义 |
|---|---|
| `shock_flag` | （SPY 5 日涨跌 ≤ −5%，或 VIX ≥ 252 日 80 分位）且（标的池 + 广域集合中 5 日下跌的比例 ≥ 70%） |
| `l1_state` | 正常 / 警戒 / 危机（按 SPY 回撤、VIX 分位、广度分档） |
| `resid_1d`、`resid_5d` | 每只股票剔除市场、L2、L3 β 后的 1 日、5 日剩余涨跌，及其 σ 标准化值 |
| `basket_resid`、`basket_breadth` | 每个篮子的剩余涨跌、同向成员比例 |
| `beta_share_5d` | 5 日涨跌中可由市场和板块 β 解释的比例 |

第一阶段：页面展示；感知模块用来做异常发现和冲击分解；交易模块**只在 A+ 的 S10 中读取**（默认关闭）。

**系统性事件类型标签**（Q6 已确认）：

- 标签集合：战争 / 地缘、关税 / 贸易、疫情 / 公共卫生、货币 / 流动性、其他宏观、无。
- 谁打：`l1_state` 不是"正常"或 `shock_flag` 为真的交易日，`deepseek-v4.1-flash` 从当日回捞的信息中抽取候选标签；规则要求引用的信息 id 至少一条为一级或二级信源，否则标签为"无"。
- 存在哪：`perception` 的市场日记录和 S10 的影子记录里；属于感知模块，`marketstate` 不读它。
- 第一阶段：只展示（`/market`、处置卡）和影子记录。
- 以后：只能作为 S10 的**收紧**条件（例如关税事件、且图谱显示该公司对关税有直接成本暴露 → 取消复核资格），不能放宽任何卖出。

### 11.4 影子信号（只记录，不进订单）

| # | 信号 | 条件 | 影子动作 | 记录位置 | 评估条件 |
|---|---|---|---|---|---|
| X1 | 基本面恶化减仓 | 持仓所在联动事件"已验证·有影响"（负面），暴露为直接；当年 EPS 共识较事件前 ≤ −5%；收盘低于 50 日线 | 减 1/3 | `perception_shadow` | ≥ 20 次触发或两个财报季后，与"等下一份 10-Q"的结果比较 |
| X2 | 核查期首笔减半 | 联动事件"基本面核查中"且直接暴露 | 首笔 × 0.5 | `perception_shadow` | 同上 |
| X3 | 情绪性折价 + 观察名单波段 | 标签"情绪性折价"，且满足 9.11 观察名单波段的资格 | 允许观察名单波段入场 | `perception_shadow` | 同上 |
| X4 | 一致预期进成长账 | 一致预期快照满两个季度后 | 成长与预期账加一项"当年 EPS 共识 30 日修订"（权重 15，其余按比例缩减） | `perception_shadow` | 前向两个季度对比 |

X1 回答的是：两次财报之间，已经被验证的基本面恶化（例如东芝扩产被证实压价、STX 一致预期大幅下修）**目前没有任何通道进入卖出**，只能等下一份 10-Q 让四本账变化。X1 先记录"如果当时减仓会怎样"，攒够证据再决定是否做成规则。

影子信号写入的 schema，交易服务账号没有写权限，也没有读权限（I32）。

### 11.6 决策矩阵：持有的该怎么办，没持有的要不要买

**第一阶段实际执行**（只有规则 A + 冷静期）：

| 情况 | 持有 | 未持有 |
|---|---|---|
| 叙事驱动下跌，基本面未变，低暴露 | 按规则 A：没破位、没逻辑死亡就**持有不动**（M-59） | 估值账因价格下跌上升，但时机账通常同时跌破 → 多数情况"**等**"（N3）；时机账修复后按门槛买 |
| 叙事驱动下跌，直接暴露、正在核查 | 持有；**冷静期内不加仓**（N5） | 冷静期，不买，已挂买单撤单 |
| 系统性冲击击穿破位线 | 恐慌日由 M-63 暂停价格型卖出；非恐慌日按规则执行（S10 启用后改为减半 + 二级线） | M-61 黑天鹅暂停买入 3 天 |
| 基本面已验证负面（两次财报之间） | 不加仓；卖出要等下一份 10-Q 让四本账变化（M-50 / M-56）；**X1 影子记录** | 冷静期延续到下次财报 |
| 叙事驱动上涨 | 持有；`dev50` 过大时波段仓止盈（M-53）；"不追高"红线挡加仓 | 不追：M-18 不追高；估值参考显示偏高 |
| 基本面兑现的上涨 | 新财报后按门槛加仓（M-40） | 按门槛买 |
| 原因未明 | 按规则 A，不额外动作（N6） | 同左 |

**终局**（第四阶段以后）在上表基础上：价格超过估值区间乐观值且基本面没跟上 → 按价值减 1/3；基本面没变但价格大跌 → 估值位置下降、仓位系数上升，时机账修复后买得更多；系统性冲击 → S10 复核。

| 模式库 | 反复出现的"触发类型 → 传导 → 资金行为 → 结局"，例如"应用榜单登顶 → 主题叙事上涨 → 20 日回吐 70%" | 新异常命中模式时显示历史同类的回吐比例、持续时间、基本面兑现率 | 候选 → 观察（≥ 10 例）→ 有效（≥ 30 例且保留样本成立）；只展示统计，不直接交易 |

| 交易规则候选 | 被冷静期挡掉的、被止损卖掉后反弹的、该减没减的；影子信号和 A+ 的分歧 | 治理流程：一次一条、PIT 回测、批准 | —— |

### 13.3 独立结果标签

每个环节单独评价，**方向猜对但原因错误，不算传导验证成功**：

| 评价对象 | 标签 | 判定依据 |
|---|---|---|
| 消息内容 | 支持 / 反证 / 修订 / 仍未知 | 原始来源、官方表态 |
| 市场连接 | 确认 / 否定 / 未检验 | **二次命中检验**（第 6.9 节）+ 四项指纹 |
| 经营连接 | 兑现 / 未兑现 / 相反 / 尚未到期 / 到期仍未知 | 基本面轨道、下一份财报 |
| 交易执行 | 是否遵循生效规则 | 盈利不等于执行正确 |
| 规则效果 | 收益、回撤、成本、换手、错失机会、错误阻断 | 规则对照 |

"尚未到期"不计成败；"到期仍未知"计入无法识别，不当作"无影响"。

### 13.4 独立漏检评价

只统计"系统发现的事件里有多少对"会掩盖漏报。另设一个**独立于系统候选的样本框**：每月从未达阈值的行情异动、未触发的线索、被丢弃的消息、广域集合中未输出的公司里分层抽样，人工判定"是否是应发现的事件"（不看系统是否发现），分别报告检出率和正确率。

| 漏在哪一环 | 闭环动作 |
|---|---|
| 证券 / 来源不在覆盖范围 | 覆盖漏检 → 数据接入建议 |
| 有数据但异常 / 累积入口没触发 | 检测漏检 → 检查阈值和观察窗 |
| 议题已启动但没提出关键中间机制 | 连接生成漏检 |
| 机制已提出但没查到当时可得的资料 | 补证漏检 |

### 13.5 验证纪律（防过拟合）

- 不能用单个事件定参数；按事件家族划分样本，同一根源的消息、认证、修订属于同一家族。
- 时间顺序划分开发 / 验证样本；最终验证集只用一次。
- 登记全部尝试过的候选和参数，不只保存获胜者。
- 每次比较同时看收益、回撤、成本、换手、错失机会、错误阻断。
- 相似案例展示时必须同时展示反例。
- "原因未明"和失败案例与成功案例同等保存；它们的占比下降才说明系统在进步。
- 复盘只产生修改建议，不在线自动改权重、门槛、止损或池子。

### 13.6 先兆特征库

C3 需要大量"异常发生前的状态"样本和同样多的对照样本。叙事热度、榜单、期权快照这类数据不保留历史，事后无法补齐，所以**第一天起**每日为每只标的、每个篮子存一份状态快照，缺失项写明：

| 维度 | 特征 |
|---|---|
| 拥挤度 | 6 个月涨幅分位、篮子内部相关性、动量暴露 |
| 空头 | 空头占流通股比例、回补天数及变化 |
| 期权 | 看涨 / 看跌持仓比、隐含波动率分位、偏度、到期集中度 |
| 叙事热度 | 独立来源数、搜索热度、榜单名次变化 |
| 估值 | p、Δg |
| 价格结构 | 距均线、波动率分位、连续涨跌天数、`beta_share_5d` |
| 预期 | 一致预期修订方向和广度 |

评估（达到样本门槛后）：比较"发生前 5 天"和对照样本的特征分布；用时间顺序保留样本检验预测提升；通过后先作为"风险提示"展示，前向验证后再考虑进入仓位规则。先兆快照不拿去改交易。

### 13.7 因子候选池（持续迭代）

"扩充交易因子"和"高 PE 成长股的买入路径"都走这一个流程。新因子不直接改规则，而是从登记开始，一步步靠近订单。

**生命周期**：

| 状态 | 做什么 | 阶段 |
|---|---|---|
| 登记 | 写明定义、输入数据及其 PIT 可得性、想放进哪本账或哪条规则、经济逻辑、来源、预期方向 | 任何时候 |
| 影子计算 | 每个交易日计算因子值和"如果生效会怎样"，写入 `factor_shadow` | **第一阶段起** |
| 回测 | 按第 10.6 节的方法单独回测，再与已采纳的因子合并回测 | 第二阶段 |
| 前向影子 | 回测通过后，与现行规则并行至少一个季度 | 第二阶段起 |
| 生效 | 用户批准，走变更提案，Harness 期望值同步修改 | —— |
| 监控 | 每季度对比生效后的表现与回测预期 | —— |
| 退役 | 连续两个季度前向失效，或被新版本替代 | —— |

**来源**：复盘（第 13.1 节的交易规则候选）、漏检周报、A+ 提案、影子信号、用户指定。

**初始候选**：

|---|---|---|---|---|
| F-01 | 成长调整估值分（B1） | 估值账（替代 M-31） | 高 PE 成长股被绝对倍数挡死 | 影子计算 |

| 隐含幅度（按渠道） | **直接收入渠道**（OpenAI ARR 少几十亿）：对整个 AI 篮子 R 远大于 5，不相容。**订单 / 积压渠道**：对 RPO 中 OpenAI 合同占比高的公司（例如数千亿美元级的算力合同对手方），按四级信源的延期比例上限计算，R 可能落在 1.5–5 → 部分相容 → 进基本面核查。**缺美元暴露的公司**：无法检验，登记补暴露任务 |
| 分层 | 高暴露（订单高度依赖 OpenAI）→ 客户 / 融资机制，核查 + 冷静期；低暴露（多数 AI 股）→ 估值倍数，不冻结 |
| 传闻隔离 | 真实性"未核实"；"OpenAI 收入不及预期可能影响算力订单"只计入叙事维度和跟踪清单，不能作为经营证据 |
| 二次命中 | 登记指纹：OpenAI 官方否认 / 新融资消息 → 合作方篮子应反弹；后续再有负面爆料 → 应再跌 |
| 交易 | 持仓 NVDA、AVGO、MRVL 等低暴露 → 持有，没破位不动；直接暴露的标的冷静期，不买；系统性下跌若触发恐慌日，M-63 暂停价格型卖出 |

要点：**"禁不住推敲"要按渠道推敲**。直接收入渠道确实解释不了跌幅，但对手方 / 订单渠道可能可以。系统不在当下贴"情绪"标签，而是让高暴露公司进核查、低暴露公司按估值倍数冲击处理，由截止日结论和二次命中决定最终标签。

**T+1 至截止日**：情绪扩散 → 衰减；资金 5 日回吐 60%；OpenAI 侧否认 → 合作方篮子反弹 1.5σ（**二次命中：确认**市场在交易这个逻辑）；无分析师下修 → 经营传导"失效" → 标签"情绪性折价"，解除冷静期。

### 14.3 Meta Muse 登顶 App Store → META、CPU 股大涨

| 环节 | 系统行为 |

### 16.3 Harness 的层

Harness 要拦住已经发生过的问题：注释和常量不一致、两套卖出规则混用、财报缺口被当成 0 分、估值渗进订单、回测用了当时还不存在的股票、测试被改成跟着错误结果走。

| 层 | 标记 | 跑什么 | 每次提交 | 允许网络 | 允许 LLM |
|---|---|---|---|---|---|
| H0 静态门禁 | `phase1_blocking` | 导入关系、禁用词、常量、时钟、未登记的 skip | 是 | 否 | 否 |
| H1 纯函数 | `phase1_blocking` | 插值、红线、门槛、估值公式、隐含幅度、健康码，输入是仓库里的小 JSON | 是 | 否 | 否 |
| H2 回放 | `phase1_replay` | 用冻结的日线和财报状态重跑 v18 | 每晚；改 `trading` 时也要跑 | 否 | 否 |
| H3 案例 | `phase1_cases` | 东芝、OpenAI、Meta Muse、DeepSeek 的冻结新闻和价格 | 改 `perception` 时 | 否 | 只用录音 |
| H4 A+ | `aplus` | A+ 各条规则的纯函数和夹具 | 改 `rules_a_plus` 时 | 否 | 否 |

`phase1_blocking` 必须在 3 分钟内跑完。任何测试访问套接字即失败。时间只能从注入的时钟来：`trading`、`valuation_v1`、`perception`、`overlay`、`marketstate` 里出现 `datetime.now(` 或 `date.today(` 即失败。

### 16.4 目录、标准答案与不变量

```

### 16.6 运行失败时怎么停

## 19. 诚实的边界

- **系统不能在当下确定因果**。它能做的是：快速看到异常；尽量找全候选；用证据区分"市场在交易什么"和"经营上是否成立"；在不确定时按固定规则行动；事后诚实评估自己对了多少。
- **第一阶段两个模块之间的联系是有意做薄的**：只有冷静期和撤单会影响交易。估值（通过估值—仓位对照）、背离、基本面恶化、新的基本面因子、事件感知的止损复核都先展示和影子运行，第二阶段回测后按第 11.5 节的路线逐步接入。这样做的代价是第一阶段的交易仍然是机械的；好处是不会出现情绪和资金数据"打架"把交易系统变脆弱。
- **一手数据覆盖有限**：社交要付费，产业价格数据很贵，总会有信源之外的源头。漏检报告就是用来暴露这一点的。
- **日级时效**：交易影响以次日盘前为准，当天来不及反应。
- **参数都是初始值**，要靠回放和前向运行校准；样本少的时候，系统宁可"原因未明，等待"，也不硬给答案。
- **回测结论有偏**：规则 A 的 +49.45% 来自一个 9 个月的上涨窗口和事后挑选的池子，不能当作纸面组合的收益预期（第 18.2 节）。
