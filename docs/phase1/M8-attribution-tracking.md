# M8 建连归因与三轨跟踪

| 项 | 内容 |
|---|---|
| 文档版本 | v1 |
| 规格章节 | 6（全部）、7（全部）、5.4、11.3（系统性事件标签） |
| 依赖 | M7（异常）、M6（图谱、篮子、`marketstate`）、M1（全量库）、M2（一致预期、分部、营业利润率） |

| 规模 | 大（设中期检查点） |

## 1. 目标

对每个异常，在当时可得的信息里找出最可能的几个原因，用证据而不是故事给每个原因打分；把"市场在按这个逻辑交易"和"这个逻辑在经营上成立"分开回答；然后对成立的联动事件持续跟踪情绪、资金、基本面，直到有结论。

对应需求（逐条）：

- "源头事件有没有被抓到；抓到了会不会被当成普通信息过滤掉" → 回捞；
- "它凭什么知道 CPU 的上涨来自下载榜，而不是别的原因" → 证据打分、对照篮子、二次命中；
- "OpenAI 的 ARR 新闻经不起推敲" → 按渠道的隐含幅度；
- "如果市场形成了共识……说明这是市场和资金的共同反应" → 市场确认、二次命中；
- "持续看：后面还带来什么、价格有没有企稳、后面的消息和资金怎么走，最后确认基本面会不会受影响，股价和基本面有没有背离" → 三轨跟踪、截止日、背离标签；
- "中间的逻辑必须建出来，不能只给一个结论" → 传导链、解释报告。

## 2. 范围

**做**：回捞、补证搜索、说法抽取、候选生成、证据打分、按渠道的隐含幅度、市场确认与指纹、二次命中、"原因未明"处理、联动事件与五维状态、生命周期状态机、跟踪清单与截止日、三轨、"已验证"判定、背离标签、系统性事件标签、冲击分解、Brain 增量触发、受影响标的的 N1 / N2 / N6 代码、解释报告。

**不做**：覆盖层（M9 读取本模块结论后生成）；影子信号（M9）；页面和处置卡渲染（M10）；任何订单；任何估值改动（估值只随一致预期和财报变化，M5 自己读 M2）。

**边界澄清**：

- **LLM 只负责"想到"**：候选机制由 `glm-5.3` 提出，必须引用回捞到的信息 id；**所有分数、状态、结论都由规则计算**。
- 二次命中和共识度只写市场层，**不能作为"已验证"的证据**（规格第 7.3 节）。
- "情绪性折价 / 溢价"标签**只在截止日由三轨结论给出**，隐含幅度"不相容"不得直接生成情绪标签（I30）。
- 广域集合的异常（`universe = 'wide'`）只做回捞和记录，不生成候选、不建联动事件。

## 5. 功能需求

### 5.1 回捞与说法

| 编号 | 需求 |
|---|---|
| FR-M8-01 | 异常起点：`close` 时段为当日美东 09:30，`post` 时段为当日收盘时间；回捞窗口 = [起点 − 72 小时, 运行时刻] |
| FR-M8-02 | 检索实体 = 异常成员 + 所属篮子成员 + 这些实体在图谱上一跳内的邻居（任何状态）+ 关联的监控实体 |
| FR-M8-03 | 两路检索取并集：（a）规则：`entities` 或 `tickers` 与检索实体有交集；（b）向量：用"篮子名、方向、成员名"组成的描述文本，在窗口内按余弦相似度取前 50。按 `source_root` 去重 |
| FR-M8-04 | 排序分 = 0.5 × 实体重合度（命中实体数 ÷ 检索实体数，上限 1）+ 0.3 × 向量相似度 + 0.2 × 信源权重（一级 1.0、二级 0.75、三级 0.5、四级 0.25）；取前 40 条交给候选生成 |
| FR-M8-05 | 回捞结果 < 5 条时，用补证搜索（Tavily / Exa / Google CSE，沿用现有预算）按实体名和日期补搜；结果作为 `info_items` 入库，`first_seen_at` 为当前时间，时间对齐只用 `published_at` |
| FR-M8-06 | 说法抽取：对进入前 40 条、尚无说法的信息调用 `claim_extraction`（`deepseek-v4.1-flash`）；原文不支持的字段保持空 |

### 5.2 候选与证据

| 编号 | 需求 |
|---|---|
| FR-M8-07 | 候选生成：`anomaly_candidates`（`glm-5.3`）。输入：异常对象、前 40 条信息（id、时间、等级、标题、摘要、说法）、图谱邻域。输出最多 5 个候选，每个含：机制类型（供给 / 需求 / 竞争 / 客户融资 / 估值倍数）、传导链（实体 id；新节点以"候选"提出）、预期受影响的篮子和标的及方向、对照篮子、引用的信息 id |
| FR-M8-08 | 候选校验：引用 id 为空或不在本次回捞集合里 → 丢弃（I23）；标的不在池子或广域集合里 → 删去该标的；另加固定候选"无事件 / 资金面"，它不打分，只在其他候选都低于 0.5 时作为结论 |
| FR-M8-09 | 六项证据分（0–1，缺数据为 `NULL`，总分按可用权重重配）：**时间对齐**：引用信息中最早 `published_at` 早于起点所在时段 → 1.0；同一时段 → 0.7；晚于 → 0。**暴露梯度**：成员暴露度（直接 3、间接 2、概念 1、无 0，来自状态 ≥"观察到"的关系）与按预期方向取号的 `resid_z` 的 Spearman 秩相关，取 max(0, ρ)；成员 < 3 为 `NULL`。**篮子特异性**：预期篮子 `|resid_z|` 均值减对照篮子 `|resid_z|` 均值，除以 3，限制在 [0, 1]；没有对照篮子为 `NULL`。**叙事证据**：窗口内同时提到事件实体和受影响实体的独立来源根数 N，取 min(N ÷ 5, 1)。**隐含幅度**：相容 1.0、部分相容 0.6、不相容 0.2、无法检验 `NULL`。**替代解释排除**：1 −（当日有自身财报反应日、8-K 指引或评级变化的成员数 ÷ 成员数） |
| FR-M8-10 | 权重 20 / 20 / 15 / 15 / 15 / 15（参数表）；总分 ≥ 0.70 为"高"，0.50–0.70 为"中"，< 0.50 为"低"；最优候选 ≥ 0.5 → 联动事件进入"假设中"。`requirements/m8_attribution.json` 的 `evidence_scores` 全部命中 |

### 5.3 隐含幅度（按渠道）

| 编号 | 需求 |
|---|---|
| FR-M8-11 | 市场侧：ΔE_mkt = Σ 成员（前一日市值 × 当日剩余收益 ÷ TTM PE）；EPS ≤ 0 的成员不计入，全部成员都不可计 → 结论"无法检验" |
| FR-M8-12 | 渠道由机制决定：供给 → 供给 / 价格；需求、竞争 → 直接收入；客户融资 → 订单 / 积压 + 融资 / 对手方；估值倍数 → 估值倍数。事件侧上限按规格第 6.7 节公式；比例上限按引用信息里**最高**的信源等级查参数表；增量利润率用分部利润率（暴露基础为分部收入时）或公司 `op_margin_ttm` |
| FR-M8-13 | 美元暴露只取状态 ≥"观察到"的关系；判定规则（含"部分渠道缺暴露"）按规格第 6.7 节；`requirements/m8_attribution.json` 的 `implied_magnitude` 全部命中 |

### 5.4 市场确认、二次命中、原因未明

| 编号 | 需求 |
|---|---|
| FR-M8-14 | 市场确认（四项同时满足）：（1）有最早说法时间；（2）对应对象有异常响应；（3）至少一个独立于价格的证据：独立来源根 ≥ 2，或监控实体搜索热度突增，或三级及以上信源的点评；（4）替代解释排除分 ≥ 0.5 |
| FR-M8-15 | 二次命中：市场归因 ≥ 中的候选登记预测指纹（关联实体、预期篮子和方向、对照篮子）；之后出现 `published_at` 晚于原异常起点、实体与关联实体有交集的新信息（同一来源根只算一次），在它的反应时段测预期篮子的 `resid_z`：方向一致且 ≥ 1、对照篮子 < 1 → 命中；方向相反且 ≥ 1 → 反证；否则无响应。结论：≥ 1 次命中且 0 次反证 → 确认；≥ 1 次反证或连续 2 次无响应 → 否定；跟踪期内无后续信息 → 未检验 |
| FR-M8-16 | 原因未明：所有候选 < 0.5 → 状态"已发现·原因未明"；每天重新回捞一次，持续 5 个交易日；涉及持仓且 `max_abs_z ≥ 4` 时写入系统日志"请人工查看" |

### 5.5 联动事件与三轨

| 编号 | 需求 |
|---|---|
| FR-M8-17 | 生命周期状态机（规格第 6.12 节）：每次状态变化写历史（时间、旧状态、新状态、触发条件、证据 id）；不允许跳过"假设中"直接进入"市场确认" |
| FR-M8-18 | 五维状态的规则：**真实性**：只有三四级信源 → 未核实；有二级独立信源 → 部分核实；一级信源确认 → 核实；一级信源修改数字 → 修订；一级信源否认或事实矛盾 → 证伪。**叙事**：每天提到事件实体的独立来源根数 Nₜ；Nₜ ≥ 3 且 ≥ 1.5 × Nₜ₋₁ → 扩散；连续 2 天 ≤ 0.5 × 峰值 → 衰减；衰减后 ≥ 0.8 × 峰值 → 重新活跃；其余 → 稳定（首日为初现）。**市场关联**：按指纹和二次命中。**经营传导**：见 FR-M8-20。**交易状态**：回吐比例 r = 1 − 累计剩余 ÷ 首日剩余；首 2 个交易日为风险释放；r ≥ 0.3 → 初步修复；r ≥ 0.5 且维持 5 个交易日 → 持续确认；初步修复后创出低于首日收盘的新低 → 修复失效 |
| FR-M8-19 | 资金轨道状态：k ≤ 1 → 冲击中；r ≥ 0.5 → 已消化；同方向累计 ≥ 1.2 × 首日 → 延续；r ≥ 1.0 → 反转；其余 → 消化中 |
| FR-M8-20 | 基本面轨道：读 M2 F2（共识修订、广度）、8-K、一二级信源的定量说法；状态 待验证 → 局部支持（出现一条一二级定量说法）→ 支持 / 冲突（满足规格第 7.3 节任一门槛，方向一致 / 相反）→ 失效（截止日未达门槛）；供给 / 需求类事件生成约束核查表（规格第 7.3 节六项），每项状态：未知 / 有数据 / 结论 |
| FR-M8-21 | 截止日 = min（受影响标的中暴露最直接者的下一个财报反应日，机制对应的周期参数，20 个交易日）；到期必须落到支持 / 反证 / 条件风险之一；不得续期；只有新的一二级原始证据、新的异常范围、或接近兑现期才能重新激活 |
| FR-M8-22 | 背离标签：截止日或"已验证"时按规格第 7.4 节的表和阈值给出；其他时刻为空 |
| FR-M8-23 | 系统性事件标签：`l1_state ≠ 正常` 或 `shock_flag` 为真的交易日，`systemic_event_tag`（`deepseek-v4.1-flash`）从当日回捞信息中给出标签；至少一条引用为一级或二级信源，否则为"无" |
| FR-M8-24 | 冲击分解：事件可解释 = 符号 × min(\|总剩余\|, ΣΔE_evt × PE ÷ 市值)（隐含幅度为"无法检验"时为 0）；资金放大 = (总剩余 − 事件可解释) × (M7 中为真的资金放大特征数 ÷ 可得特征数)；未解释 = 其余；三项之和等于总剩余（I23，允许 0.1 个百分点舍入） |
| FR-M8-25 | Brain 增量：对持仓和当日候选中"直接暴露、机制非估值倍数"的标的调用现有 `runtime.run_brain_update`（`brain_incremental`），每天最多 3 次，按"持仓 > 候选、暴露 > 幅度"排序；本模块不直接写任何 Brain 对象 |
| FR-M8-26 | 受影响标的代码：估值倍数类连带 → N2；叙事冲击且基本面未变 → N1；原因未明 → N6；写入 `perception.ticker_status` |
| FR-M8-27 | 解释报告按规格第 5.7 节和第 4.2 节旧模板的字段：冲击分解、类型候选（补全"事件冲击 / 叙事冲击 / 原因未明"）、候选列表及证据明细、影响范围、对估值（固定为"不变 / 待基本面轨道"）、对交易（交给 M9 / M10 填写）、跟踪清单、已检索信源与缺口 |
| FR-M8-28 | 日程：北京 08:15 生成候选和打分；09:30 更新三轨和截止日结案；12:30 写 T+1 打标草稿（交 M10）；写 `job_runs` |

## 6. 异常与降级

| 情况 | 行为 |
|---|---|
| `glm-5.3` 超时或失败 | 该异常标"待分析"，不阻塞其他异常；下一轮重试 |
| 全量库向量检索失败 | 只用规则检索，报告里写明 |
| 补证搜索预算耗尽 | 不补搜，报告里写"补证未执行" |
| 某渠道缺暴露 | 按规格规则给"无法检验"，并在图谱补暴露任务里登记 |
