# M10 页面、处置卡与复盘

| 项 | 内容 |
|---|---|
| 文档版本 | v2（新增今日大幅波动榜 FR-M10-14） |
| 规格章节 | 12（全部）、13（全部）、15（上线效果模拟） |
| 依赖 | M1–M9 |
| 关闭的不变量 | I25、I36 |
| 规模 | 中到大 |

## 1. 目标

让用户每天打开系统就能看懂：市场发生了什么；系统看见了什么、没看见什么；为什么做了、为什么没做；所有标的值多少、能不能买；系统有没有在变好。同时把每个异常变成可以复盘的案例，为"慢慢具备感知能力"攒样本。

对应需求："上线之后要能看市场动态、看所有标的的价值，并靠这些来做投资"；"用户还要看得见系统在做什么：是漏了新闻所以没动，还是已经看到了、理解了，但判断不用动，并且后面还会继续盯"；"还要有一套自我闭环：不断复盘，改善交易，扩充交易因子"；"最终目标是通过事后不断复盘、补强，让系统慢慢具备感知能力"。

## 2. 范围

**做**：

- 页面和每个页面对应的 JSON 接口（规格第 12.1 节的全部页面）；
- 处置卡（五种状态）、系统日志首页、个股决策时间线、不行动理由代码的展示；
- 一句话摘要（`summary_oneliner`）；
- 案例库与 T+1 / T+5 / T+20 打标、模式库候选、先兆快照、独立漏检抽样、周报、月报；
- 影子信号和因子影子的后续收益统计（5 / 21 / 63 个交易日）；
- 页面分区规则：市场与研究页面不显示订单、仓位和估值区间；交易内容只在 `/paper/*`，带固定标注。

**不做**：任何计算规则的改动（只展示上游结果）；任何下单功能；季度参数调整（季度复盘由用户批准，系统只出报告）。

**边界澄清**：

- 页面只读上游表，**不重新计算**任何分数、状态或估值；页面上看到的每个数字都必须能在上游表里找到同一个值。
- 处置卡的最终状态由三处结果合成：M8 的归因状态 + M9 的覆盖层动作 + M4 的计划动作（第 5 节 FR-M10-03）。
- 市场与研究页面（`/`、`/market`、`/stock`、`/events`、`/linkage`、`/graph`、`/settings/data`、`/review`）的 JSON 里不得出现订单、仓位、估值区间字段；这些内容只出现在 `/paper/*`。

## 3. 输入

所有上游模块的输出表（只读）。

## 4. 输出

页面和 JSON 接口（每个页面一个 `GET /api/pages/<name>?date=` 接口，测试调用 JSON 而不是截图）：

| 页面 | JSON 必须包含 |
|---|---|
| `/`（系统日志首页） | 规格第 12.3 节全部计数；一句话摘要；未处置项清单 |
| `/market` | L1–L4 状态、每层覆盖率、当日异常、当前联动事件、系统性事件标签 |
| `/linkage/{id}` | 证据时间线（标"晚于异常"）、候选及六项证据分、按渠道的隐含幅度、二次命中记录、传导链、指纹、五维时间轴、跟踪清单、约束核查表 |
| `/stock/{symbol}` | 影响本股的联动事件、"这次什么变了、什么没变"、基本面档案 |
| `/graph` | 关系、证据、美元暴露、审核状态和操作 |
| `/settings/data` | 数据源健康 |
| `/paper/plan` | M4 计划 JSON + N9 记录 + 影子摘要 |
| `/paper/portfolio` | 持仓、层预算、闸门、估值—仓位对照（带固定句子） |
| `/paper/universe` | 59 行：健康码、四本账、能否买和卡点、事件状态、估值参考、因子影子判断 |
| `/paper/stock/{symbol}` | 四本账历史、决策时间线、估值卡、基本面档案、因子影子 |
| `/paper/health` | M2 健康 JSON |
| `/paper/ledger` | 成交流水 |
| `/review` | 案例库、周报、月报、漏检报告、模式库候选 |

另有表：`perception.cases`（案例）、`perception.case_labels`（打标）、`perception.precursor_snapshots`（先兆快照）、`perception.miss_samples`（漏检样本框）、`perception.patterns`（模式库候选）、`perception.reports_weekly`、`perception.reports_monthly`。

## 5. 功能需求

| 编号 | 需求 |
|---|---|
| FR-M10-01 | 每个页面有 JSON 接口，字段按第 4 节；页面渲染只读 JSON |
| FR-M10-02 | 系统日志首页的计数必须等于上游表的计数（异常数、各状态数、高优先级信息数、交易动作数、"决定不动"数、影子分歧数） |
| FR-M10-03 | 处置卡状态合成：M8 为"原因未明" → ①；M8 已归因且 M9 / M4 没有对任何标的产生动作 → ②；M9 产生冷静期或 M4 产生订单 / 撤单 → ③；截止日已结 → ④；事后在漏检报告中确认 → ⑤；北京 13:00 仍没有状态的异常在首页标红 |
| FR-M10-04 | 决策时间线：每只持仓和当日候选每个交易日至少一条记录；"不动"也记，带 N 代码和下次检查日期 |
| FR-M10-05 | 一句话摘要：`summary_oneliner`（`deepseek-v4.1-flash`）只能使用当日上游 JSON 里的事实，输出必须引用至少一个异常 id 或"无异常"；失败时显示模板句"今日异常 x 个，详见下方" |
| FR-M10-06 | 案例：每个池内异常建一个案例；T+1、T+5、T+20 各写一条打标（规格第 13.2、13.3 节的独立结果标签），缺一条则案例"未完成"（I25）；T+20 的打标由系统起草，用户在周报里批量确认 |
| FR-M10-07 | 先兆快照：每个交易日为 59 只和全部篮子存一份规格第 13.6 节的状态快照；缺失维度写明原因 |
| FR-M10-08 | 独立漏检样本框：每周随机抽 20 条被排在关注队列之外的信息；每月抽 10 个未达阈值的价格异动和 10 只广域集合中未输出的公司；用户逐条判定"是否是应发现的事件"；分别报告检出率和正确率，未知和数据不覆盖单列 |
| FR-M10-09 | 模式库候选：按"触发类型 → 机制 → 资金行为 → 结局"分组，≥ 10 例进入"观察"，≥ 30 例且在保留样本上成立进入"有效"；展示时同时展示反例 |
| FR-M10-10 | 周报：漏检报告、估值区间变化最大的 10 只及原因、待确认打标、冷静期挡掉的买入此后 5 / 21 日表现、估值—仓位对照标黄的持仓此后表现。月报：归因校准（按置信度分桶的二次命中率和截止日结论）、规则 A vs 因子影子的分歧和结果、影子信号 X1–X4 的"如果当时这样做"、信源缺口排序、"原因未明"占比趋势 |
| FR-M10-11 | 固定标注：`/paper/*` 页面标"纸面跟踪，非投资建议"；估值相关区域标"估值参考 v1，不参与仓位"（I21、I36） |
| FR-M10-12 | 页面分区门禁：市场与研究页面的 JSON 中不得出现订单、仓位、估值区间字段（字段名清单写在测试里） |
| FR-M10-13 | 未接通的数据源在相关页面显示"未接通"，缺数据显示"数据暂缺"，不显示模拟值 |
| FR-M10-14 | **今日大幅波动榜**（2026-10-15 新增）：首页列出标的池和 ETF 里当日（含盘后）涨跌幅绝对值 ≥ 7% 的全部股票，按幅度排序，显示涨跌幅、z 值、所在篮子，以及是否已有异常对象（`alert` / `watch` / 无）。只展示，不触发归因，不调用 LLM。目的是让用户感觉到的大幅波动不会因为没达到异常阈值而在页面上消失 |

## 6. 异常与降级

| 情况 | 行为 |
|---|---|
| 上游某模块当日未完成 | 对应区块显示"今日未更新"和上游 `job_runs` 状态；其他区块照常 |
| 一句话摘要失败 | 用模板句 |
