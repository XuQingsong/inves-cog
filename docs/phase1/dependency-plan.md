## 2. 两条总原则

1. **每个任务有两个时间**：可见截点（只用这之前已发布、已入库的数据）和实际执行时间。等上游可以推迟执行，但**截点不跟着后移**；作业记录写真实开始/结束时间，快照与下游按真实结束时间判断可见。
2. **任务状态只有一个来源**：`ingest.job_runs`（任务 + 交易日）。调度标记只负责防止重复启动；“成功”以 job_runs 为 ok/degraded 为准，不以进程返回码为准。

## 3. 强依赖与弱依赖的规则

- **强依赖**：缺了上游，下游的结果就是错的或没有意义。下游从“最早开始时间”起轮询，上游成功且真实结束时间不晚于当前时间才执行；到“最晚期限”仍未就绪，记 `skipped_upstream` 并写明缺哪个上游，下游的下游同样跳过并沿用原因；绝不拿部分数据凑数。暂时性失败（网络、模型超时）在窗口内最多重试 2 次。
- **弱依赖**：缺了上游，下游仍能产出有用、不会误导的结果。下游按时运行，使用截点前最新可见的版本，并在输入完整度里写明缺什么、用的是哪天的数据、对结论有什么影响。每条弱依赖必须写出“为什么可以弱”。
