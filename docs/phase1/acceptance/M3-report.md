## 3. 需求方核查中发现的问题

### 3.1 规格第 10.1 节 GEV 的层级写错了（需求缺陷，不算开发问题）

规格写 GEV 为"普通层、估值 41.4 < 45、不能买"；本项目算出进攻层、`entry_pass = true`。需求方核对：

- 分层只在新财报生效那天重估（M-20）。GEV 2026-07-22 美东盘前发布财报，当天 `vol60` = 55.044（需求方用库里价格独立重算，结果相同），满足 M-21 的 `vol60 > 55`；07-23、07-24 分别为 55.72、55.53，生效日不论落在这三天中哪一天，结论都不变；
- 规格那张表用的是 10-09 当天的 `vol60`（48.6）分层，不符合 M-20。

开发的结果正确。已在规格第 10.1 节加注说明。

### 3.2 UNH 的毛利率算错，导致估值账被清空（M2 数据错误 → D-27）

`fixed` 下 UNH 自 2026-01-02 起每天被标为 `split_suspect`，估值账为空，实际上进不了候选。原因：M2 `fixed` 推算出的 UNH 毛利率是 88.6%（健康码 `gross_margin_derived`），保险公司扣除医疗成本后的真实毛利率约 15–20%。错误的毛利率触发 M-08（PS < 3 且毛利率 > 60%）。

这属于"数据算错"，按冻结规则必须修，但问题在 M2，不在 M3：M3 正确执行了 M-08。已记为 D-27，期限是 M4 开工前。需求方核对了其他推算毛利率的标的（COST 12.8%、WMT 24.5%、META 81.7% 等），都在合理范围。

### 3.3 其他"拆股疑似"都是规则的正常行为

- NFLX、NOW：去年确实拆过股；
- KLAC：2026 年 1 拆 10，最新财报里的股数从 1.31 亿变成 13.07 亿。新财报出来之前，用拆股后的价格乘以拆股前的股数，市值被低估 10 倍，PE 只有 4.5，正是 M-08 要识别的情况。
