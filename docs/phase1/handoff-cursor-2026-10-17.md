## 1. 项目是什么

独立项目 `XuQingsong/inves-cog`（Python 包 `inves_cog`），美股市场分析加纸面交易系统。不依赖 stock-pm 或 Muse 的代码和数据库。Muse 只作数据导入来源、v18 标准答案，以及规则 A 未写明细节的参考（重写实现，不复制代码）。

**用户的原始诉求**（10-13 第一条消息，原文见对话开头）：

- 分成两个严格隔离的模块：
  - 模块一：市场与基本面，包括消息面、情绪面、资金面和公司基本面；
  - 模块二：估值与交易，包括评分、估值、仓位、止损止盈。
- **快慢机制**：消息、情绪、资金变化快，基本面变化慢。快的东西不能直接改写慢的结论，否则系统会变成追涨杀跌。
- 用于检验设计的案例：
  - 东芝扩产导致 HDD 板块暴跌（WDC、STX）；
  - OpenAI ARR 低于预期，AI 股集体下挫；
  - Meta 的 Muse 登顶 App Store，带动 META 和 CPU 股上涨。
- 系统要能：
  - 感知股价异常（以天为单位）；
  - 自己建立事件和异常之间合乎逻辑的连接；
  - 持续跟踪后续影响；
  - 判断股价和基本面是否背离；
  - 给出稳定的估值和合理的交易行为。
- 用户要能看懂系统在做什么：分清"漏掉了"和"知道了但判断不用动"。
- 最终目标是让系统逐步具备"感知能力"，并通过复盘形成闭环。

**三个阶段**：

1. 第一阶段（当前）：看见、解释、记录。交付基本面、独立估值（只展示加影子，不影响仓位）和规则 A 纸面计划。
2. 第二阶段：回测、A+ 规则、因子的前向影子评估。
3. 第三阶段：估值进入评分和仓位。

**信箱机制**（`ops/README.md`）：

- 任务写在 `ops/inbox/A|B/<编号>.md`，只由需求方写，发出后不改；
- 回报写在 `agent-status` 分支的 `ops/status/A.md`、`B.md`，最新的在最上面；
- 开关是 `ops/control.md`，可设"运行"或"暂停"；
- 需求方对开发问题的答复放在 `ops/answers/<任务编号>.md`。

**关键节点**：

- G1 开工：用户批准；
- G2 方向确认：需求方审开工复述；
- G3 验收：需求方出报告和验收页；
- G4 合并：给用户一张合并单，用户回"合并"后由需求方来合并，agent 不合并。

**铁律（用户 10-16 明确要求）**：

- 每条线同时只有一个任务：下发 → 执行完 → 需求方验证完 → 再下发下一个；
- 任务执行期间，不改已下发的任务文件和 `ops/README.md`；规则变化随下一个任务一起生效；
- 例外：只剩"等时间"的证据时可以先收口，剩余证据由需求方事后核对。

**用户决策的同步**：开发直接问用户得到的答复，记成 `UD-A-xx` / `UD-B-xx`，由需求方写进模块文档。协调方得到的决定记为 `UD-COORD-xx`，见 tracker 末尾。

**用户外出授权（10-16 起）**：

- 可以直接做：任务下发、验证、合并和常规决策，事后同步给用户；
- 仍然要等用户：花钱或接入付费数据源；不可逆地删除或改写数据；改变规则 A 交易结果或 golden。
