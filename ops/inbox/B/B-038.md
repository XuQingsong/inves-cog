# B-038 修复 M8 PIT 快照的多标的 affected 结构

> 发给：B 线（Cursor）。类型：B-037 验收修复；沿用 B-036 已授权的唯一 M8 PIT 快照 schema/权限范围。
> PR #47 保持草稿，在本修复通过前不得合并。

## 复核发现

PR #47 当前 `_affected()` 对多只 ticker 返回 `ticker=[...]`、`exposure=[...]`；`_flatten()` 再把这两个数组塞进一个 `affected` 对象。M9 的消费合同要求 `affected` 是多个对象、每个对象的 `ticker` 和 `exposure` 都是单值；M9 会把 ticker 当作映射 key。多标的事件因此会把 list 当 key，导致不可哈希错误；即使未抛错，也无法逐只应用暴露/冷静条件。

## 修复要求

- 一个事件涉及多只标的时，快照输出一条 `affected` 记录对应一个 ticker；每条的 ticker/exposure/divergence/next_filing 等都保留该 ticker 自己的值，不合并成数组。
- 多来源对同一 ticker 给出冲突值时，保留字段缺失/冲突原因；不挑一个“更可行动”的值。
- 单 ticker 结构保持兼容；无 ticker 或无暴露的事件保留缺失原因，不制造受影响标的。
- 不改 M8 完成标记、snapshot PIT 时间、M9 规则、M4 调度、schema、角色或来源。

## 补充（B 线接单前追加，同属本单）：“完整”按日判定，字段缺口按事件/标的记录

复核 PR #45 的 M9 消费代码后确认第二个问题：当前快照只要**任一事件的任一字段**为 NULL（包括只用于展示的 `divergence_tag`、`dimensions`、`systemic_tag`、`next_filing_at`），整日就标 `degraded`、provider 返回 `complete=false`；M9 遇到 `complete=false` 会整体沿用上一版覆盖层（首次上线时即无覆盖层）。M8 报告常缺这些字段，所以实际效果是覆盖层几乎永远发不出来。M9 规格只规定“**M8 当日未完成**”才沿用上一版（`docs/phase1/M9-overlay-shadow-factors.md` 第 88 行），字段缺失不是“当日未完成”。

改为：

- `status=complete` 的条件：三个 M8 阶段都在快照时钟前以 `ok` 结束，且快照成功写入。仅当阶段缺失/失败/晚于 cutoff 时才是 `degraded`（并且此时不写 complete 快照）。
- 字段缺口**不再降级整日**：保留在每个事件的字段单元格和 `missing.fields[event_id]` 中；provider 在 `complete=true` 时也必须原样返回 `missing.fields`。
- `lifecycle` 没有 cutoff 前历史版本的事件：仍随快照返回，`lifecycle=null` 并记录原因，不删除事件、不让整日降级。
- reader 的 `_event_usable` 只校验 `observed_at` 和已有字段的 `at` 不晚于 cutoff；不再要求全部字段非空。晚于 cutoff 的字段视为缺失。
- 不改 PIT 时间规则：无自带时间的当前值仍以快照注入时钟为时间；不回填、不伪造。

补充测试：

6. 三阶段成功、某事件缺 `next_filing_at`/`divergence_tag`：快照 `complete`，provider `complete=true`，该事件其他字段齐全返回，`missing.fields` 列出缺项；
7. 阶段缺失/失败/晚于 cutoff：仍为 incomplete，行为不变；
8. 某事件无 cutoff 前 lifecycle：事件保留、`lifecycle=null`、原因可见，整日仍 complete；
9. 字段 `at` 晚于 cutoff：该字段按缺失返回，不影响同事件其他字段。

本补充同样只改 `snapshot.py` 与专项测试；必要时可调整 B-035/B-036 中断言“字段缺失即整日 incomplete”的旧测试，须在 PR 说明里逐条列出改动原因。

## 测试与交付

先写失败测试，再修复。至少覆盖：

1. 一个事件涉及两个 ticker，输出两个 scalar `affected` 项；
2. 两个 ticker 的暴露分别保留，不交叉覆盖；
3. 一个 ticker 的 exposure 缺失或同 ticker 来源冲突时只标该 ticker 的缺失，不抹掉其他完整 ticker；
4. 单 ticker 回归形状仍兼容；
5. 用 M9 消费合同夹具验证 ticker 是可哈希字符串，不能产出 `ticker=[...]`。
