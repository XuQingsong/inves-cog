# B-032 M7 结果时间可见性与 M6 数据缺失原因

> 发给：B 线（Cursor）。类型：第一阶段线上验收阻塞修复。需求方：协调方。2026-10-21。
> 当前只有 B-031 已回报完成；本单是 B 线下一项。一次只做本单，不取后续编号。
> 依据：M7 冻结验收合同、`ops/answers/A-014.md` 续二/续三/续四、2026-10-21 自然运行回报。不得改异常阈值、golden、规则 A、M1 ingestion 契约。

## 背景和已观测证据

1. M7 历史检查 job 8750 是只读回放，没有写 `perception.anomalies`。服务器早报发生时异常表为空。
2. 当前 `perception.anomalies` 没有结果生成时间字段；早报 `morning.py` 只按 `trade_date` 读异常。若之后把历史结果补写进表，页面可能把补算结果伪装成当时已知，违反 PIT 和「只往后记」。
3. 2026-10-21 自然 `market_structure` job 8941 成功并写入当日数据，但指标完整性不足。每个 session 1,289 个对象中有 1,253 个带 `null_reason`：
   - close：`missing_current_return` 1087、`sector_unmapped;missing_current_return` 141、`l3_same_as_l2` 23、`insufficient_history` 2；
   - post：`missing_post_price` 1089、`sector_unmapped;missing_post_price` 141、`l3_same_as_l2` 23。
   不能把覆盖对象数说成可计算对象数，也不能填造价格或结构指标。任务要查明这些缺失来自什么上游行、哪个计算步骤、哪些是合理降级、哪些是可修缺陷。

## A. 修复 M7 结果的 PIT 可见时间

### 发生

- 给 `perception.anomalies` 增加实际生成时间，例如 `generated_at timestamptz`。新增迁移遵守 M0 schema/权限合同；旧记录没有可证实生成时间时保留 NULL，不按 `trade_date` 回填，不给旧结果伪造时间。
- M7 每次写入新异常时，用注入的 `Clock` 记录实际结果可用时间。历史回放/补算也记真实计算时间，绝不写成历史交易日当时。
- 修改早报异常查询：只取 `trade_date` 对应且 `generated_at <= 页面运行时刻` 的结果；生成时间为 NULL 或晚于运行时刻的都不可见。
- 不改变 M7 检测阈值、异常内容、M8 归因逻辑或规则 A。

### 先红后绿验收

为现有入口补离线测试，至少覆盖：

1. 同一交易日、生成时间早于早报时刻的异常可见。
2. 同一交易日、生成时间晚于早报时刻的异常不可见。
3. 旧行 `generated_at IS NULL` 不会被当成早报时已知。
4. 历史补算行按真实生成时间处理；用 `--at` 重出旧日期时不会穿越到未来。
5. 检测写入使用注入时钟；不依赖系统当前时间，不连生产库、不调模型。

PR 内含迁移、代码、测试和自测证据。生产迁移/回填只能在 PR 合并后按 A-014 执行；不得自行登录或写生产库。本单只解决契约和离线行为。

## B. M6 数据缺失诊断

使用已有的私有自然运行证据和离线代码追踪，按 close/post、pool/wide、ticker/source 分层，明确每类 null reason 的直接原因：

- 当前交易日原始行情是否存在、来自哪个已批准源、是否满足 freshness；
- 是 M1 没有该 ticker/date 的原始行，还是 `marketstate` 计算/映射逻辑没有使用已有行；
- `sector_unmapped`、`l3_same_as_l2`、`insufficient_history` 分别是预期降级还是缺陷；
- 缺失会影响哪些市场状态、异常路径和成员；哪些字段仍然有效。

**先诊断，不能为清零 NULL 而降级门槛或补造数据。** 若证实问题在 B 所属的 `marketstate`/`graph` 代码、且不改冻结阈值/接口，可在本 PR 中按先红后绿修复并给出覆盖测试。若根因是 M1 上游未采集、缺数据源/权限或需要改其他线的 schema，报告确切输入和阻塞，不越界修改；由协调方另行安排。
