## 修复项

1. **没有 `links` 的候选不能绕过门禁。** 在 v3 的候选路径上（`propose_candidates` 及读 v3 录音的路径），没有 `links` 字段，或 `links` 不是数组，都按"未给逐环依据"处理：
   - 所有标的移入 `research_gaps`，原因写"未给逐环依据"；预期影响范围为空；`link_checked` 为真；另加一个标记 `links_missing`；
   - 候选本身、机制、引用照常保留。

   不在 v3 路径上的旧录音和历史读取方式保持原状，不重新标成 v3。
   **允许改动现有测试，但仅限于此**：只因这一条而受影响的现有测试，优先给夹具补上合法的 `links`，使原期望值不变；实在不能保持的，在 PR 说明里逐条列出测试名和前后值。除此之外任何现有期望值的变化，仍按"必须停"处理。
2. **盲审不得泄露组别。**
   - 盲审表的 id 用与组别无关的随机标识，由对象 id 和种子决定，可以复现；
   - `packet.json` 与 `blind_table.json` 都不得包含组名、格名或映射，映射只写在 `blind_map.json`；
   - 测试断言：在前两个文件的序列化文本里，搜不到任何组名或格名。
3. **删除变体只删目标。** 只删除目标条目和同一 `source_root` 的条目，以及它们的摘要和说法；其他条目原样保留。目标 id 不存在时拒绝生成，并写明原因。测试断言：非同源条目与基线逐字节一致。
4. **四格和对照对象生成实际 payload。**
   - 每一格、安慰剂对象和方向反转对象，都用现有 `candidate_payload` 生成 v3 payload。人工参考抽取的格子，用人工说法替换 `claims`；
   - 哈希使用调用客户端实际采用的规范 payload 哈希，与 `historical.recording_path` 的算法一致；
   - 调用计划包含这 6 个对象，每个对象的次数由参数 `runs` 指定（默认 3），合计上限等于 6 × `runs`；
   - 测试断言：用同一 payload 经现有规范化函数算出的哈希与计划中的一致。
5. **已支持的市场关联由规则填写。**
   - 用已经计算出的 `_confirmation` 结果和二次命中结论填写，按候选、按标的列出；只列确认结果实际覆盖到的 M7 成员，每条注明来源（市场确认或二次命中）和规则名；
   - 结果为未知或不确认时不填；
   - 候选的 `scope_layers` 和报告的 `link_view` 两处保持一致；
   - 模型输出中的同名字段继续剔除。
6. **次要项**：
   - 预登记检查把时间解析为带时区的时间后再比较；没有时区的时间一律拒绝；
   - 报告的 `link_view` 展示每个候选的 `hypothesis_width`，不进入评分。
