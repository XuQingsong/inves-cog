## 需求方验证结论（2026-10-23，私有目录 `inves-cog-data/devin-model-compare-20261023/`）

同 4 个真实 pool 异常（10-16 HDD、AI 芯片、数据中心电力，10-21 AI 服务器），payload 与回放 hash 一致，门禁代码不变：

| prompt | 配置 | 门禁后留下受影响标的 | 单次耗时 |
|---|---|---|---|
| 现行 v3 | GLM 默认 / GLM low / DeepSeek（+回放） | 2/15 | 680–900 秒 / 13–47 / 13–25 |
| **v4**（第二轮） | GLM low ×2 | 6/6（10-16 三例）；10-21 两次均 0 候选 | 15–42 秒 |
| **v4**（第二轮） | DeepSeek ×2 | 5/6（10-16）；10-21 一次留下 | 2–22 秒 |
| v4 | GLM 默认 | 4 次均超过 900 秒未返回 | — |

v3 失败的共同原因是输出合同含糊：links 终点用抽象节点而非 ticker、证伪预测写在对照标的上、`hypothesis_type` 与 mechanism 混用、缺 `kind`。v4 写明这些规则并附完整示例后，GLM low 语义质量优于 DeepSeek（DeepSeek 有把 BE 新闻外推到 GEV/VRT 等弱推断）。10-21 的 0 候选是允许的诚实结果（新闻不足以解释 DELL/SMCI 上涨）。

## 修改要求

1. **prompt v4**：`anomaly_candidates` 的 system 消息**整段**使用 `docs/phase1/contracts/m8-candidate-prompt-v4/instruction.txt`（不再拼接通用前缀）；payload 的 `output` 使用同目录 `output.json`（结构原样）。`PROMPT_VERSION` 改为 `evidence-bridge-v4-links`。原 `source_document` passage 扩展保留：items 含文档时，在 v4 的 anchor 结构里追加 `passage` 选项及 `passage_schema()` 字段。两个文件是唯一来源，代码读取文件，不手抄文本。
2. **GLM 低强度思考**：`anomaly_candidates` 请求加 `reasoning_effort="low"`；`config/llm_tasks.yaml` 该任务 `timeout_seconds` 改为 300。模型仍为 glm-5.3，重试次数不变。
3. **早页先发**：09:15 先完成所有 pool 异常的 move_card 并写出早页（`_emit`），再跑结构化链落库；结构化链失败或慢不得推迟或阻止早页写出。模型调用次数与 B-040 相同（每条有盘前新闻的 pool 3 次）。job 成败语义不变（落库失败仍记 failed）。
4. **快照方向**：实时 `snapshot._direction_field` 与回放 `replay_window._direction` 改为取该事件首选候选（与 linkage 机制一致的已打分候选）门禁后保留的 `affected[*].direction`：唯一则填；不一致写缺失原因“受影响标的方向不一致”；无保留标的写“没有保留的受影响标的”。不再用 claims 汇总方向，也不用异常价格方向。
