# B-019 新闻卡要留下模型实际给出的答案

> 发给：B 线（Cursor）。日期：2026-10-19。类型：修复。需求方：Cursor 云端协调方。
> 测试只用注入的回复。不发起真实模型调用，不连数据库，不部署，不合并。

## 为什么有这张单

B-018 已合并（`17147a1`）。需求方用合并后的程序，对 2026-10-14、10-15 当时已经入库的新闻问了 DeepSeek，共 786 次，没有调用失败。页面上新闻卡是空的：786 张里「说了什么」全是空的，名单内只有 1 家。

原因不在模型没答。需求方对同一条新闻又问了一次，模型返回的是英文栏：`summary`、`industries`、`companies_affected`、`companies_outside_list`。公司写在 `code`、`name`、`direction`、`reason`、`relation`、`importance`。程序只读中文栏 `说了什么`、`行业`、`名单内`、`名单外`，英文栏被丢掉，页面就只剩标题。

这是需求方的问题。B-015 写了要保存的中文栏，没有写模型若用英文栏时怎么接。验收例子注入的是中文栏。

## 基线

从最新 `origin/main` 开新分支 `cursor/m8-b019-news-card-keys-e013`，开新 PR。

## 什么时候发生，什么时候不发生

发生：入库细读要写新闻卡的那一次。下面两种回复都发生。

1. 模型用中文栏：`说了什么`、`行业`、`名单内`、`名单外`。
2. 模型用英文栏：`summary`、`industries`、`companies_affected`、`companies_outside_list`。公司用 `code`、`name`、`direction`、`reason`、`relation`、`importance`。

不发生：标题初筛不写新闻卡。波动卡的问法不改。模型没答、答坏了，仍写原因，名字匹配保留。

## 用户看到的结果从哪一个入口出来

入口是 `enrich(..., close_read=True)`。做完时，新闻卡在 `extraction_source["news_card"]`。

英文栏按这个对应写进原来的中文栏：

- `summary` → `说了什么`
- `industries` → `行业`
- `companies_affected` → `名单内`
- `companies_outside_list` → `名单外`
- `code` → `代码`，`name` → `名称`，`direction` → `方向`，`reason` → `理由`，`relation` → `关系`，`importance` → `重要程度`

中文栏有内容时用中文栏。中文栏空着或没有时，用英文栏补上。名单仍只分成名单内和名单外，不删模型答出的公司。`标明` 仍是「模型判断」。名字匹配仍要有。

## 先红后绿

用注入的回复。两个例子都从 `enrich(..., close_read=True)` 跑。只直接调用 `read_card` 或 `attach_news_card` 就算通过的，不算。

1. 注入英文栏：`summary` 是「苏姿丰说供应要增加」，`companies_affected` 里有 AMD，`importance` 是「高」，`relation` 是「新闻点了名」。新闻卡的「说了什么」是这一句，名单内有 AMD，重要程度是高，关系是「新闻点了名」。
2. 注入中文栏：名单内有 META。新闻卡里 META 还在。再注入一个坏回复：新闻卡写原因，名字匹配还在。
