## 目标

把线上四个页面、个股页和移动端，**照定稿原型一比一实现**：
- 原型：`docs/phase1/design/prototype/index.html`（单文件，双击打开；hash 路由见 README）
- 规则与数据修正：`docs/phase1/design/prototype/README.md`

原型是验收基准，不再另出设计稿。**结构、文案层级、颜色语义、价格尺算法和交互都要与原型一致。** 只有一种情况允许偏离：生产数据确实取不到。此时显示原型规定的“暂缺 / 待接入”样式，并在 status 里逐条列出偏离点和原因。

## 实现要求

1. **渲染方式**：服务端继续用现有方式生成 HTML，数据全部来自现有接口和查询；排序、筛选、展开、定位这些交互用原生 JS。不引入框架，不使用外部 CDN 或网络字体。CSS 变量和类名按原型规范页 `#ds` 的设计系统实现。
2. **路由**：保持现有 URL（`/`、`/stocks`、`/account`、`/trust`、`/s/{symbol}`，都带 `?date=`）。另外支持 `/account#AVGO` 这种直接定位并展开某只持仓的写法。日期 ‹ › 在相邻交易日之间切换。
3. **页面**（逐区块对照原型）：
   - 市场总览：判断标题、指数卡、涨跌家数条、“对我意味着什么”、板块发散条形图加风格标签、情绪刻度（VIX）和情绪数据表、可展开的“今天的大事”（成员股标签，持仓股高亮，引用旧闻时标“旧闻”）。指数近 20 日走势：库里有 SPY、QQQ、IWM 日线就画迷你折线，没有就显示“待接入”。
   - 我的标的：主题强弱表，点击展开成员，可以联动下方表格筛选；59 只明细支持任意列排序、筛选（全部 / 持仓 / 可买 / 异动 / 空头拥挤）、主题下拉和代码搜索。
   - 纸面账户：
     - 标题和计数只统计下行风险；
     - 风险分“下行风险”和“止盈提示”两组；
     - 组合边界：集中度条加两条阈值刻度，回撤轴标出 −8% 和 −12%；
     - 持仓行包括类型、成本 → 现价、盈亏、当日涨跌、价格尺、标签、下一步和估值；点击后在原位展开条件卡片，卡片带四种状态和逐条附加条件；
     - 待成交、处置记录、待选股票（含现价）。
   - 复盘与数据：数据状态卡片，点击展开影响说明；复盘空状态；“发现的数据异常”列表（由第 4 节第 8 项的检查生成）；口径说明默认折叠。
   - 个股页：一句话、近 60 日收盘折线（叠加当前 50 日线、200 日线；持仓股再叠加成本线和止损/灾难线）、位置与情绪、四项评分条、我的仓位（价格尺和条件卡片）或“为什么没买”、新闻与事件（旧闻标签）、基本面与估值、数据时间。
   - 移动端（宽度 < 760px）：布局按原型的媒体查询实现，价格尺随宽度自适应。
4. **价格尺**：完全按原型的 `ruler()` 算法实现：适用价位、200 日线参考线（只画核心仓）、最近触发段、核心仓没有价格触发线时画到 200 日线的虚线段、已越过的价位画空心圆加 ✓、六泳道标签避让。价位和条件沿用 B-061 的 `exit_levels`，不得在页面层另算规则。
5. **状态**：计划缺失日、盘中、暂缺、过期、旧闻、部分覆盖、各种空状态，样式与原型 `#ds` 第 06 节一致。盘中状态这次只实现样式和标注接口，不接入盘中数据。

## 必须同时修正的数据口径（详见 README 的表格）

1. 账户页的“距高点”与回撤刹车距离统一口径：都用**按收盘估算的总资产 / 历史峰值 − 1**。10-22 应显示 −3.65%。
2. 某日计划缺失时（如 10-23），账户页沿用最近一次有效持仓和价位，顶部显示“X 日计划缺失，以下沿用 Y 日持仓”，**不得显示空仓**。
3. 风险分组：止盈接近（翻倍价已到、波段止盈接近）归入“止盈提示”，不计入风险；当日跌幅达到 5% 及以上或卷入当日异常的，仍按现有规则算下行风险（AMD 在 10-22 同时出现在两组）。10-22 的期望结果：**下行重点 2 项、关注 6 项，止盈提示 3 项**。
4. 待成交单从账本读取股数和计划成交日，取不到时显示“暂缺”。
5. 处置记录区分“计划”和“已成交 · 价格 · 股数”。只读账号如果没有成交表的读权限，就显示“计划”，并在 status 里报告，**不要自行加权限**。同一天、同一股票、同一原因的重复计划记录，要么合并显示为“×2”，要么查明它们是两笔不同的减仓，在 status 里说明是哪一种。
6. 待选股票增加现价（当日收盘价）一列。
7. 空头数据只能取结算日不晚于页面截点的记录。PLTR 11/15、WMT 11/28 这类结算日晚于截点的记录，要查明原因（是查询条件还是日期解析的问题），修正后加测试；如果根源在上游，只在 status 里报告。
8. 极端市盈率：市盈率大于 300 或 EPS 接近零时，显示“市盈率不适用（盈利过低）”；“无法反解：价格不在[-50,200]…”这类内部文字改成人话。这两类情况和第 7 项一起，写入“发现的数据异常”列表。
9. HD 等不在标的池里的持仓：当日涨跌能取到日线就显示，取不到就显示“暂缺”。
