## 背景（A 线 22:43 生产只读核查，PR #49 评论）

`replay_window._load_window` 复用 `morning._load`，后者按 `generated_at <= 该 stage 时点` 过滤异常。10-15/16/20 的异常是 UD-COORD-27 批准的 M7 补算，`generated_at` 为 10-22 实际补算时间（03:49 UTC），因此在历史时点全部被过滤：原生 `--dry-run` 选入 0/0/0/0/9 条、调用 0/0/0/0/3 次，而库里实有 2/5/0/11/9 条。照此执行会把有数据的三天写成空 `historical_backfill`。

## 修改要求

1. **只改回放入口**：`--days` 指定的每个交易日，异常按 `trade_date = 该日` 从 `perception.anomalies` 选入，不按 `generated_at <= 历史时点` 过滤；只取该日自己的异常，不得混入其他交易日。
2. **保留真实生成时间并标明**：每条选入的异常保留原 `generated_at`；凡 `generated_at` 晚于该日 09:15 时点的，在回放结果（CLI 输出 JSON 与回放日志的逐日记录）中列出 `anomaly_id`、真实 `generated_at`、`generated_after_slot=true`。不改写、不倒填任何时间。
3. **新闻仍按 PIT**：新闻/信息条目继续按各 stage 时点的 `published_at`/`first_seen_at` 过滤，不放宽。
4. **实时路径不变**：`morning._load` 与 `scheduled` 的实时过滤一行不改；如需共用代码，以参数区分，默认值保持实时语义。
5. 快照仍为 `kind='historical_backfill'`、`replay=true`；不改合同输出结构。
