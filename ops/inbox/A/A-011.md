# A-011 把 Muse 当前的纸面持仓放到 GitHub

> 发给：A 线（Codex）。日期：2026-10-19。类型：数据交付，不是开发，不是 M9/M10。需求方：Cursor 云端协调方。
> 用户 2026-10-19 原话：「你发给 a 开发，让他去找 muse 要当前的纸面持仓，然后发到 git 上，这是纸面持仓，上传了也不要紧。」

## 要什么

去 Muse 取**当前**纸面账户里已经拿着的股票，放到 GitHub。

这是纸面持仓，不是券商里的真实账户。用户说上传不要紧，所以这次**明文提交**，不要加密。

不要用 inves-cog 里规则 A 回放到 2026-10-07 的那 11 只代替。那份是这个仓库自己的复现，不是 Muse 当前账户。两份不一样时，以 Muse 当前账户为准，并在说明里写清差在哪。

## 文件

分支：`data/a011-paper-holdings`。不要合并进主分支。

文件：`handoff/A011/paper-holdings.json`，一个 JSON 对象：

- `as_of`：这份持仓对应的时间，带时区。
- `source`：在 Muse 的哪一处读到的（文件路径或表名）。不要写密钥、账号、连接串。
- `positions`：数组。每只有 `ticker` 和 `shares`。股数是 0 的不要放进来。有成本就加 `avg_cost`，没有就省略。
- 可以加 `cash` 和 `equity` 两个数。没有就省略，不要填 0 充数。

说明写在 status 里：几只、截止时间、从 Muse 的哪里读的。若和 2026-10-07 那 11 只不同，列出多出来的和少掉的代码。

## 不做

不改业务代码，不改 `config/universe.yaml`，不改估值和交易计算，不调模型，不部署，不把券商真实持仓写进来，不写密钥。跟踪名单已经在主分支 `config/universe.yaml`，这张单不要重导那 59 只。

## 完成标准

1. 分支上有上述 JSON，内容是 Muse 当前纸面持仓，不是本仓库回放。
2. status 写 `已收到`、`已完成`，并写上只数、`as_of`、来源。做完就停，不领下一张。
