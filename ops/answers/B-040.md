# B-040 提交前自验清单（需求方验收将逐项照此复核）

> 不改 B-040 任务本身，只说明“怎样才算一次通过”。提交 PR 前请逐项自验，在 `ops/status/B.md` 的“已完成”条目里按 V1–V9 列出：结果（通过/不通过）、测试名、证据（命令输出摘要或文件）。任一项做不到，或与任务书的约束互相冲突，**先停下写清冲突再提交**，不要自行取舍。
> 合同样例：`docs/phase1/contracts/m8-m9-provider.json`（合成数据）。

## 夹具要求（所有 V 项共用）

真实形态，不能用空夹具让测试“绕过”关键路径：
- 交易日 2026-10-20；三个阶段按 `slot_moment` 的真实时刻运行（09:15/09:30/12:30 北京）。
- 异常：pool 两条（一条成员 WDC/STX/MU，一条成员含 NVDA），wide 一条。
- 新闻：每条 pool 异常都有**盘前**新闻（`_before_move` 为真）；另有一条 `first_seen_at` 晚于 09:15 的新闻、一条 `published_at` 早但 `first_seen_at` 晚于 as_of 的新闻。
- 模型：用“计数+返回固定结果”的假客户端，返回值让 WDC/STX 暴露为“直接”、MU 为“概念关联”、NVDA 无暴露。

## 验收项

- **V1 合同一致**：三阶段跑完后，`m8_provider(conn)(target, cutoff)` 的输出与合同样例 `output` **同键、同类型、同嵌套**；Toshiba 事件的 `mechanism`、`direction`、`affected` 三只标的的 `ticker`+`exposure` 与样例一致，`lifecycle` 非空且等于完整链实际写入 `linkage_events` 的值（样例里的“基本面核查中”只是示例，不要求相同）；NVDA 只出现在 `missing.fields[event]["NVDA.exposure"]`；`affected[*].ticker` 全是字符串。用测试直接读取合同 JSON 做逐键比较，不手抄期望值。
- **V2 模型调用次数**：按阶段、按 pool/wide 输出实际调用表。断言 09:30=0、12:30=0；09:15 每条 pool 异常 = move_card 1 次 + 完整链实际所需次数（写明具体数字）；09:15 wide 按实际。
- **V3 估算等于实际**：同一夹具，`replay_window(..., dry_run=True)` 的逐阶段计数 == V2 的实际计数；dry-run 不写库、不调模型（断言执行的 SQL 只有读）。
- **V4 09:15 结果不被覆盖**：09:30 后 `perception.reports` 中该异常的 `daily_text`、`move_card` 与 09:15 写入的值逐字相同。
- **V5 PIT**：晚于 as_of 才 `first_seen_at` 的两条新闻不进入任何阶段的输入（断言模型收到的 payload 不含其 info_id）；`generated_at` 晚于 cutoff 的异常不进入实时快照。
- **V6 完整性语义**：删掉任一阶段 job（或改为 failed / ended_at 晚于 cutoff）→ provider 输出与合同 `incomplete_case.output` 同结构；只缺字段 → `complete=true`，缺项在 `missing.fields`。
- **V7 逐标的值**：同一事件两只标的各有不同的 `divergence_tag`/`next_filing_at` 时，provider 输出逐只保留；字段时间晚于 cutoff 时该项为 null 并进入 `missing.fields`。
- **V8 回放隔离**：五日回放（计数客户端）后断言：没有任何 SQL 写入 `linkage_events/ticker_status/candidates/tracks/claims/reports/market_day`；`m9_input_snapshots` 新行 `kind='historical_backfill'`、`snapshot_generated_at` 等于注入的实际时钟（不是历史时间）；`read_replay_snapshot` 返回 `replay=true` 且结构同 V1；实时 `read_snapshot` 在历史 cutoff 读不到它们。
- **V9 回归**：`make phase1-test`、`make phase1-cases` 本地通过；两个 PR 的**准确 head** CI 通过；附链接。

## 需求方验收方式

需求方会在 PR head 上直接运行 V1–V8 对应测试，并抽查夹具是否满足上面的“真实形态”要求；夹具缺盘前新闻、缺 late 新闻或用空客户端，视为该项未自验。
